# Release 0.138.0 (2026-04-20)

Scope-toggle UX correctness — dual-scope indicator, tombstone cleanup, symmetric info-panel diff.

## Fixed

### D-223 — Dual-scope badge preserved on hydration

A skill toggled G→P (ending with a project-active entry + a global-excluded tombstone) showed only the `[P]` badge on the next `cc edit` — the tombstone was dropped during hydration. `populateFromSkillIds` filtered excluded configs by `!resolvedSet.has(sc.id)`, collapsing the pair whenever the active entry shared its id. The render layer was already dual-scope capable; it simply never received the tombstone.

`wizard-store.ts::populateFromSkillIds` now drops the `!resolvedSet.has` guard so tombstones flow through unconditionally. The unit test that encoded the bug ("should not create duplicate entries…") is replaced with the inverted assertion ("preserves excluded tombstone when active entry exists for same skill at different scope").

E2E: `e2e/interactive/edit-wizard-dual-scope-indicator.e2e.test.ts` (3/3) — G→P toggle produces dual `[P][G]` badges, passthrough edit preserves them, and config.ts carries both entries byte-identical.

### D-224 — P→G tombstone cleanup unconditional

After a G→P→G cycle on a skill with a prior global tombstone, the wizard persisted a corrupt `{global} + {global, excluded:true}` pair. `toggleSkillScope`'s P→G branch only ran tombstone cleanup when `wasInstalledGlobally` returned true, but that predicate filters `!sc.excluded` — so a tombstone-only project config was invisible to the gate. The cleanup never fired; the writer's compound-key merge dropped the new active entry; the UI read the remaining tombstone as "not installed."

`wizard-store.ts::toggleSkillScope` now unconditionally removes same-scope tombstones on every P→G (gate dropped). The G→P branch stays gated — tombstone *creation* still requires a real prior global install to avoid fresh-init spurious tombstones. `toggleAgentScope` made symmetric (the agent path had the same asymmetry by accident).

E2E: `e2e/lifecycle/tombstone-cleanup-PtoG-restoration.e2e.test.ts` (3/3) — P→G collapses to a single global entry, full G→P→G roundtrip is byte-idempotent, no-op edit between toggles does not corrupt state.

Fix B (pass live global config into wizard hydration) and Fix C (writer-side merger invariant) intentionally deferred — Fix A alone proved sufficient against the empirical trace in `.ai-docs/agent-findings/2026-04-17-d224-ptog-tombstone-not-cleared.md`.

### D-225 — Symmetric info-panel diff on scope toggle

A P→G toggle rendered `+` next to the new global row but no `-` next to the removed project row — `removedSkills`/`removedAgents` filtered by id/name only, while `prevSkillKeySet`/`prevAgentKeySet` were keyed on `(id, scope)`. Asymmetric keys produced asymmetric diffs; users saw "skill added to global" with no companion "removed from project."

`src/cli/components/wizard/skill-agent-summary.tsx`:
- `skillDiffBaseline` / `agentDiffBaseline` pre-filter `installedSkillConfigs` / `installedAgentConfigs` by `!s.excluded` so tombstones don't pollute the baseline keyset
- `removedSkills` / `removedAgents` re-keyed on `(id, scope, !excluded)` / `(name, scope, !excluded)` — symmetric to `isNew` detection
- `inheritedGlobalSkills` / `inheritedGlobalAgents` exclude tombstoned entries so G→P falls through to `removedSkills` (not mis-classified as "inherited global")
- `removedGlobalSkillIds` / `removedGlobalAgentNames` suppression sets prevent `uniqueExcludedGlobal*` from double-rendering a tombstone bullet alongside the new `-` row

E2E: `e2e/interactive/info-panel-scope-toggle-diff.e2e.test.ts` (4/4) — P→G skill, G→P skill, P→G agent, build-step info-panel overlay. All assert symmetric `{project: -, global: +}` / `{global: -, project: +}` tuples via `getSummaryDiffEntries`.
