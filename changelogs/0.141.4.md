# Release 0.141.4 (2026-07-09)

Regenerated skill matrix and metadata schema from the skills source repo.

## Changed

### `metadata.schema.json` category/slug enums caught up to the skills repo

`src/schemas/metadata.schema.json` — read by every skill's `metadata.yaml` via its
`yaml-language-server: $schema` comment — had stale `category`/`slug` enums, causing
editor-level validation errors on newly-added skills. Ran the existing two-step generation
pipeline (`bun run generate:types` then `npm run generate:schemas`) to catch it up:

- Added ~30 new category slugs picked up from new skills (`api-caching`, `api-graphql`,
  `api-messaging`, `api-queue`, `api-specs`, `cli-prompts`, the `desktop-*` family,
  `infra-containers`, `infra-iac`, the `mobile-*` family, and more)
- Removed `nextjs-app-router` and `nextjs-server-actions` slugs, replaced by `nextjs` — these
  were already stale relative to a past skills-repo merge (`13d6519`, 2026-03-16) that combined
  both into a single `web-meta-framework-nextjs` skill; no other skill still referenced the old
  slugs
- `src/cli/types/generated/source-types.ts` and `matrix.ts` regenerated to match (222 skills,
  89 categories, 9 domains, 23 agents, 17 stacks); matrix.ts also drops a handful of stale
  `group: "React"` fields no longer present in `default-stacks.ts`

No source logic changed — this is purely regenerated build output catching up to the current
skills repo and `default-stacks.ts`.

## Findings

None filed — this was a straightforward regeneration, not a code fix.
