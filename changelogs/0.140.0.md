# Release 0.140.0 (2026-04-20)

Per-skill plugin skill reference format in compiled agents (D-217).

## Fixed

### D-217 — Per-skill `pluginRef` based on `source`

Compiled agent `.md` files now reference each skill in the format dictated by that skill's own `source` field, not by a whole-agent `installMode` flag. Mixed-mode agents — one agent whose curated skill list contains both plugin-source skills and eject-source skills — now emit the correct per-skill format; previously they emitted all-qualified or all-bare refs depending on the whole-agent `installMode`, breaking resolution at runtime for half the skills.

**Contract (compiled frontmatter `skills:` + body `skill: "..."` invocations)**:
- `skill.source === "eject"` (or `undefined`, e.g. user-authored local skills) → bare `${id}` (resolved via `.claude/skills/`)
- `skill.source` is a marketplace name (e.g. `"agents-inc"`) → `${id}:${id}` (plugin-qualified; what Claude Code's plugin resolver expects)

**Implementation**:
- `src/cli/types/skills.ts` — optional `source?: string` added to `SkillReference` and `Skill`
- `src/cli/lib/resolver.ts` — `resolveSkillReference` threads `ref.source` onto the returned `Skill`
- `src/cli/lib/installation/local-installer.ts::buildCompileAgents` — builds a `sourceById` map from `config.skills` and attaches per-skill `source` onto each `SkillReference`; drops the `installMode` arg from the `compileAgentForPlugin` call
- `src/cli/lib/stacks/stack-plugin-compiler.ts::compileAgentForPlugin` — drops the `installMode` param; new `derivePluginRef(skill)` helper with an `EJECT_SOURCE` constant decides pluginRef per-skill via `skill.source !== undefined && skill.source !== "eject"`
- `src/cli/lib/agents/agent-recompiler.ts` — drops `installMode` at the `compileAgentForPlugin` call site

Dead `installMode` plumbing retained on wrapper types (`RecompileAgentsOptions`, `CompileAndWriteParams`, `compileAndWriteAgents`) to preserve caller contracts — tracked as a documented follow-up in `.ai-docs/agent-findings/2026-04-20-d217-installmode-plumbing-dead-in-wrappers.md`.

**Known latent edge case (deferred, not shipping blocker)**: `sourceById` is keyed by `id` alone. For a dual-scope config with distinct per-scope sources (e.g. `{id, project, source:"eject"}` + `{id, global, source:"agents-inc"}`), `Map` last-write-wins produces the wrong source tag for one scope. Canonical agents-inc configs use `"eject"` on both sides, so this does not bite in practice. Defensive fix (key by `${scope}:${id}`) tracked as D-217 follow-up.

## Added

- Unit tests (all green):
  - `src/cli/lib/stacks/stack-plugin-compiler.test.ts` — 5 new per-skill ref-format cases (pure plugin, pure eject, mixed, undefined source / user-authored local, dual-scope same id)
  - `src/cli/lib/resolver.test.ts` — 2 new tests verifying `source` propagates through `resolveSkillReference` onto the resolved `Skill`; 2 pre-existing `toStrictEqual` tests updated to include `source: undefined` (shape evolution of the resolved-Skill contract, not assertion broadening)
  - `src/cli/lib/installation/local-installer.test.ts` — 2 stale `installMode` tests rewritten to assert per-skill `source` on the `agent.skills[]` argument passed to `compileAgentForPlugin`
- `e2e/lifecycle/mixed-mode-skill-ref-format.e2e.test.ts` (new) — full init-plugin → edit-toggle-one-skill-to-eject flow; asserts both the frontmatter `skills[]` and the body Skill Activation Protocol table carry per-skill formats in the same compiled agent `.md`

## Changed

- `e2e/helpers/create-e2e-source.ts`:
  - **Template bug fix** — the fixture ships its own `agent.liquid` template (diverges from the production template). It previously read `agent.preloadedSkills` (nonexistent path on the template context), producing an always-empty frontmatter `skills:` array in every E2E-compiled agent regardless of stack configuration. Fixed to match the production template's `preloadedSkillIds` iteration.
  - **Realism trim** — trimmed meta-skill preload flags on `webDeveloperAgentConfig` and `apiDeveloperAgentConfig` to match real user-facing stacks in `src/cli/lib/configuration/default-stacks.ts`. Real stacks do not preload meta skills (`meta-reviewing-reviewing`, `meta-reviewing-cli-reviewing`, `meta-methodology-research-methodology`) on `web-developer` or `api-developer`. The over-preload was a fixture-reality drift that surfaced during D-217 E2E work as false "edit path drops meta skills" failures.
