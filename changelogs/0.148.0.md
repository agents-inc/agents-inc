# Release 0.148.0 (2026-08-02)

One module owns the global config, sub-agents gain a model and an effort, and several commands now reach outside the directory you ran them in (D-281, D-282, D-304, D-305, D-307, D-308, D-309)

The theme of this release is that a global change stops being a local one. Ten code paths could write `~/.claude-src/config.ts` and its `config-types.ts` sibling, and only two of them told the projects that inline it. The rest left every other project holding a stale copy — and because the CLI never said so, the staleness was invisible until a type error surfaced somewhere nobody was working.

Read the Changed section before upgrading: `compile`, `uninstall`, `update` and `edit` now write files in directories other than the one you invoked them from.

## Added

### A sub-agent carries its own model and reasoning effort

A sub-agent's `metadata.yaml` could name a model, but nothing in a project's config could override it, and there was no way to say how hard it should think. Both are now optional fields on `AgentScopeConfig`; the config wins when it names one, and the pair is written into the compiled agent's front-matter.

`fable` joins the model names, and `EFFORT_NAMES` is declared beside them so the two scales live where every other closed union in the CLI does.

### `update` recompiles every registered project

`update` replaces the content of installed skills, and compiled sub-agents embed that content — but it only ever recompiled the directory it ran in. Every other project kept agents built from the text that was just replaced. It now recompiles each registered project afterwards and reports how many.

## Changed

### D-282 — one module writes the global config pair, and it always propagates

Writing the pair is now the exclusive privilege of `lib/config-gate/`. It classifies what actually moved between the config on disk and the config being written, writes both halves from the same source so they cannot disagree, fans the change out to every registered project, and recompiles the projects it rewrote — returning a report the caller renders, rather than a list the caller must remember to act on.

That last distinction is the whole point. Both gaps this fixed were a caller forgetting: a project-scope source migration that rewrote the global config and told nobody, and a global uninstall that pruned every registered project's config and left their compiled agents naming skills that no longer existed.

Four independent layers make bypassing the gate impossible rather than discouraged: the raw writers leave the public barrels, ESLint refuses the imports, a runtime tripwire in `utils/fs.ts` refuses the write itself whatever route reached it, and a guard test scans the source for anyone trying. The tripwire compares resolved paths, so it catches the filename assembled at runtime that no static check can see.

**The behaviour that follows from it** — each of these previously stopped at the current directory:

- `compile` at the home directory fans the global config out to every registered project and recompiles their agents. This is the documented hand-edit workflow, and it previously reconciled nothing.
- `uninstall` at the home directory recompiles the projects whose configs it just pruned.
- `edit`'s project-scope source migration propagates instead of writing only the global file.
- `eject` at the home directory writes both halves of the pair; it used to write the config half and leave the types sibling missing.

### Every instruction reads `npx agents-inc <cmd>`

Guides, agent playbooks, runtime messages and code comments now use one invocation form — the one that works before the CLI is installed, which is when instructions are read. Prose naming a command stays bare.

### JSON schemas regenerated

The committed schemas predated several Zod edits. Regenerated wholesale rather than patched, so `generate:schemas:check` starts from zero.

## Fixed

### D-281 — both `agents-inc` and `agentsinc` work

The bin map registered `agentsinc` while the help output, the docs and every message said `agents-inc`, so the name promoted everywhere was the one that did not exist after a global install. Both now point at the same entry: neither spelling is wrong, and no existing install breaks. The generated config header stamps `agents-inc` too.

### D-304 — `settings.json` fields this CLI does not own

Running `init` against a real `~/.claude/settings.json` warned about `model`, `statusLine` and `effortLevel` as unknown fields. They are Claude Code's, and it adds settings on its own schedule, so any hardcoded key list here is stale by construction and teaches people to ignore warnings.

The CLI consumes `permissions` and owns nothing else in that file, so the warn pass is gone. Files the CLI does own keep theirs: `marketplace.json`'s unknown-field warning is unchanged, and now has a test standing guard over it.

### D-305 — a plugin matcher that passed on bookkeeping alone

`toHavePluginInRegistry` checked that a registry entry existed. It never checked that the path that entry names exists, let alone that it holds the skill — so a run that wrote the bookkeeping and installed nothing was indistinguishable from a real install. That is precisely the shape a reported plugin-install failure took.

The matcher now requires the install path to exist and to carry the skill's own `SKILL.md`, read from the registry rather than assumed from the cache layout.

### D-308 — a source change silently unassigned skills from sub-agents

An exclusive category is emitted as a single value rather than a one-element list. One of the two config readers restores that to a list and the other does not, and the operations that record a source — adding or removing a marketplace in a project, `eject --source` — used the one that does not. On write-back every exclusive category's entry was dropped from the `stack` section.

The skills stayed installed and stayed listed; what was lost was which sub-agent carried them. The next `compile` then wrote those sub-agents without them. Normalising at the write boundary covers all three callers at once.

### D-309 — the gate's private writer no longer authorises itself

The runtime tripwire is satisfied by a token the gate switches on. That token used to be minted by the internal writer, so a caller that dodged the public entry points and called the writer directly satisfied the check anyway — leaving that one route guarded by lint alone. Only the public entries mint it now, and reaching the writer directly throws before anything reaches disk.

### A project's generated types no longer go stale behind its own config

A project's `config-types.ts` declared only its project-scoped entries while its `config.ts` inlined the active global rows verbatim, relying on the global unions to cover them. Any later global-scope run narrowed those unions, and a project nobody had touched stopped type-checking. The extras now cover every literal the emitted config holds, including the domains array and the stack's category keys.

## Removed

### D-307 — the marketplace-sources settings overlay is withdrawn

The `s` key opens a settings overlay for registering extra marketplaces, and the wizard's root key handler kept claiming `s` while that overlay's text input had focus. Typing any URL containing the letter closed the overlay mid-word and spilled the remaining keystrokes onto the step underneath, where two of them are hotkeys — so no source URL containing an `s` could be entered at all, which is every `https` one.

The surface is behind `WIZARD_SETTINGS_OVERLAY`, off by default, and the seven specs that drive it are gated on the same flag rather than deleted. The input handling is deliberately unfixed: D-307 stays open and carries the fix direction, so the flag cannot be flipped on without doing the work.

## Documentation

Eight subsystems had no reference documentation at all, so an agent working on them had to re-derive the module from source: the seed contract, per-agent model and effort, code generation, build and packaging, the skill primitives, the built-in catalogue, remote source fetch and cache, and the leaf exports. All eight are now written.

Verifying the existing set against the code turned up eight places where a document contradicted it — a model union missing a member in four documents, an agent record missing two fields in four more, a schema count stated as exhaustive that was not, and the wrong hash function named for detecting a locally modified skill. All corrected against the code.

## Note on 0.147.1

`@agents-inc/cli@0.147.1` was tagged in the changelog but never published to npm; the `agents-inc` alias shipped at that number and the CLI did not. Because the alias depends on `@agents-inc/cli` by range, everyone running `npx agents-inc` stayed on 0.147.0 and the `validate` fix in 0.147.1 reached nobody. This release supersedes it: 0.147.1's contents are included here, and both packages ship at 0.148.0.
