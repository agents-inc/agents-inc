# Release 0.144.1 (2026-07-20)

Test infrastructure and documentation for the 0.143.0–0.144.0 fixes. No runtime changes — the published package is functionally identical to 0.144.0.

## Added

- **E2E coverage for every fix shipped in 0.143.0 and 0.144.0** — one spec per defect, each verified to fail against the pre-fix code for the right reason before the fix landed. Covers the global-skill lock on the `f` hotkey, deselect/re-select scope preservation, generated-union narrowing (asserted with a real `tsc` probe), marketplace naming for local sources, the global config's `marketplace` field and plugin deregistration on `uninstall --all`, project-context source-switch divergence, cancelled-`init` reachability, global-scope install reporting, invalid `metadata.yaml` handling, and the `doctor` blind spots.

  Each spec asserts config **and** filesystem state rather than exit codes — a wizard can exit 0 having silently refused the mutation, so an exit code proves nothing.

- Shared E2E infrastructure: `finishWizard` / `abortAndDestroy` teardown, `readSkillBadgesViaEdit`, a `TestEnvironment` type, `completeWithLocalSources`, asserting config readers, and path helpers. Inline literals replaced with `TERMINAL_SIZE`, `TIMEOUTS.SETUP_DUAL`, `STEP_TEXT` and `SOURCE_PATHS`. `E2ESource`, `WizardType` and the matcher expectation types are now exported from their implementations, so `setup.ts` can no longer drift from them.

## Changed

- **`waitForStableRender` renamed to `waitForWizardFooter`** (and `waitForStableRenderAfter` to `waitForWizardFooterAfter`). The old name read as a generic "wait until stable" primitive, but it is a one-string match on the wizard footer text `"select"` and is only valid on screens rendered by `WizardLayout`. Applying it to the dashboard — which paints no footer — hung for the full timeout and cost 72 failing tests. The name now states its own precondition, and every doc explaining the keypress guard carries that precondition rather than just the identifier.

- **Transient toast assertions moved to the raw, append-only output surface**, anchored to a cursor captured before the keypress. The toast renders in an absolutely-positioned row that Ink rewrites in place, so xterm's processed buffer can lose it entirely; the anchoring also prevents a stale earlier toast producing a false pass.

- Two specs migrated off raw `InteractivePrompt` driving onto the page objects, gaining dropped-keystroke protection.

- Assertions that pinned setup-helper state rather than the behaviour under test were re-pinned more strictly — snapshot the project config after setup and assert byte-identity after the guarded edit, instead of merely asserting a file is absent.

## Internal

- Agent findings recorded for the refactor, bug-hunt and review passes, including several that correct the record on their own subject: the shared-constant aliasing predated the refactor blamed for it; a structural config load cannot replace the raw-text stack extractors because it erases the writer's bare-string compaction; and the wizard-footer sentinel described above.

- Parked owner decisions consolidated at the top of the refactor ledger, deliberately without checkboxes so the Ralph loop rule cannot pick them up as work.
