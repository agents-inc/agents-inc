# Release 0.141.1 (2026-07-09)

Wizard tab-bar spacing fix (hoisted domain-nav case).

## Fixed

### Hoisted domain-nav double-counts dropdown reserve spacing

The wizard tab bar reserves vertical space (`marginBottom={3}`) so the absolutely-positioned
per-step dropdown/sub-nav has room to render underneath it without shifting following content.
The **hoisted** domain-nav variant (triggered when domain labels exceed
`DOMAIN_NAV_CHAR_THRESHOLD`, e.g. "Web API CLI Infrastructure Meta Shared") renders that same
nav inline instead of absolutely-positioned, but kept a copy of the same `marginBottom={3}`.
In normal document flow the inline nav already occupies its own height, so the reservation
stacked 3 dead blank rows on top of it — 4 blank lines before the skills grid instead of the 1
every other step shows.

`wizard-tabs.tsx` no longer applies `marginBottom={3}` to the hoisted `DomainNav` wrapper.
Verified via `ink-testing-library` renders of all six wizard steps (stack, domains, build
non-hoisted, build hoisted, sources, agents, confirm) — each now shows exactly one blank line
between its dropdown/nav and the step content.
