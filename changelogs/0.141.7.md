# Release 0.141.7 (2026-07-18)

Removing the only skill an agent's stack referenced in a category no longer leaves a stale reference behind in `config.ts`.

## Fixed

### Removing the last skill in a stack category no longer resurrects a stale entry

Deselecting a skill correctly cleared it from the `skills[]` array, but if that skill was the
only active skill left in its category across the whole selection, the stale reference survived
in the `stack` property — an agent's compiled frontmatter could keep referencing a skill that no
longer existed anywhere.

Root cause: `generateProjectConfigFromSkills` (`src/cli/lib/configuration/config-generator.ts`)
rebuilds `stack` from the current selection via `buildStackForSelection`. That function used to
collapse two different situations to the same `undefined` return value — "no agents in play,
stack genuinely untouched" and "agents in play but nothing left to preload" — and the generator
omitted the `stack` key entirely whenever it got `undefined`. Downstream, `mergeConfigs`
(`config-merger.ts`) treats an absent `stack` key as "this save didn't touch the stack" and falls
back to preserving whatever was already on disk, resurrecting the just-removed skill's entry.

Fix: `buildStackForSelection` now only returns `undefined` when there are no agents at all
(genuinely untouched). Whenever agents are selected, it returns an explicit `{}` if nothing
should preload — the merger already trusted `{}` as authoritative, it just never received one.

Traced scenarios: other categories on the same agent are unaffected; removing a skill that
emptied one of several agents drops only that agent from `stack` (no empty `{}` orphan); a
skill removed at project scope behaves the same as at global scope; dual-scope tombstones still
cannot resurrect a removed skill; the "no agents selected" legacy path still preserves the
existing stack unchanged.

## Findings

- `.ai-docs/agent-findings/2026-07-18-empty-stack-sparse-omit-vs-authoritative-empty.md` — the
  "empty vs. absent" ambiguity that caused this, and the general pattern (don't collapse "I
  didn't touch this" and "I determined this is empty" into the same falsy return value when a
  caller branches on it).
