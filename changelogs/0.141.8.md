# Release 0.141.8 (2026-07-18)

Pushing a global skill or agent removal out to other registered projects now correctly reconciles their `stack` and `selectedAgents`, not just `skills[]`/`agents[]`.

## Fixed

### Propagation left stale stack references in registered projects after a global skill removal

`propagateGlobalChangesToProjects` (`src/cli/lib/installation/local-installer.ts`) rewrites every
other registered project's `config.ts` whenever a global skill or agent is added or removed via
`cc edit` at global scope. It correctly reconciled `skills[]` and `agents[]`, but carried a
project's `stack` forward completely unchanged — so a project-scoped agent that legitimately
referenced a global skill kept referencing it in `stack` even after that skill was removed
everywhere.

Fix: new `computeRemovedGlobalSkillIds` + `retainReconciledStack` helpers prune only the stack
assignments whose skill id was inherited from global and is now gone — every other assignment
(including a project's own project-scoped skills, and skills the project owns independently at
project scope in a dual-scope pair) is left untouched, in order, with `preloaded` flags intact.

### Removing a global agent left its name behind in a registered project's `selectedAgents[]`

Same propagation path: the agent correctly disappeared from a registered project's `agents[]`,
but `selectedAgents[]` was carried forward verbatim and re-unioned with the (now smaller) global
list on every write, so the removed name never got pruned. New `retainReconciledSelectedAgents`
helper reconciles it symmetrically with `agents[]`.

### Also included

- `cc init` registering a project in the global `projects` array is now covered by an E2E test
  exercising two separate projects against the same global install (no duplication, no
  overwriting the first entry).
- Small, currently-inert plumbing addition: `buildAndMergeConfig` gained an optional
  `authoritativeScope` parameter, threaded through from `write-project-config.ts`. It's not
  exercised by anything shipped in this release — it supports the dual-scope work landing
  separately.
