# Release 0.142.3 (2026-07-18)

Test-only fix: `init-dashboard-edit-plugin-install.e2e.test.ts` never actually exercised project scope (D-241), and its assertion was wrong as a result.

## Fixed

### D-241 — Test never exercised genuine project scope, asserted the wrong behavior

A full E2E suite run surfaced `e2e/lifecycle/init-dashboard-edit-plugin-install.e2e.test.ts`
failing reproducibly: installing React globally, then selecting Vue (the other option in the same
exclusive "Framework" category) at what the test labeled "project scope" made React disappear
from the config entirely. The test's own assertion expected both to survive — coexisting across
scopes.

Root cause: the test never set an explicit `HOME`, so the E2E sandbox's `HOME=cwd` default
collapsed it onto `projectDir` — the already-documented D-226 gap — forcing
`isEditingFromGlobalScope=true`. Under that collapse the "Edit" step silently ran as a *global*
edit, where dropping React on an exclusive-category swap is correct behavior; the test was never
actually exercising project scope despite its name. Confirmed not a regression from the previous
release's dual-scope fixes, both by static trace (today's `wizard-store.ts` changes are no-ops on
this exact path) and empirically (swapping in the prior release's `wizard-store.ts` reproduced the
identical failure).

In a **genuine** project-scope edit, the store's existing exclusive-category guard already blocks
this exact scenario — selecting a conflicting exclusive-category skill at project scope while a
different one is installed globally is rejected with a toast ("Global skills cannot be changed
from project scope"). No store change was needed.

Fix: gave the test an explicit, separate `HOME` (the same pattern the dual-scope test suite
already uses) so it genuinely exercises project scope, and rewrote its assertion to match the
already-correct behavior — the conflicting selection is blocked, React remains the sole selected
framework, and Vue never leaks into any config or `settings.json`.

## Findings

- `.ai-docs/agent-findings/2026-07-18-init-dashboard-plugin-test-vacuous-project-scope.md` —
  documents the vacuous project-scope coverage and proposes the standard: any test claiming
  "project scope" must set an explicit `HOME` distinct from `projectDir` (or use the dual-scope
  harness), or it silently tests global-edit semantics instead.
