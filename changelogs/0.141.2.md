# Release 0.141.2 (2026-07-09)

Runtime CLI invocation strings now match the promoted `npx @agents-inc/cli` UX.

## Fixed

### Stale `agentsinc` command promoted in runtime messages

Warnings, errors, and generated snippets across the CLI told users to run bare `agentsinc
<command>` (e.g. `Run 'agentsinc init' or 'agentsinc edit' first.`), but the project's
documented/promoted invocation (per the README's "Getting Started" section) is
`npx @agents-inc/cli <command>`. `agentsinc` remains the real registered binary name in
`package.json`'s `bin`/`oclif.bin` fields (valid for anyone who globally installs the
package) — this fix only changes what the CLI recommends users type.

`src/cli/consts.ts`'s `CLI_BIN_NAME` constant (value `"agentsinc"`) is renamed to
`CLI_INVOKE_COMMAND` (value `"npx @agents-inc/cli"`), with a doc comment clarifying the split
from the registered bin name. All ~21 call sites across commands, config writers, the
installation/skill-fetcher libs, and generated marketplace snippets now render correct,
copy-pasteable commands, e.g.:

> No local skills found. Run `npx @agents-inc/cli init` or `npx @agents-inc/cli edit` first.

A second, undetected instance of the same bug — a hardcoded literal `agentsinc init` in
`source-manager.ts` that bypassed the constant entirely — was also found and fixed.

Tests updated: `installation.test.ts`, `config-types-writer.test.ts`, `edit.test.ts`,
`e2e/interactive/edit-wizard-launch.e2e.test.ts`.
