**Build-order constraint, found 2026-08-16.** `apps/editor`'s typecheck reads the worker's route
types from `apps/server/dist/index.d.ts`, and that directory is gitignored. So **`apps/server` must be
built before `apps/editor` typechecks**, or the editor fails with a type error naming whatever the
worker's contract last emitted (it surfaced as `Type '4' is not assignable to type '3'` during the
seed v4 bump). Nothing in the repository states this today; a clean checkout typechecking the editor
first will fail for a reason that looks like the editor's fault.

#### REPO-42: nothing mechanically reads `.husky/pre-push`

Moved from `todo/cli.md` on 2026-09-02: `.husky/pre-push` is a repository-root file, so it is this
tracker's subject rather than the CLI's.

Re-derive the absence:

```
grep -rln "pre-push\|\.husky" --include='*.ts' --include='*.tsx' packages apps
```

Empty. No vitest project collects shell, and no formatter touches the file — the root `format` is
`**/*.{ts,tsx}` and lint-staged's root pattern is `*.{js,json,yaml,yml,md,mdx}`.

**The specific regression it cannot see**: collapsing the two `bunx turbo run` invocations back into
one `bunx turbo run test test:e2e` — which reads as a tidy-up — restores the concurrency that
reddens about 1 push in 10, and every gate stays green. A "do not tidy the pairs back into one turbo
run" sentence in the hook's header is the entire enforcement today. **CLI-867 (landed 2026-09-02)
removed the prose arguing the suites do not belong in this hook at all** — the OTHER regression this
row names, and the larger one. Nothing documented ever argued for the collapse; that claim was an
error in CLI-867's own record, corrected the same day.

**Deferred rather than ready, because the rule it would pin is not settled.** CLI-865's cause was
falsified on 2026-09-02; until the 1-in-10 red is understood, a checker asserting the hook's present
shape pins a workaround rather than a requirement.

**Its own "no natural home in this repo's vitest projects" sentence is false.** The root
`package.json` already runs three root-subject checkers out of `packages/cli/scripts/` under
`deps:check`, and `ci.yml` gates it. A `scripts/check-*.ts` asserting the hook's text is the obvious
shape — weaker than it looks, since text can be equivalent and still wrong, but it has a home.
