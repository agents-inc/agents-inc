## Defects

### D1: under a live global install, doctor does not name a project's stranded skill (journey 14, project leg)

Repro: `repro/entry-repro-14.sh`
(self-contained: mints both payloads on the worker, builds a fresh HOME under `/tmp/r14.*`).

```
(in ~/proj, config.ts deleted, global install behind it)
    No Orphans              !  1 orphaned agent file
                               - pm.md (not in config)
(control, blank global)
    No Orphans              ✗  1 skill and 1 agent installed here, and no configuration declares them
                               - ~/proj/.claude/skills/web-framework-react
                               - ~/proj/.claude/agents/pm.md
```

Suspected cause: `resolveOrphansCheck` (`commands/doctor.ts`) runs `checkNoOrphans` whenever any config resolved,
including the global one a configless project falls back to. `checkNoOrphans` lists agent `.md` files only.
`checkUnownedInstallation`, which lists skills and agents, runs only when no config resolves at all. The 10-01 half
(`Config Valid` naming a file the project lacks) is fixed.

### D2: `edit --from` repeats its marketplace load warnings three times (journey 39)

Repro: `repro/entry-repro-39.sh`
(self-contained: scaffolds and builds a marketplace with a broken SKILL.md, installs from `~/proj` as the Install dialog
says, then `edit --from` at HOME confirmed in tmux). Output: `init --from` count `1`. `edit --from` count `3`, made of
1 before `Apply this configuration?` and 2 after `Changes:`. Without a registered project the same edit prints it once.

Suspected cause: the global edit recompiles each registered project, which reloads the marketplace (twice per
project). Each load prints its own warnings, and nothing dedupes them per run.

  'npx agents-inc uninstall' … then 'npx agents-inc init'". Since CLI-923, a bare `init` over nothing only prints the
  editor link. The next sentence ("Or build one … `init --from <id>`") is the real route, so the first is half-stale.
- O2: The retired-folder line says `Move it to .agents-inc/claude/.` even when `.agents-inc/claude/` already exists
  beside it (journey 52's both-folders case). Followed literally, it overwrites the live config.
- O3: `edit`'s summary still reads `Edit skills in the plugin` (the root command list and the `edit --help` header).
  Its description is the new spec text.
- O4: A CLI-minted payload (`edit` / dashboard Edit) carries `stackId: null`. The editor opens it with "Clear and start
  from scratch" highlighted instead of the CLI Tool card (shot `19` vs `17`), so the round trip loses the stack's
  identity.

  only).
