plus `xdg-open`/`open` that log to `/tmp/c924/lifecycle/opened.log`). It also sets HOME, `CODEX_HOME`, `BROWSER` and

the next click.

**Tools**:

- `snap.sh`: sha256 plus mtime (in ns) for every file under a scope, excluding `.cache`. "Snapshot identical" means
  both sha and mtime match.
- `inspect.mjs`: each compiled agent's frontmatter `skills:` (preloaded) and its `Invoke: skill:` entries (dynamic),
  compared with the config's `stack` entry for that agent. Prints `MATCH` or `DIFF`.
- `roster.py`: the stack as the fetched `catalog.json` `suggestedStacks` declares it, compared with `config.ts`. It
  also checks that every payload assignment and preload state landed.
- `tc.sh`: TypeScript 6.0.3 `--strict --ignoreConfig` on `config.ts` where it sits. Then a probe importing that
  `config-types.ts` by absolute path assigns bogus `SkillId`/`AgentName`/`Category`/`Domain` literals (expect 4×
  TS2322). Then a copy of `config.ts` with a `{ id: 'bogus-skill-id' }` row (expect TS2322). Written as
  `tsc 0 / probe 4×TS2322 / row TS2322` below.

stack sub-agent whose entry is `{}`. Whether `{}` makes the sub-agent a roster member is for the owner. The catalogue
lists it as one, and the removed wizard treated it as one.

## Observations (not journey claims; for triage)

- **O1. Every link the CLI prints and opens is production, even when the id was minted on the local worker.**
  `Open it: https://agentsinc.sh/editor/?fromId=<id>`, and `xdg-open` received the same URL. Those ids cannot be
  opened from the link. This is the 2026-10-01 minor item, unchanged.
- **O2. `compile` says `Refreshed config-types.ts` when it wrote nothing.** At HOME (row 11) neither sha nor mtime
  changed. At project scope (row 6, B) the bytes were identical but the mtime changed, so the project compile does
  rewrite the file. Row 11's "byte-identical" claim holds at both scopes.
- **O3. A no-op `edit --from` still asks a question.** Row 11 printed `Nothing is removed — this configuration only
adds and re-tunes. Apply this configuration? y/N`, with nothing to add. After `y` it printed `No changes made.`
- **O4. A P→G confirm says `Nothing is removed` although it deletes the project's copy.** Row 15: the copy moves to
  `~/.claude/skills`, and the outcome line is `~ Tailwind CSS ([P] → [G])`.
- **O5. `description` goes stale.** After row 9 dropped Vitest, `config.ts` still reads
  `description: 'oclif, Ink, Zustand, Vitest'`.
- **O6. B's `init --from` misreports what it wrote.** It added nothing (row 6) and listed only the global `config.ts`
  under `Configuration:`, although it also wrote `B/.agents-inc/claude/config.ts` and `config-types.ts`.
- **O7. The editor cannot express a `[P][G]` skill pair directly.**
  - Setting a global skill that global sub-agents carry to `PROJECT` blocks Install until the skill is unassigned
    from every global sub-agent. It took 9 clicks for React (row 4), and Tailwind in row 3 took 4.
  - Moving a sub-agent that carries a project skill to `GLOBAL` blocks the same way (row 16).
