## Defects

**D1 (journey 26). A project installed under a global installation records the global config's description
in its own `config.ts`, over the description its own configuration names.**

- Repro: `repro/marketplace-repro-26.sh`.
  It is self-contained and needs the built CLI, the worker on :8787 and `~/dev/skills`.
  - It builds a scaffold marketplace with two stacks: `acme-api-only` ("Just the acme Hono skill") and `acme-starter`
    ("Every skill acme ships").
  - It installs the first globally from HOME, then installs a project payload naming `acme-starter`.
- Seen: `project config.ts: description: 'Just the acme Hono skill'`. Expected: `'Every skill acme ships'`. The
  same project id in a fresh HOME with no global install records `'Every skill acme ships'` (p18a).
- In the journey's own state, global from acme and project from plain with no description, the plain project claims
  `'Just the acme Hono skill'`. This was observation O1 on 2026-10-01 and is still there.
- Suspected cause (read-only): `mergeConfigs` in `src/cli/lib/configuration/config-merger.ts` lets
  `existingConfig.description` win over the new config's. On a project's first save, `loadProjectConfig` falls back
  to the HOME config, and `existingConfigForMerge` withholds only `name` and `HAND_WRITTEN_FIELDS`, so the global's
  description is lent to the project.
