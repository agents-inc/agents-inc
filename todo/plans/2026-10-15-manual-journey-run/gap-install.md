## Observations

- **Every Install open costs a limiter token.** `useInstallCommand` re-POSTs on every open, even with the selection unchanged (effect keyed on `[open, serialized]`). The worker limits `POST /configs` to 20 per 60 s per `cf-connecting-ip`, so the 21st open in a minute reads `id unavailable — this command starts over in the editor`, with no hint to retry (shots 25, 26). The hook's comment says a re-open "costs a read rather than one of the free tier's 1000 daily writes". That is true for KV, but each re-open still counts against the per-IP limit.
- **A page on an origin other than `WEB_ORIGIN` reads as "offline"** while the worker is up. The CORS preflight fails, the fetch throws, and `unreachable` is shown (shot 31).
- **Crossweb O1 still holds on all three refusals:** step 02 says `Run the installer. It writes .agents-inc/claude/config.ts …, ejects no skills, and links the rest as plugins` above the bare `npx agents-inc init` (shots 22, 25, 28).
- **Swapping the dev server reloads the stale tab.** Vite's dev client reloaded it by itself when I swapped the server (shot 29 shows the new layout before I clicked anything). A production bundle has no such client, so there the reload the note asks for is the user's.
- **Read only, not driven:** a tab whose bundle predates CLI-923 (e.g. `b0fa8961`) would say `id unavailable — this command starts a fresh wizard` / `offline — this command starts a fresh wizard` (`git show b0fa8961:apps/editor/src/features/configure/lib/use-install-command.ts`). That lasts until the tab reloads after the deploy.
