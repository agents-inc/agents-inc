## Defects

Each repro mints its payload by POSTing the editor's JSON (embedded) to the worker — ids are content-addressed, so it
gets the id the editor minted — and runs in a fresh `mktemp` HOME. Default worker `http://localhost:8787`.

**D6 (new) — `eject skills` on a Codex installation writes Claude's `.claude/skills`.** Row 66.
Repro: `journeys/codex/repro-66.sh` (legs A and B). Wrong output: in a Codex-only project "✓ 238 skills ejected to
…/code/a/.claude/skills" and `.claude/` now exists; in a project holding both installations
`eject skills --provider codex --force` → "✓ 228 skills ejected to …/code/b/.claude/skills" and the Claude
installation's skills folder goes from 10 to 238 entries. Suspected cause: `ejectSkills` in
`src/cli/commands/eject.ts` resolves `path.join(projectDir, LOCAL_SKILLS_PATH)`, and `LOCAL_SKILLS_PATH` is
`.claude/skills` (`packages/compile/src/paths.ts`), with no provider in the path. `eject agent-partials` does land in
`.agents-inc/codex/agents`.

content)" about the Claude installation. Suspected cause (unchanged from 2026-10-01): `uninstall.tsx` runs
