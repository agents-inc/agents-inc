## Observations (none changes a verdict)

- **O1. False dependency and assignment warnings when a project sits on a global install.** These are the same class as
  marketplace D6 of 2026-10-01.
  - With a global React and a project payload carrying only Zustand (`init --from rbWAeOc5` in a project under
    `gXl1TiYi`), `init --from` and every project `edit --from` print
    `Warning: Zustand requires one of: React, Next.js, Remix, React Native`.
  - Project `edit --from` also prints `Warning: Skill 'web-framework-react' is assigned to no sub-agent — nothing will
load it.` The global `web-developer.md` does load it. `compile` and `doctor` in the same project print neither
    warning.
  - Reproduce:
    `R=/tmp/c924/modes/run.sh; H=$(mktemp -d); mkdir $H/p; $R $H $H agents-inc init --from gXl1TiYi </dev/null >/dev/null; $R $H $H/p agents-inc init --from rbWAeOc5 </dev/null 2>&1 | grep Warning`
- **O2. (10-01 lifecycle O5, still present.)** With a config present, `doctor` counts a hand-written agent among
  `3 agents validated` and calls it `1 orphaned agent file - my-own-agent.md (not in config)`. `uninstall` calls the same
  file `no agents-inc marker, so this CLI did not compile it`. Nothing offers to remove it, and `compile` does not prune
  it, so the offer and the refusal still agree. The doc comment on `checkUnownedInstallation` in
  `src/cli/commands/doctor.ts` says the config-present warning "is earned by the next `compile` pruning what it names".
  That is not what happens to an unmarked file.
- **O3.** On the `COMPLETED_WITH_FAILURES` ending, `edit --from` prints no trust line, although the run rewrote a writing
  sub-agent (`web-developer`) into an untrusted project. `init`'s failure ending still prints it (37, sabotaged init). The
  skip is deliberate: `reportWhatThisHostCannotCarry` in `edit.tsx` says "Skipped on a run that owes work". So the two
  commands differ on that ending.
- **O4.** An all-eject round trip keeps `marketplaceName: 'agents-inc'` in `config.ts` at each scope that went through
  plugin (journeys 5 and 17). The content is benign.
- **O5.** `edit --from`'s confirm screen lists the skills it will touch and says `Nothing is removed — this configuration
only adds and re-tunes.` The install-mode change itself (`~ React (Eject → Agents Inc)`) is printed only after `y`.
- **O6.** The printed `Open it:` link is fixed to `https://agentsinc.sh/editor/?fromId=…` even under
  `AGENTS_INC_API_URL=http://localhost:8787` (10-01 minor item, unchanged). The id was minted locally, so production
  cannot open it.
- **O7. Rig note.** Non-TTY `init --from` and `edit --from` apply without a prompt, which is how setup installs were
  piped. When stdout is piped through `tee` with stdin at a TTY, the `y/N` prompt does not appear in the pane until a
  key is pressed.
- Timings with the real `claude`: a GitHub-marketplace clone plus 2 plugin installs took about 5 s; a per-skill switch took
  4–6 s; `update` took about 2.4 s.
