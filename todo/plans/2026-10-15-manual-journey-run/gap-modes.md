## Observations (none changes a verdict)

- **O1. Following the editor's own step 01 adds an editor round for global skills.** For an all-global configuration,
  the Install dialog says `Go to your project root`. `init --from` there registers the project, with a project config
  that only inlines the global rows. Bare `edit` from that project then opens the editor on those global skills and
  lets the user flip them. `edit --from <id>` from the same project holds them (`Kept as installed in the global
install … Change them with 'npx agents-inc edit' from your home directory.`), prints `No changes made.` and exits 0.
  - The user then repeats the editor round from HOME. The repeat mints the same id (`SqmxnGKj`), so
    `cd ~ && agents-inc edit --from SqmxnGKj` would have done. The message points to bare `edit` rather than the id it
    holds, and the editor gives no sign that global rows opened from a project cannot be applied there.
  - This is by design (owner ruling 2026-10-02, quoted in `selectionFromSharedConfig`'s doc; www recipe
    `switch-a-skill-to-eject.md`, "A global install can't be switched from a project").
- **O2.** Over an existing installation, the editor's Install dialog still hands `npx agents-inc init --from <id>`
  (footer: `change it later with npx agents-inc edit`). Run as printed, it refuses, exits 1 and writes nothing, and the
  refusal names the right `edit --from <id>`. The www recipe documents this.
- **O3.** The `edit --from` confirm lists the touched skills and says
  `Nothing is removed — this configuration only adds and re-tunes.`
  - The mode arrow (`~ React (Eject → Agents Inc)`) appears only after `y`.
  - Eject → plugin then deletes `~/.claude/skills/<id>/` (row 5 leg 2 removed all three). `deleteEjectedWorkingCopy`
    makes no check for local edits.
  - The www recipe states "Anything you edited is gone"; the TTY confirm does not. This is modes O5 again, seen on the
    editor-authored route.
- **O4. A www sentence is false on claude 2.1.300.** `apps/www/src/content/docs/docs/concepts/install-modes.md`
  reads: "registered in Claude's own plugin store (`~/.claude/plugins/` for global scope, your project's
  `.claude/plugins/` for project scope)". What happens instead:
  - The project-scope plugin is registered in `~/.claude/plugins/installed_plugins.json` with
    `"projectPath": "/tmp/c924/gap-modes/17/h/p"`.
  - Its `installPath` is `/tmp/c924/gap-modes/17/h/.claude/plugins/cache/agents-inc/web-state-zustand/4.0.0`.
  - The project gets only `.claude/settings.json` `enabledPlugins`; no `p/.claude/plugins/` exists (`find`, snapshot
    `$L/snap/17/h-1-A`).
- **O5. Round-trip residue, all benign.**
  - `marketplaceName: 'agents-inc'` stays in `config.ts` at every scope that went through plugin (modes O4).
  - `p/.claude/settings.json` stays as `{"enabledPlugins": {}}`; init had none.
  - HOME keeps the files `claude` wrote: `.claude.json`, `.claude/settings.json` (`extraKnownMarketplaces`), `plugins/`
    and `backups/`.
- **O6.** The Install dialog's text for a configuration with no plugin skill still says `ejects 3 skills into
~/.claude/skills/, and links the rest as plugins`, although no skill is left to link as a plugin.
- **O7. The editor round trip is exact.** Bare `edit` re-published the very ids the editor had minted (`SqmxnGKj`,
  `1g3ghO--`, `0MHk6G2G`, `NTsHU7T9`, `GNWWP5Fh`), and every mode and scope read back correctly in the editor. The
  fresh mint `33huNZ0g` and the round-trip `V_vT45Zl` differ only in the explicit `agents.<name>.{on,scope}` entries
  (`$L/payloads/*.json`).
- Timings with the real `claude`: a GitHub marketplace add plus 3 installs took about 4 s; each per-skill switch took
  under 2 s.

## Corrections

- The brief: nothing proved false. One clarification: the editor has no bulk install-mode control. Its toggles are per
  skill only: the cell pair, and the `•••` panel's Install mode.
- Journeys page, row 17's Journey column: "a global-scoped skill and a project-scoped skill switched in the same
  install" cannot happen in one `edit --from` run.
  - From the project, the global skill is held ("Kept as installed in the global install … a project run only adds to
    the global install").
  - From HOME, the both-scope id is refused (`This configuration cannot be installed here: the home directory is the
global scope`, exit 1).
  - So it takes two runs and two editor rounds, as the brief's route already assumed.
