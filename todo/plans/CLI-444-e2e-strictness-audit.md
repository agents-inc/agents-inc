# CLI-444 — E2E strictness audit

**Status: COMPLETE** — all 193 spec files under `packages/cli/e2e/` classified.

Investigation only. No spec, no source, no fixture was changed, and nothing was executed: every
verdict comes from reading the spec file. No git command of any kind was run.

**Bottom line:** the suite is in better shape than the flow-verification round implied. 118 of
209 verdict rows are SOUND (plus 35 `lifecycle/` files sound enough to need no row),
`lifecycle/` is near-uniformly strong, and **there is no
fixture-planting defect** under the refined rule — every journey a fixture-planted spec varies
is proved reachable from scratch somewhere else. The real problems are four dark journeys (one
of them unflagged and shipping), seven assertions that cannot fail, and a large redundancy
cluster in `commands/` that costs runtime rather than correctness.

## Verdict vocabulary

| Verdict               | Meaning                                                                                            |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| SOUND                 | Drives a real flow, asserts a user-visible outcome, strict enough to redden on the defect it names |
| REDUNDANT             | Another spec already covers the same behaviour at the same or greater strength (named)             |
| CAN-BE-STRICTER       | Right subject, weak assertion (named) — a stronger one is affordable (named)                       |
| IMPLEMENTATION-SHAPED | Asserts internal file shape / internal wiring where the user-visible outcome is the contract       |
| FIXTURE-PLANTED       | **Narrow sense only** — see below                                                                  |
| UNRULED-PINNING       | Asserts a behaviour no ruling, finding or standard established — copied from output                |

Verdicts are per describe-block where blocks differ; otherwise per file.

### FIXTURE-PLANTED is not a defect by itself (owner refinement, 2026-08-08)

Fixtures and mocks are a legitimate efficiency tool for **variant** coverage. The binding rule is:

> Every user journey must have at least one **from-scratch** E2E spec — the journey driven end to
> end from nothing, real binary, asserting observable output. Fixture-planted specs are fine as
> variants branching off a journey that from-scratch coverage proves reachable.

So `FIXTURE-PLANTED` is recorded **only** when one of these holds:

1. **Journey gap** — the journey the spec covers has no from-scratch spec anywhere, so the planted
   state is the _only_ evidence the state exists, and nothing proves the product can reach it.
2. **Unreachable plant** — the planted state is one no real flow can produce any more, so the spec
   is testing a shape that cannot occur (this is the class the flow-verification round was bitten
   by: a fixture writing `scope: "project"` where the wizard writes `scope: "global"`).

Everything else that merely _uses_ a fixture is left unflagged, or flagged on its own merits
(REDUNDANT / CAN-BE-STRICTER / UNRULED-PINNING) without reference to the fixture.

**The journey map below is therefore the highest-priority artefact in this document.** A journey
with no from-scratch spec is the top class; a weak assertion inside a well-covered journey is not.

## Remediation plan, grouped by class

Ordered by risk — what a class costs if left alone — not by row count.

### Class 1 — Unflagged journey gap: `import skill` has no passing E2E

**Rows:** 1 (`commands/import-skill`, 6 `it.fails`).
**Why first:** it is the only journey that ships to users, is advertised in `--help`, and has
zero evidence it works. Every happy path is `it.fails` on one root cause
(`parseGitHubSource` prepends `github:` to local paths). The suite is green and the command
may be entirely broken for the only source type the tests can reach offline.
**Blast radius:** one command, one parser function; no other spec depends on it.
**Mechanical or judgment:** _judgment_ — fixing the specs means fixing or re-scoping the
product path first. The audit's output is the ticket, not the patch.

### Class 2 — Flag-blocked journeys the harness structurally cannot reach

**Rows:** 5 (`new-agent`, `new-skill`, `new-marketplace`, both filter-incompatible files).
**Why second:** four commands and one hotkey have **no** live E2E, and the cause is one missing
harness capability — the E2E harness spawns the binary as a separate process, so `vi.mock`
cannot reach `FEATURE_FLAGS`. CLI-323 already tracks the env-var override. Until it lands,
every future flagged feature inherits the same hole.
**Blast radius:** one change to `src/cli/lib/feature-flags.ts` (`envFlag` already reads env —
the gap is that the harness does not set it) plus un-skipping five files.
**Mechanical or judgment:** _mechanical once CLI-323 lands._ Note that un-skipping `new-agent`
alone would **not** close the journey — see Class 5.

### Class 3 — Vacuous-by-construction assertions

**Rows:** 6 UNRULED-PINNING + the fallback case. These are the ones that cannot fail:

**Mechanical or judgment:** _judgment_ — each needs the intended contract derived from a ruling

`eight-specs-pinned-two-behaviours` finding.

### Class 4 — Generic-absence and alternation assertions

**Rows:** ~18 sites inside CAN-BE-STRICTER rows.
`not.toContain("Failed to")`, `not.toContain("ENOENT")`, `not.toContain("error")`,
`not.toContain("claude")`, `not.toContain("FAIL")`, `toMatch(/[Ss]witch|[Ii]nstall/)`,
`toMatch(/warn|recompilation/)`.
**Why fourth:** the standards already ban both shapes; they are false-negative machines (any
skill id containing "error" trips one) and they cannot discriminate the two outcomes the file
exists to tell apart.
**Blast radius:** 11 files, assertion-line-local.
**Mechanical or judgment:** _mostly mechanical_ — replace with the specific string or the
`STEP_TEXT` member. The alternations need one judgment call each: which branch is the contract.

### Class 5 — Count / floor / existence assertions where membership is affordable

**Rows:** ~24 sites. `toHaveLength(9)`, `toBeGreaterThan(0)`, `toBeGreaterThanOrEqual(n)`,
`fileExists(...).toBe(true)` without content, bare `toHaveCompiledAgents()`, `toContain("2")`.
**Why fifth:** the standards name every one of these ("3 wrong items pass the same as 3 right
items"). The sharpest is `eject` → `toHaveLength(9)`, which is the only thing pinning 5 of the
9 ejected skills.
**Blast radius:** ~15 files, assertion-line-local. `E2E_SKILL_IDS` already exists for the eject
case.
**Mechanical or judgment:** _mechanical_ — swap for `toStrictEqual` on a sorted list, or pass
parameters to the bare matcher.

### Class 6 — Redundant re-runs of one scenario

**Rows:** 26, of which 22 are in `commands/`.
Clusters: `doctor` (4 its, one run), `doctor-diagnostics` (3 clusters), `list` (6 + 3),
`uninstall` (4), `compile` verbose (3) and YAML-verification (3), `help` (5 pairs),
`compile-scope-filtering` (4), `eject` (3), `import-skill` help (3), `new-*` echo assertions.
**Why sixth:** this is a **runtime and flake** problem, not a correctness one. Each duplicate is
a full binary spawn — some a full PTY wizard run — and the standards note PTY tests are
load-sensitive under parallelism. Merging them buys wall-clock and reduces flake surface
without losing a single assertion.
**Blast radius:** large file-count, zero semantic risk if assertions are _merged_ rather than
dropped.
**Mechanical or judgment:** _mechanical, with one rule_ — fold the assertions into one `it`,
never delete an assertion. Do this class **last**: it touches the most files and is the one
most likely to obscure a Class 3–5 fix in review.

### Class 7 — Assertions that import the constant they assert (tautological constants)

**Rows:** not separately verdicted; a cross-cutting observation. 60+ spec files import runtime
values from `src/cli/` — `UI_SYMBOLS`, `EJECT_SOURCE`, `DEFAULT_PUBLIC_SOURCE_NAME`,
`CLI_INVOKE_COMMAND`, `FEATURE_FLAGS`, `buildMarketplacePluginRef`. The standards ban runtime
`src/cli` imports outright ("E2E tests exercise the CLI as a black box").

There is a real distinction inside this set, and it matters:

- **Deriving an expectation from a definition the product must honour is correct** —
  `init-wizard-stack-roster` and `global-scope-install-reporting` read `defaultStacks`, and the
  CLI-441 archive entry records that as the _fix_ ("rewritten to read the roster off the stack").
- **Asserting a rendering constant the product used to produce that same output is
  tautological** — `toContain(UI_SYMBOLS.LOCK)` cannot fail when the symbol changes, because both
  sides move together.

**Blast radius:** ~20 files use the tautological kind. The fix is to mirror the marker glyphs
into `e2e/pages/constants.ts` (which is deliberately `src/cli`-import-free), not to remove the
definition-derived reads.
**Mechanical or judgment:** _judgment to classify each import, mechanical to move the glyphs._

### Suggested order

1 → 2 → 3 → 4 → 5 → 7 → 6. Classes 1–3 change what the suite can detect. Classes 4–5 and 7
change how sharply it detects it. Class 6 changes only what it costs to run, and touching the
most files last keeps the earlier diffs readable.
