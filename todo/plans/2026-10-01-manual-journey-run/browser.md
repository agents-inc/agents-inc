## Defects

**D1. The signed-out composer says "nothing was sent", but it sends the sentence.**
Repro: open `http://localhost:5173/editor/` signed out (`GET /api/auth/get-session -> null`), type any
sentence in the Composer prompt and press Ctrl+Enter.
Seen: the network carries `POST http://localhost:8787/compose`, `content-type: application/json`, body
`{"sentence":"Swap Zustand for Jotai and add Tailwind CSS."}`, answered `401 {"error":"unauthorized"}`.
The proposal reads `Sign in to use the composer — nothing was sent.` (`015-acct-composer-sent-signed-out.png`).
The copy comes from `REFUSAL_COPY["signed-out"]` in `apps/editor/src/features/configure/components/composer.tsx`.
Expected: either the copy is true, so no request is made when the client already knows the session is
signed out (the same pre-POST gate that `scope-reach.spec.ts` asks of a refused save), or the copy stops
claiming that nothing was sent. Journey 50's row describes the request as "signed-in"; the client sends it either way.

**D2. Dark theme: the Install button's counts and the Send button's shortcut hint cannot be seen.**
Repro: choose any stack, then `page.emulateMedia({colorScheme:"dark"})` (or press the theme toggle to dark).
Seen: the Install button reads only `INSTALL`. Its child `11 agents · 25 skills` is `color: rgb(228,224,212)`
on a button background of `rgb(228,224,212)`, the same value. In light mode it is `rgb(139,135,120)` on
`rgb(36,35,32)`. The Send button's `Ctrl ↩` span (`text-faint`) is `rgb(228,224,212)` on `rgb(228,224,212)`,
so it is invisible whether the button is enabled or disabled. On hover the counts show faintly.
Screenshots: `057-ev-dark-install-zoom.png`, `059-ev-dark-send-zoom.png`, `060-ev-dark-send-enabled.png`, `061-ev-dark-install-hover.png`.

**D3. Dark theme: the Output preview's code is unreadable.**
Repro: dark scheme, choose a stack, press Preview.
Seen: identifiers, keys and punctuation (`Domain`, `ProjectConfig`, `skills`, `SkillConfig[]`, `id`,
`scope`, `origin`, braces) carry inline `style="color: rgb(36, 35, 32);"`, which is the light theme's ink,
on the dark pane `rgb(22, 21, 19)`. That is about 1.2:1. Only the string literals and comments can be read.
Screenshots: `063-ev-dark-preview-dialog.png`, `064-ev-dark-preview-code-zoom.png`. The highlighter appears to emit
light-theme colours whatever the theme.

**D4. Dark theme: the stuck filter band's placeholder all but disappears.**
Repro: dark scheme, scroll to 1500 so the bar pins.
Seen: the band turns cream `rgb(228,224,212)` and the `search skills` placeholder is `rgb(196,192,179)`,
about 1.4:1 (`056-ev-dark-stuck.png`, `058-ev-dark-search-band-zoom.png`). In light mode the same placeholder
is `rgb(168,162,148)` on `rgb(36,35,32)`.

**D5. Keyboard focus goes to controls hidden under the docked composer.**
Repro: choose Next.js T3 Stack, scroll to the top, focus `Search skills` and press Tab 25 times.
Seen: focus sits on Svelte's `global` scope radio at `rect [958,935,1002,953]` with `scrollY 0`.
`document.elementFromPoint` at its centre returns the composer `<textarea aria-label="Composer prompt">`,
so the focus ring cannot be seen (`025-j51-focus-under-composer.png`). Tabbing on to the bar sticking,
14 stops were covered this way, among them Vue, `Options for Vue`, every row of plugin/global radios at
y≈898–988, and `Tailwind CSS` at `[917,1000]` (`026-j51-tab-stuck.png`). The page does not scroll,
because each control is inside the viewport; the composer simply overlaps it.

**D6. The Add skill dialog does not return focus to its trigger.**
Repro: reload, focus `Search skills`, press Tab (focus is on `BUTTON Add skill`), Enter, then Escape. Or
click Add skill and press Cancel.
Seen: `document.activeElement` is `BODY` both ways. As a control, Preview and Install opened and closed the
same way return focus to `BUTTON Preview` and `BUTTON Install 10 agents · 13 skills`.

**D7. The left nav's EDITOR item loses its active highlight whenever the URL carries a query.**
Repro: on `/editor/`, type in the search (`?q=query`), click a domain tab (`?domain=ai`), or choose
Selected (`?sel=true`).
Seen: the `EDITOR` link (`href="/editor/"`) loses `data-status="active"` and its `bg-wash` pill, although the
visitor is still on the editor (`021-…`, `034-…`, `035-…`). On a `?fromId=` shared view this looks intended
("Yours is untouched under Editor"), but not for the editor's own filters.

**D8. The blocked Install label runs edge to edge, with its reason in low contrast.**
Repro: choose Next.js SaaS Starter, open `Options for Tailwind CSS`, choose `project` under Install scope.
Seen: the disabled button reads `INSTALL 8 SUB-AGENTS NEED PROJECT SCOPE` with `padding: 0px 0px`,
`scrollWidth 299 > clientWidth 298`; the reason span runs from x 1346 to 1588 past a button edge at 1586.8.
`INSTALL` touches the left edge and `SCOPE` the right. The button is drawn at `opacity: .4`, which puts the
only explanation, `rgb(139,135,120)`, at roughly 1.6:1 against the composited fill

**D9. The install dialog footer breaks the `npx agents-inc edit` command across lines.**

## Corrections

- Brief, "run with cwd `apps/editor` so `import { chromium } from "@playwright/test"` resolves": this is false for a
  script file in the lane directory. ESM and `require` resolve from the file's own location
  (`node $LANE_ROOT/esm-probe.mjs` with cwd `apps/editor` gives `ERR_MODULE_NOT_FOUND`). It needed
  `createRequire("apps/editor/package.json")("@playwright/test")`. And with `HOME` pinned by
  `env.sh`, Playwright looks for browsers under the fake HOME (`…/lanes/browser/home/.cache/ms-playwright/…`),
  so the run needed `PLAYWRIGHT_BROWSERS_PATH=~/.cache/ms-playwright`, which reads that cache and never writes to it.
- Brief, "the install dialog's command (no id minted vs minted)": with the worker up, opening Install always mints
  first (`POST /configs -> 201`). The no-id state appears only when the mint fails. It was reached by aborting
  `POST /configs` inside the browser context, without touching a server.
- Journey 50 row, "the docked composer sends a signed-in `POST /compose`": the client sends `POST /compose` signed
  out as well, and the worker 401s it (D1). "Signed-in" holds for the worker's guard, not for the client.
- Journey 49 row: nothing in its signed-out claims proved false. Its signed-in claims could not be tested (BLOCKED).
