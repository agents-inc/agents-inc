## Defects

**D1. A custom marketplace with no `marketplace.json` is labelled as the public marketplace.**

- Repro:
  - `new marketplace acme`, add skills, do not build.
  - `init --marketplace <acme>`, pick `acme API only`, Local.
  - From the install: `agents-inc search react`.
- Seen: `acme-web-framework-react │ React │ agents-inc │ web-framework`. The same happens for a served tarball source (journey 22: `acme-web-state-zustand │ … │ agents-inc`) and for `plain` (journey 18). In the wizard's Confirm step, with the default Plugin rows, the marketplace reads `Marketplace Agents Inc` for the acme source.
- After `build marketplace` the same search shows `acme` (h21b), so only un-built sources are affected. The spec fixtures for 18 and 22 are un-built, so they cannot see it.
- Root (read-only, by inference): `loadSkillsFromAllSources` in `src/cli/lib/loading/multi-source-loader.ts` has `const primarySourceName = resolvedMarketplace ?? DEFAULT_PUBLIC_SOURCE_NAME;`. Meanwhile `resolveMarketplaceLabels` in `source-loader.ts` says an absent manifest is "using its ref as the label". `defaultOriginFor` in `wizard-store.ts` falls back to `DEFAULT_PUBLIC_SOURCE_NAME` the same way.

**D2. The wizard preselects Plugin for every skill of a source that has no `marketplace.json`, then fails after confirm.**

- Repro: `init --marketplace <un-built acme>` → `acme API only` → Sources step (`capture-pane -e` shows the bold-cyan selection on `Plugin`) → Enter, Enter, Enter.
- Seen: "Install mode: Plugin (native install) … The .claude-plugin/marketplace.json file is missing … Error: Cannot install plugin skills: marketplace could not be resolved from '…/src/acme'. Plugin install mode requires a marketplace", `EXIT=1`. Nothing is written.
- The wizard knows the source has no manifest when it loads, but it still preselects, and offers, a mode it cannot carry out. The `new marketplace` "Next steps" do put the build before `init`, so this only hits authors who skip that order.

**D3. `init --marketplace Y` in a project over an existing global install drops the flag silently.**

- Repro:
  - HOME has a global install from `src/acme`.
  - In an empty project dir: `agents-inc init --marketplace <src/plain>`.
- Seen: the global's dashboard ("Marketplace: …/src/acme", Edit / Compile / Doctor / List). Choosing Edit loads "Loaded 5 skills (local)", which is acme's 5 skills, not plain's 4. Nothing mentions `--marketplace`.
- `init.tsx` comments "Only a bare `init` is diverted to the dashboard", but the condition is `if (!flags.from && (await this.showDashboardIfInitialized(projectDir))) return;`, which diverts `init --marketplace …` too.
- This removes the obvious route into journey 26's state. The only working route found was `init --from` with `payload.marketplace`.

**D4. `share` of an eject install from a custom marketplace leaves the marketplace out, and the id installs nothing elsewhere.**

- Repro:
  - From p18b (installed from `src/plain`, eject): `agents-inc share` → `be8ACvHX`.
  - `curl localhost:8787/configs/be8ACvHX` has no `marketplace` key and no carried content.
  - In a fresh HOME and project: `agents-inc init --from be8ACvHX`.
- Seen: "Warning: Skipped 1 skill(s) this catalog does not know: plain-web-framework-react / Selected 0 skills … Compiled 8 agents … initialized successfully", exit 0. The config records `marketplace: 'github:agents-inc/skills'`.
- `needsMarketplaceNamed` in `src/cli/lib/seed/config-to-seed.ts` exempts `eject` origins ("An ejected copy travels with the project"), but the payload carries no copy.

**D5. Skill slugs are not namespaced, so two marketplaces in one installation collide on slug.**

- Repro: journey 26, route 2. The global is from acme (`slug: hono`), the project from plain (`slug: hono`). Then any of `doctor`, `compile`, `search` in the project, or `compile` from HOME.
- Seen: `Warning: Duplicate slug 'hono': already mapped to 'plain-api-framework-hono', ignoring 'acme-api-framework-hono'` on every command, several times per command. `doctor` prints it between its own rows and still reports "Summary: 15 passed, 0 warnings". The slug map silently resolves `hono` to the skill that is not installed.
- This will be common: every `new marketplace` scaffold ships `slug: example-skill`, and authors copy public skills with their slugs.
- Journey 26 is marked "CLOSED BY CONSTRUCTION", but the construction covers ids only. `todo/cli.md` CLI-596 files this as a fixture problem; it is a product one.

**D6. False "assigned to no sub-agent" warning when a project install sits over a global one.**

- Repro: global from `init --from=BRQP7W9U` (acme hono → api-developer, global), then in a project `init --from=1yODtQ-7` (acme react → web-developer, project). It also reproduces with the plain payload `-Qj0SA5w`.
- Seen: `Warning: Skill 'acme-api-framework-hono' is assigned to no sub-agent — nothing will load it.` But the global config has `'api-developer': { 'api-api': 'acme-api-framework-hono' }` and the global `api-developer.md` contains `skill: "acme-api-framework-hono"`.
- This is not specific to marketplaces.

**D7. Two refusal messages give remedies that are wrong for where they appear.** Both are small wording issues.

- (a) `agents-inc new marketplace agents-inc` says "Choose a name of your own: set package.json 'name', or pass --name." No package.json exists yet, and `new marketplace … --name foo` → "Nonexistent flag: --name".
- (b) The `build marketplace` namespace refusal says "Rename each skill directory and the id in its metadata". The id is SKILL.md `name:`; `metadata.yaml` has no id field. The load-side refusal words it correctly ("the 'name' in its SKILL.md").

**Observations.** These do not contradict any row; they are for the owner to judge.

- **O1.** A project install over a global one rewrites the global config beyond registering the project.
  - Clean repro (h26c): global `selectedDomains ['api']` → `['api', 'web']`, and the global `config-types.ts` gains `'web'` in `Domain`, both because of a project-scoped skill.
  - In h26 the project config (from plain) also took the global's stack description, `'Just the acme Hono skill'`.
- **O2.** The load side accepts a third-party `marketplace.json` named with a reserved name (`"agents-inc"`, ids `acme-*`). No row claims the load side refuses reserved names. Built-in stacks were correctly withheld.
- **O3.** A stackless custom marketplace's domain step offers all 9 built-in domains and preselects web/api/mobile (`DEFAULT_SCRATCH_DOMAINS`). The Mobile grid then shows "No categories to display."
- **O4.** The known open finding "Per-agent assignment is re-derived rather than honoured" reproduces on a custom marketplace's stack. `acme starter` declares only vitest for `web-tester`; `web-tester` gets react, zustand, vitest and example.

## Corrections

**In the journeys page.**

- `user-journeys.md` → "Legs no hand-run drives" says a hand-built marketplace renders "No categories to display". False here: a `new marketplace` scaffold with copied public skills rendered every category it ships. The message appeared only on a preselected domain the marketplace ships nothing in (Mobile, O3).
- Row 26: "closed by construction" holds for ids, not for slugs (D5). Its natural entry, `init --marketplace` in a project over a global install, is unreachable (D3).
- Rows 18 and 22: their fixtures are un-built sources, so neither spec can see the Origin mislabel (D1).

**In the brief.**

- `NO_COLOR=1` does not strip the wizard's truecolor. The Sources step marks the chosen Local/Plugin column only by colour and weight, so the briefed `tmux capture-pane -p` cannot show it, and the `❯` cursor on "Local" looks like a selection when it is not. `capture-pane -e` is needed.
- Journey 22 needs a server whose ETag the driver controls, so I started and later stopped my own fixture on 127.0.0.1:47322. The worker and editor were not touched.
- Journey 35's editor leg fetches `catalog.json` from api.github.com directly. It could only be driven by routing that one request to the CLI-built bytes.
