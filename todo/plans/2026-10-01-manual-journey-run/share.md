## Defects

### 1. `share` from a project drops the global sub-agents' skill assignments, so the round trip does not reproduce them (journey 29)

This is the wizard's default shape: one project-scoped sub-agent with the rest global. Sharing it from the project mints a payload that lists the 7 global sub-agents as `{on:true, scope:"global"}` but carries none of their skill assignments. Their per-agent stack rows live in `~/.agents-inc/claude/config.ts`, and the payload reads the project's file alone. The rebuild compiles all 7 global sub-agents bare.

Reproduction:

```
source $J/env.sh share
export HOME=$LANE_ROOT/j29/home-origin CODEX_HOME=$HOME/.codex   # fresh
cd $LANE_ROOT/j29/origin && agents-inc init                        # tmux
#  Stack: Down x4 → "React Old School", Enter; Domains Enter; Skills Enter x3; Sources Enter;
#  Agents: `s` on "Web Developer" (→ [P]), Enter; Confirm Enter → EXIT=0, 11 skill plugins, 8 agents
agents-inc share                       # → "Sharing 11 skill(s) across 8 sub-agent(s)... ✓ Shared as OhniJqq_"
curl -s localhost:8787/configs/OhniJqq_
#  every skills[*].assignments names only "web-developer"; "meta-reviewing-reviewing": {"assignments": {}}
export HOME=$LANE_ROOT/j29/home-recv; mkdir -p ../recv && cd ../recv
agents-inc init --from OhniJqq_
#  "Warning: Skill 'meta-reviewing-reviewing' is assigned to no sub-agent — nothing will load it."
cmp home-origin/.claude/agents/reviewer.md home-recv/.claude/agents/reviewer.md   # differs (all 7 global agents differ)
```

Origin `reviewer.md` frontmatter:

```
skills:
  - web-framework-react:web-framework-react
  - meta-reviewing-reviewing:meta-reviewing-reviewing
```

The origin body also holds a `<skill_activation_protocol>` listing 8 skills. The rebuild has no `skills:` key, and its body reads `No skills are configured for this agent.` The origin's global `config.ts` holds a `stack` for agent-summoner, codex-keeper, pm, reviewer, skill-summoner, web-researcher and web-tester; the rebuild's global `config.ts` has no `stack` at all.

The project half does round-trip: `web-developer.md` is byte-identical.

**Control:** the same installation shared from `$HOME` (`cd $HOME && agents-inc share` → `CXm8binm`) carries every global agent's assignments. Installed at a fresh HOME with `init --from CXm8binm`, it reproduces all 7 global agents byte for byte.

**Expected (journey 29):** "installing that id into a second untouched directory reproduces it". The producer's own doc comment (`readInstalledConfig`, `src/cli/lib/seed/installation-payload.ts`) promises the same: "a payload minted from a project describes the whole of what is installed for it rather than half of it".

**Why no spec sees it:** `lifecycle/share-round-trip-compiled-bodies` builds its origin with `initGlobalWithEject` and runs `share` with `dir: origin, globalHome: origin`, which is the HOME-minted case and works. `commands/share`'s origin is built by `init --from`. No spec shares from a project whose sub-agents are split across scopes.

**Also affected:** `edit --ui` mints through the same `seedPayloadForInstallation`, so editor round trips started from such a project (journey 23) lose the same curation.

This is for the owner to rule on; it may be accepted as harmless.

## Observations (not defects)

- **Editor link points at production.** `share` and `share --stdin` print `Open it: https://agentsinc.sh/editor/?fromId=<id>` even when `AGENTS_INC_API_URL` points at the local worker. The only override is `SEED_API_URL` in `src/cli/lib/seed/fetch-seed.ts`, and there is none for the editor base. On this rig, the printed editor link cannot open the id it names. This affects development and test rigs only.
- **The update check writes to `~/.cache`.** `share --stdin` was seen writing `~/.cache/agents-inc/version` (`{"latest":"0.164.0","current":"0.165.0"}`). That is `@oclif/plugin-warn-if-update-available`: third-party, CLI-wide and timing-dependent (`list` on another fresh HOME wrote nothing). It is the only file the run touched, and it is outside any installation.
- **`init --from` at `$HOME` names the global config `agents-inc`.** It writes `name: 'agents-inc'` into the global `config.ts`. The wizard's global config, and the one `init --from` writes as a side effect from a project, both use `name: 'global'`.
- **One refusal is formatted differently.** The journey 24 write-over refusal (leg f) prints its `Error:` block indented without oclif's `›  ` gutter. Every other refusal in this lane uses the gutter. Cosmetic.
- **The wizard's Sources step looks like it selects Local but installs Plugin.** With `NO_COLOR=1`, the step renders `❯ Local   Plugin` per row. The `❯` is the cursor, not the choice, and Enter installed as **Plugin** (the default). Nothing on the screen or the Confirm step shows which mode was chosen.

The product does not refuse that pair. `edit --from 5Gg040PG --ui` printed `Open it at https://agentsinc.sh/editor/?fromId=5Gg040PG` and `To apply it here instead, run 'npx agents-inc edit --from 5Gg040PG'.`, exited 0, and made no request. - **Row 29:** it reads **COVERED**, but a project-minted id with global sub-agents does not round-trip (Defect 1). The specs it names only ever mint from `$HOME`.
- **The brief:** nothing false.
