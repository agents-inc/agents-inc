## The adjudicated CLI-405 derivation rule

Derivation never reads the adapter list; it reads what remains when the adapter slices are
deleted. If the remainder is a followable skill — its patterns executable in a project
containing none of the listed hosts — the support surface derives **nothing**: it is routing
metadata, and any pairing wisdom is recommends-shaped D-306 material (setup-env, the PostHog
trio, sanity, axiom-pino-sentry usage, and now payload). If the remainder is not followable —
every surviving pattern presumes one of the hosts — derive `requires needsAny` over the
catalog's full enumeration of hosts the body actually serves, per the maestro doctrine
(setup-axiom-pino-sentry → [nextjs]; turborepo-ci → [turborepo]; class B by identity is this
branch by definition — resend-react-email, setup-resend). The test runs on the skill's
**demonstrated content**, never on the upstream product's install story (payload: Next-mandatory
install, host-neutral taught surface → nothing) and never on the class letter (both outcomes
occur inside class C). CLI-405 therefore needs the two shapes distinguishable in metadata —
"optional wiring for these hosts" (derive nothing) versus "runs only inside one of these hosts"
(derive needsAny) — before any generation code exists; SKILLS-01's unconditional "a skill whose
only adapter is `nextjs` derives `requires needsAny [nextjs]`" sentence is superseded by this
conditional form.
