## Doctrine notes

- **Followability discriminates within a radio'd pair.** lexical and tiptap got opposite
  binding verdicts from the same test run on demonstrated content: tiptap-minus-React is a
  licensed vanilla route missing one constructor call; lexical-minus-React has no way to obtain
  an editor or register anything. Proportion (6% vs ~6.5% React lines — nearly identical!) and
  self-scope (absent in both) could not have separated them; the remainder-followability test
  did. Upstream first-classness of vanilla (true for BOTH editors) changed neither verdict —
  the payload doctrine cuts both directions: a product's install story neither creates nor
  removes a binding.
- **The enumeration boundary (maestro vs visual-regression):** enumerate catalog hosts in a
  `needsAny` only when the thing the skill needs can enter a valid selection _only_ via catalog
  skills (maestro: an app to drive). When out-of-catalog alternatives (BackstopJS/Percy-class
  tools) coexist with fully reachable selections, the enumeration hard-blocks a real steady
  state and must be declined; pairing advice goes to D-306.
- **Carrier-presumption is the `requires` discriminator for skill-to-skill bindings:** a body
  that opens on its carrier's client without instantiating it, and self-defers general usage to
  the carrier, earns `requires` (claude-vision, openai-whisper). A body that carries its own
  complete client — even when that client is literally the carrier's package pointed elsewhere —
  earns none (litellm; wire-protocol reuse ≠ dependency, and the binding would assert a false
  provider of the projects the skill exists to serve).
- **Single-member open categories are legitimate exactly when** no existing open category serves
  the member AND an incumbent radio must survive (sse → web-streaming). Distinct from the
  duplicate-category smell (B5's elysia: two categories, one purpose slot) and from
  residue-fits cases (tanstack-table: an open home already existed).
- **Membership consistency over tier labels (storybook):** when a rule's existing members
  already include a community-tier integration, tier cannot be the rule's admission criterion;
  state the criterion that actually explains membership (listing on the vendor's own supported
  page) and apply it uniformly — it admits qwik, keeps astro out, and survives the discovery
  that "officially supported" was never true of solidjs either.
- **Vacuous-edge radios decouple cross-batch verdicts:** because every cross-framework
  `web-ui-kit` pair is unreachable via `requires`, B3's vuetify placement is structurally
  independent of whatever verify-B1-B2 concludes about `web-client-state` — same reachable
  semantics under either outcome. Consistency handoffs between such radios are advisory, never
  blocking.
- **Advice lines must be checked against the catalog's own defaults:** B4's vite ⊥ nextjs
  dubious-combo note is contradicted six times by `default-stacks.ts`. A D-306 line that calls
  a shipped default dubious without naming it leaves the tension for a user to find.
