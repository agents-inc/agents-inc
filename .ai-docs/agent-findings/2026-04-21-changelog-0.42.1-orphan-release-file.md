## What Was Wrong

`changelogs/0.42.1.md` exists (dated 2026-02-19) with real release content — removal of `react-native-stack` from default stacks plus TODO doc updates — but is never referenced from `CHANGELOG.md`. The roll-up jumps directly from `[0.42.0] - 2026-02-19` to `[0.43.0] - 2026-02-21`, skipping 0.42.1 entirely.

Evidence that the work shipped (orphan, not draft):

- Fix commit `ec4f928f fix: remove react-native-stack from default stacks` exists on `main`.
- Sibling patch releases in the same range (`0.41.1`, `0.41.2`, `0.43.0`) all have CHANGELOG.md entries.
- No `chore(release): 0.42.1` commit exists; no git tag `0.42.1` exists. The release-commit step of the protocol was skipped.

So the detailed changelog file was written, the code change landed, but the release-commit / roll-up step was dropped on the floor.

## Fix Applied

None — discovery only. Per the task rules, `CHANGELOG.md` is immutable; historical gap left as-is.

## Proposed Standard

Add a release-integrity lint to `.ai-docs/standards/commit-protocol.md` (and consider a CI check): for every `changelogs/X.Y.Z.md` there must be a matching `## [X.Y.Z]` heading in `CHANGELOG.md`. A pre-release script walking `changelogs/*.md` against the roll-up would catch this drift before the next release ships. No retroactive edits to historical CHANGELOG.md sections.
