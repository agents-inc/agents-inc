# Release 0.152.0 (2026-08-06)

Feature flags obey the environment, and the package sheds its dead weight

## Added

### Feature flags can be switched from the environment

Every feature flag now reads an `AGENTSINC_FLAG_<NAME>` environment variable before falling back to its built-in default. `1` or `true` switches a flag on, `0` or `false` switches it off, and anything else — including the variable being absent — leaves the default in charge.

```
AGENTSINC_FLAG_NEW_SKILL_COMMAND=1 npx agents-inc new skill my-skill
```

The gated `new` commands stay off by default and still say so when invoked bare. What changes is that the switch exists at all: the flags used to be plain constants that the bundler inlined into the compiled commands, where nothing — not a test, not a user — could reach them. Reading the environment at load time is what makes gated code paths testable, and it means trying an in-progress feature no longer requires editing source.

The current flags: `SOURCE_SEARCH`, `SOURCE_CHOICE`, `WIZARD_SETTINGS_OVERLAY`, `INFO_PANEL`, `FILTER_INCOMPATIBLE`, `NEW_SKILL_COMMAND`, `NEW_AGENT_COMMAND`, `NEW_MARKETPLACE_COMMAND`.

## Fixed

### The package no longer ships its own tests

Every release up to and including 0.151.0 shipped sixteen compiled test files and their sixteen source maps inside `dist/`, because the build's entry patterns swept up the tests sitting beside the code they cover. They are excluded now, a packaging test pins it so they cannot return unnoticed, and a `files` entry pointing at a folder that never existed is gone too. You download less and run exactly the same CLI.

### A real terminal now beats the CI guess

Ink — the library that draws the wizard — decides whether it is talking to a real terminal by looking at CI environment variables before looking at the terminal itself. With `CI` set in the environment and a genuine terminal attached, it buffered every frame until exit: for a spinner that was cosmetic, for the wizard it meant the screen you were supposed to answer was never painted. Every render now goes through one wrapper that says so explicitly when standard output is a terminal, and Ink's own detection still applies everywhere it should — piped output and genuine CI keep their non-interactive behaviour.

## Changed, invisible from outside

- Both code generators run under bun, and both now sit inside gates: the JSON-schema check runs in CI, the types check runs before every publish.
- Eight dependency version specs aligned with the rest of the repository; no dependency resolves differently.
- Hooks linting is on for the terminal UI (an Ink codebase is a React codebase), and the handful of wrong dependency lists it found are fixed.
- A drift guard now proves the vendored config-sharing contract still matches its canonical copy in the web workspace — divergence used to surface on a user's machine at decode time.
