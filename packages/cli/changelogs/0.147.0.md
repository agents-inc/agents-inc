# Release 0.147.0 (2026-08-01)

One summary panel on both surfaces, a corrected Sources grid, and a terminal-size minimum that is actually enforced

No ticketed work ships here either — every defect below was reported from the running CLI during a single session, and each was reproduced against the real binary through a PTY before and after its fix. **D-266 is narrowed, not closed**: two of its symptoms are gone, the cause is untouched.

The theme, in one line: five of the defects were being actively concealed by the tests and docs meant to catch them.

## Added

### The confirm step renders the info panel

The confirm step and the `I` overlay always rendered the same skills/agents summary, but only the overlay had the header. The confirm step now shows the same `Marketplace …` / `Stack …` block above the same divider, because both surfaces render one component.

### A terminal-size guard that survives a resize

Shrinking the window mid-session previously left the wizard painting card borders through its own footer. It now shows `Terminal too short (need 20). Please resize.` and restores the wizard — with selections intact — when the window grows back.

## Fixed

### A first `init` marked nothing as added on the Sources tab

The confirm step listed every skill with a green `+`; the Sources tab showed no markers at all. Both classify against the hydration snapshot, which is `null` on a genuine first init, and they read that `null` oppositely — the confirm step as "everything is new", the Sources tab as "flag nothing".

The null branch is deleted rather than mirrored: a missing snapshot is now an empty set, and an empty snapshot already flagged every row. Only the `null` case changes, which is exactly the divergence.

### Three Sources-grid rendering defects

- **The `Scope` caption is gone.** The column's `Global` / `Project` row headers already say what it is. The gutter and the headers stay; a same-width spacer keeps `Local` / `Plugin` over their cells.
- **The status marker is one fixed two-column cell on every row**, blank when the row has no status, inside the focus highlight. The marker previously carried its own trailing space and the focused branch added another, so a focused row rendered `+  Name` against `+ Name` unfocused — and unmarked names started two columns left of marked ones. `SKILL_NAME_WIDTH` widens 24 → 26 by exactly the marker width, so every name that fitted before still fits.
- **Locked and pending-removal rows no longer paint a `✓`** on their selected source. Editable rows express selection with colour and weight and never drew one, so the glyph existed nowhere else in the grid — and landed on the row about to be deleted, where a checkmark reads as the opposite of what the row means.

### `Enter` was dead on the confirm step with the info panel open

Pressing `I` there and then `Enter` produced a byte-identical frame: no install, no transition, no way forward but `I` or `Esc`. `WizardLayout` replaces the step with the panel rather than overlaying it, so `StepConfirm` unmounted along with the only `Enter` handler. Once the confirm step _is_ the panel, the hotkey has nothing to reveal — it is no longer offered or advertised there.

### The `Marketplace` row could never name a real marketplace

It read a store field that no code anywhere ever wrote, so it always printed the hardcoded public default. It now derives from `SkillConfig.source`, which already records where each skill came from — so a project initialised from a custom marketplace names that marketplace. Three distinct cases: any marketplace-sourced skill names its marketplace; an all-ejected set says so; an empty set falls back to the default. The last two are different states, and the `I` overlay opens on the empty one from the stack step.

### The terminal-size minimum was documented but never enforced

`SCROLL_VIEWPORT.MIN_TERMINAL_HEIGHT` had **zero importers in all of `src/`** while the live gate hardcoded its own copy — so changing the documented constant did nothing. That gate also ran once, before Ink rendered, and dropped its resize listener as soon as the terminal was big enough.

`MIN_TERMINAL_SIZE` (`COLS 80`, `ROWS 20`) is now one constant read by the startup gate and a `WizardLayout` guard, sharing one message builder. The guard replaces the wizard tree rather than overlaying it — Ink lays a mounted subtree out at the small size regardless of what is drawn on top.

**20 is measured, not chosen.** On the build step, 16 and 17 render corrupt and 18 is the first clean frame — that is where `MIN_VIEWPORT_ROWS` starts being satisfied.

### The stack step bled at the advertised minimum

The first screen of `init` was corrupt at 20 _and_ 24 rows: the six-row ASCII logo starved that step's list past the same cliff. `LOGO_MIN_TERMINAL_ROWS` hides it below 26. Every other step was already clean at 20.

### The summary header overprinted instead of clipping

At short heights the `Marketplace` and `Stack` rows collapsed into one unreadable line. Ink defaults every `Box` to `flexShrink: 1` — the opposite of Yoga's own default — so the panel's `flexShrink={0}` protected only itself and Yoga squeezed the header rather than letting the viewport clip it.

### `getStackName` returned `undefined` for an unknown stack

Its one caller passes `selectedStackId`, which is only ever written from a stack the live matrix already holds, so the fallback was unreachable — a silent-failure path. It asserts now.

## Changed

### Deliberately unchanged: no scroll affordance on the grid steps

The Skills grid discards the `hiddenAbove` / `hiddenBelow` counts it computes, and the Domains, Agents and Stack views use a hook that never computes them — so all four clip silently with no `N more below`. **Kept.** On a grid that dense a half-cut card is self-evidently "there is more", and an affordance would be noise. Recorded at each call site so it reads as a decision rather than an oversight.

This narrows **D-266** without closing it: the shared scroll gates still stop clipping below `MIN_VIEWPORT_ROWS`, and raising the terminal minimum only moves users off the cliff.

## Proposed standards

Not yet written into the standards docs:

- A negative rendering assertion needs a positive guard proving its subject is on screen.
- Never assert a rendering invariant at a geometry where the subject does not render.
- A JSDoc explaining a workaround is a defect report unless some spec pins the un-worked-around form.
- A regenerated geometry snapshot must be read, not accepted.
- `TerminalSession.getScreen()` documents itself as viewport-only but reads from buffer line 0, which makes every absence assertion scrollback-sensitive. Flagged, not changed — every page object depends on it.
