# Release 0.159.0 (2026-08-24)

A configuration can be piped in and a shared id can be opened, the E2E harness takes ownership of the dist guards, and three rows close by disproving their own premise (CLI-328, CLI-329, CLI-597, CLI-621, CLI-768, CLI-769, CLI-772, CLI-782, CLI-798, CLI-799, CLI-816, CLI-819, CLI-820, REPO-07)

**The recurring shape of this release is a filed claim that measurement overturned.** CLI-799 was filed as a window nothing could close and is closed by one line. CLI-329 listed four items and had one subject: two of them name things that no longer exist in the tree, and a third was not a stale value but a constant with no reader at all. CLI-782's alarm was false — the gate had always run against its own 60-second budget, not the 10 seconds the row claimed — while its observation was true and worth acting on. In each case the row was correct when written and a later change invalidated the fact it rested on, with nothing in place to notice.

## Added

### CLI-621 — a configuration can be piped in, and a shared id can be opened rather than applied

`share --stdin` mints an id from a payload on standard input instead of from the installation here, so a tool that composes a configuration never has to write one to disk first. `init --ui` and `edit --ui` open agentsinc.sh on the id `--from` names, which is the other end of the same trip: the wizard is no longer the only way to turn a shared id into something you can look at.

Three refusals stand before any POST, each naming what it read — an empty pipe, JSON that will not parse, and a payload the seed contract rejects. `readAllOf` concatenates Buffers before decoding so a multi-byte character split across two chunks survives; the test bisects an `é`, because a split landing on a character boundary is one the naive per-chunk decode passes.

`e2e/fixtures/cli.ts` gains an `input` option, and it is what makes the pair of specs possible at all. `execa` gives a child with no `input` an inherited stdin, and under vitest that is not a terminal either — so "refuses an empty pipe" and "reads a full one" differ only by this option, and neither could be written without it.

### CLI-816 — the interactive dashboard carries the counts the piped one prints

`formatDashboardText` printed skill count, agent count, install mode and marketplace; the `Dashboard` component printed the title and four menu rows and nothing else. So the screen a person actually sits in front of was **less informative than the output they get by piping it**, and every assertion on the subject stayed green throughout, because each path was only ever checked against itself.

Both render `dashboardCountLines` now — one producer rather than two renderers that agree today. The parity gate reads its expected lines out of that function rather than restating them, and ships with a control: a `dashboardCountLines` returning nothing satisfies a containment check for free, so the control is what stops the pair passing vacuously. Mutation-proved in both directions.

### CLI-328 — the mirrored E2E constants get the third party that compares them

`e2e/pages/constants.ts` carried a flat "NO imports from src/cli" while 233 imports from `src/` lived across every other directory of that tree, spec directories included — so the rule read as one nobody applied. It is narrower than it was written, and it is right: what this one file buys by declaring instead of importing is the ability to FAIL. A spec that imported the constant it asserts on would move both sides at once and assert nothing, and if the product renumbered `EXIT_CODES.CANCELLED` the imported form would agree with the new number and stay green.

So the duplication is ruled ON rather than reversed, and `scripts/check-mirrored-constants.ts` is the half that was missing. `check-screen-sentinels.ts` already does this for the wizard's four screen subtitles and registers nothing else, deliberately — a pair is registerable there when both halves are a literal STRING under a key. This is the other side of that boundary: the mirrors whose values are numbers, or nested a level down.

`EXIT_CODES` compares **one-directionally**, and that is the design. Every code the product declares must be mirrored with the same value; the E2E side may hold codes of its own, and `UNKNOWN_COMMAND: 127` is the live example — the shell's command-not-found status, which a spec sees when `dist/` is absent and the CLI never emits. `TERMINAL_SIZE.SHORT` contributes its `rows` and not its `cols`: rows must track the size gate exactly, while `cols: 100` sits deliberately above the gate's 80.

## Changed

### CLI-798 — the dist door costs zero call sites

It was per-file discipline across 249 spec files with nothing gating that a new spec remembered it: forget the call and the reward is a 45-second timeout naming nothing, and no reader could tell "omitted correctly" from "forgot". `e2e/setup.ts` is a `setupFiles` entry, so one `beforeAll` there runs before every spec file in the suite. `spec-gates.test.ts` now asserts the ABSENCE of the call rather than its presence, so the discipline cannot grow back.

### CLI-772 — branding resolves per field, not per file

`resolveBranding` fell back per FILE — the project's config if one existed, the global one otherwise — so a project config declaring no `branding` resolved to the shipped default and never consulted the global config behind it. A user who branded globally stopped seeing their own name the moment any project config existed, which is every installed project, and nothing announced it: the name simply reverted.

The per-field test block survives the tagline's removal on one field, because its discriminator was never two fields. It is a project config that EXISTS and is silent about branding — exactly the per-file regression it was written for.

### CLI-819 — a fixture config must be one the CLI would write

`writeProjectConfig` stops diagnosing and starts refusing. Rendering a fixture through the product's own writer proves its FORM; reading it back and writing it again proves its CONTENT is reachable, because the loader normalises. Nineteen of 150 fixture configs failed that round trip — all one root cause, all in four files: a stack key derived from a skill id's prefix, which is the derivation the conventions forbid in fixtures as much as in product code.

The fixture skill changes identity to clear it, because the correct keys forced two exclusive skills into one stack. That is why the row was filed rather than fixed in passing: it is a change to what five specs cover.

### CLI-769 — the ASCII logo is deliberately not brandable, and now says so

`branding.name` reaches six surfaces, so a white-labelled installation says its own name throughout. The mark does not follow it, and that is the decision rather than an omission — it is the product's, not the installation's. Filed by an agent that found a white-labelled install still drawing it and read the gap as unfinished branding; recorded at the constant so the next reader finds the answer instead of refiling it. `package.json`'s `description`, the first line of `--help`, is the same class and the same answer.

## Fixed

### CLI-597 — a stack naming a withdrawn skill says so instead of dropping it

`convertStackToResolvedStack` filtered its per-category `skills` map and left `allSkillIds` unfiltered, so the two disagreed — and `allSkillIds` is the one that reaches a user: the wizard returns it verbatim as the selection when a stack is picked, and the editor's read model counts and lists it. A marketplace whose `stacks.ts` outlived one of its own skills therefore selected an id nothing could resolve, and the mismatch surfaced only once somebody picked that stack. Both are filtered now, and the ids that fall out are named in a warning rather than dropped in silence.

`built-in-catalogue.md` had recorded this as the third DIFFERENCE between the generation-time and runtime resolvers, as though it were a design. It was a defect, and the document now says so.

### CLI-329 — a stood-down `doctor` row prints the glyph its own table declares

`formatStatus` returned the literals `"!"` and `"-"` while `UI_SYMBOLS.DISCOURAGED` and `UI_SYMBOLS.SKIPPED` existed for exactly those states. The second one mattered: `SKIPPED` is an EN-DASH, so a skipped check printed the same character as `UI_SYMBOLS.REMOVED`, which is deliberately an ASCII hyphen and means the opposite.

Both e2e assertions moved together, and one of them is a NEGATIVE — a glyph change that updated only the positive would have left `not.toMatch` matching nothing and passing for a reason it does not state.

Three of the row's four items had no subject left: `step-settings` does not exist, `SOURCE_HEADER_NAMES` does not exist, and `UI_SYMBOLS.CHECKBOX_CHECKED` was filed as a stale value the UI contradicts when it had no reader at all — so the answer there was deletion.

### CLI-799 — the window a throwing `beforeAll` opens is closed

Filed as unclosable: the door has already passed, a throwing `beforeAll` skips every `beforeEach` under it, and so both registered guards are blind. The first half is true, and it is most of what a lifecycle spec does — its `beforeAll` is where it spawns, installs and waits. The second half is false. **Measured on vitest 4.1.10**: a setup file's `afterAll` runs even when the spec's `beforeAll` threw, and its throw is reported ALONGSIDE that error rather than in place of it. The spec still fails for its own misleading reason, and the real cause is now printed beside it.

### CLI-820 — the findings gate reads the repository, not the machine

The scan walked the working tree rather than what git tracks, so a gitignored directory under a scanned root contributed symbols nobody had written. It takes an `isIgnored` predicate now, defaulted to one `git ls-files --others --ignored --exclude-standard --directory` per root with a prefix test.

### CLI-782 — the title gate takes `languageOptions`, not the whole shared base

9,424ms to 5,786ms under contention, 2,294ms solo. The row's alarm was false and is corrected in `todo/archive.md`: the gate has always run against its own 60-second budget rather than the 10 seconds claimed, and its docblock had provisioned that headroom deliberately. The observation — that it took the whole config when it needed one field — was true.

## Removed

### CLI-768 — `branding.tagline`, a schema-published field with no output site

It promised _"Custom tagline shown in wizard header"_; the wizard header renders the logo and the tab bar, and no tagline text has ever been printed anywhere. The field was accepted, resolved, and read by nothing.

The pin is the DROP rather than the absence: `brandingConfigSchema` is a bare `z.object`, so an unpublished key is stripped silently rather than refused, and a name-only assertion passes whether or not the drop happened. The published JSON schema is checked separately, because `additionalProperties: false` makes a leftover tagline an ERROR for an editor validating a user's config while the parser merely drops it — and that file is hand-maintained rather than generated, which cost one regenerate to discover.

### REPO-07 — the old web monorepo, deleted from disk

1.1G freed. The safety net had done its job: `origin/main` held every commit, and the only uncommitted work was a staged rewrite of `docs/configurator-todo.md` that is the direct ANCESTOR of the `todo/` folder — its items 8, 9 and 10 are WWW-01, WWW-02 and WWW-03, and its item 7 is CLI-740's coverage bullet. Preserved outside either repository anyway; the remote is untouched and re-clonable.

## Backlog

**CLI-821** — five `UI_SYMBOLS` members with no reader anywhere in `src` or `e2e`: `DISABLED`, `SCROLL_UP`, `SCROLL_DOWN`, `CURRENT`, `UNSELECTED`. Filed rather than folded into CLI-329, which deleted the two its own row named and stopped there. Each looks live — `SCROLL_UP`/`SCROLL_DOWN` read as the scroll-overflow affordance, which the product actually paints as text — and `DISABLED` is a second name for the same en-dash as `SKIPPED`, so deleting it needs a look at whether the two states were meant to diverge. The symbol table now says this beside each one rather than asserting a use that is not made.

## Findings

[`2026-08-24-an-exhaustive-list-states-a-count-its-checker-never-reads.md`](../.ai-docs/agent-findings/2026-08-24-an-exhaustive-list-states-a-count-its-checker-never-reads.md) — `check-enumeration-drift` holds an exhaustive documentation list against the symbol it enumerates and does that job: adding one `STEP_TEXT` member reddened two documents in the same run, naming it. The list in `e2e-infrastructure.md` is introduced by a stated COUNT, and that number is prose the check does not read. It stood at 185 against 187 actual before this release touched it — two members appended correctly, the number in front of them not moved, by the same hand in the same file. The finding prefers deleting the count to enforcing it: the checker already guarantees the list is complete, and the sibling document states no total and has never drifted.
