# Release 0.173.0 (2026-10-23)

`doctor` downloads each marketplace on every run, the editor keeps a saved configuration per marketplace and its
stack-switch question waits for the stack, and a sub-agent goes off with its last skill (REPO-44, CLI-925, CLI-915,
CLI-865)

## Added

### REPO-44 — a saved configuration per marketplace in the editor

- **Each marketplace keeps its own saved configuration.** Loading another marketplace opens the configuration this
  browser saved with it, or a new, empty one. The configuration on screen stays saved with its own marketplace, with its
  stack, skills, options and sub-agent choices, and loading that marketplace again reopens it as you left it. The
  switcher does the same as a load.
  - The marketplace you load becomes the active one, so a reload continues on it and the grid shows only its skills.
  - With something selected, the Load dialog says where the selection stays before the second press:
    `Switching to <marketplace> opens the configuration saved with it, or a new one.`
  - Loading the marketplace already on screen re-reads its catalogue and keeps the selection, less any skill the
    catalogue no longer carries.
  - A saved marketplace that no longer loads keeps its configuration saved with it, and a pick made while it waits
    does not overwrite that configuration.
  - Loading another marketplace while a link is open leaves the link: its id leaves the address and that marketplace's
    own configuration opens. The link still opens what it carries. On a link a bare `edit` made inside a project, the
    global entries it holds go with the link.
- **Applying a saved stack built on another marketplace loads that marketplace, then the stack**, so the stack's skills
  survive a reload and the configuration on screen stays saved with its own marketplace. The question before it says
  so.

## Changed

### REPO-44 — the docs, the tests and the code

- **The docs** describe a configuration per marketplace, a global sub-agent staying on in a link a bare `edit` minted
  inside a project, Retry on a saved stack that could not load, and `doctor` downloading every run.
- **The server's compose specs stub the rate limiter**, so a burst that crosses a clock minute no longer fails them,
  and a spec pins that `/compose` counts a person's calls across their sessions and apart from another person's at the
  same address.
- **Code over a closed union dispatches through a switch that stops compiling when a variant is added**, nested
  branches became guard clauses, and constants are checked with `satisfies`. Behaviour is unchanged.

### CLI-865 — specs that sampled once after a fixed delay

- **The summary-panel, panel-scroll and measured-height specs wait for the settled frame** instead of sampling once
  after a fixed delay, so a busy worker no longer fails them.
- **The terminal-poll spec judges the run's own polls**, not every timer in the process.

## Fixed

### CLI-925 — `doctor` and the saved marketplace copy

- **`doctor` downloads each remote marketplace on every run**, whatever ETag the marketplace answers with, and never
  reads a saved copy in its place.
  - When that download fails though the marketplace answered, the `Marketplace Reachable` row fails under
    `Could not reach <source>` with `the download failed and only a saved copy came back`. giget's saved tarball is no
    longer counted as a download, and the saved copy, its record and giget's tarball stay as they were.
  - Where the saved copy differed from the download (edited, damaged or out of date), it is replaced and the row ends
    with `The saved copy differed from the marketplace and has been replaced`.
  - A `doctor` run interrupted mid-download leaves giget a whole tarball, and the next run counts what the marketplace
    serves.
- **A load outside `doctor` that giget serves from its saved tarball records that copy under the ETag it was saved
  with**, not the marketplace's newer one, so the next load fetches the update.

### REPO-44 — two installations, a skill without a name, and the editor

- **`doctor` passes a project holding a Claude and a Codex installation.** Each block reads the skills its own
  installation copied in, so the Codex block finds a carried skill in `.agents/skills` rather than `.claude/skills`.
- **Where a home holds a Claude and a Codex global installation, `doctor` and `uninstall` use the project's own
  provider's global.** `doctor` checks the project beside the global it inherits and finds that global's carried
  skills; `uninstall` takes the project off that global only and leaves the other untouched.
- **In a folder holding no installation, `doctor` checks the global installation it inherits under that
  installation's own provider**, finding its carried skills where that provider copied them.
- **A marketplace skill with no `displayName` is skipped with a warning naming its file**,
  `Skipping '<file>': invalid metadata.yaml — missing required field: displayName`, and the rest of the marketplace
  loads. A link naming only that skill installs its sub-agents empty, with the warning.
- **In the editor, a sub-agent whose last skill goes switches off, with the toast**, on a link the CLI minted, a link
  shared from a project and a link a bare `edit` made inside a project, whether the grid, the roster or the options
  panel removed it. A sub-agent clicked off stays off when its last skill goes and comes back, and on a link that is a
  built-in stack the stack's sub-agents stay on.
- **A held global skill set back to global keeps the rows the project gave its own sub-agents** while it was at project
  scope. Only the sub-agents the link holds return to what arrived.
- **The question before an account's saved stack replaces changes waits for the stack.** It shows loading where the
  marketplace goes and holds Switch until the stack arrives, then names the marketplace or says what switching
  discards. When the read fails it says `Couldn't load this stack.`, with Retry in Switch's place; Retry reads the stack
  again, and Keep my setup closes with the selection as it was.
- **Load and Switch keep keyboard focus** through the read their own press starts.

### CLI-915 — a link's description in the editor's preview

- **The editor's preview shows a link's own description over its stack's**, as the install writes it.
