# Release 0.170.2 (2026-10-18)

Mutation testing finds what the tests missed: a marketplace naming a private address is refused wherever it is
set, and `uninstall`'s plan, `edit --from`'s report, `eject --output` and `compile`'s skill count are fixed (REPO-44)

**Before you upgrade.** A marketplace in a project or global `config.ts` that names a private or reserved address, or
a network share, now makes every command that loads the marketplace exit 1, naming the file; `doctor` fails its
Marketplaces row instead. `uninstall` in a project that holds only your own skills exits 0 with
`Nothing to uninstall.` and removes nothing.

## Fixed

### REPO-44 — what mutation testing found

- **A marketplace naming a private or reserved address is refused however it is spelled.** The host is read with the
  URL parser giget downloads with, so octal (`0177.0.0.1`), percent-encoded, fullwidth-digit and long-form IPv6
  spellings of a private address are refused, and so is an IPv6 address with a port. The check now covers the
  reserved ranges too (`0.0.0.0/8`, `100.64.0.0/10`, `192.0.0.0/24`, `198.18.0.0/15`, multicast, `240.0.0.0/4`, `::`,
  `fc00::/7`, `fe80::/10`, `ff00::/8`) and IPv6 forms that carry an IPv4 address: mapped, translated, compatible,
  NAT64, 6to4 and Teredo. A host the parser cannot read is refused as an invalid URL. `localhost` is still accepted
  on purpose: it is how a cached remote source is tested without a public server.
- **A marketplace set in `config.ts` is checked as well.** A project or global config naming such an address made
  `compile`, `search`, `doctor` and `eject` fetch it. `compile`, `search`, `eject` and `edit --from` now exit 1 with
  `The marketplace in <path> points to a private or reserved IP address: "<url>"`, and `doctor`'s Marketplaces row
  fails with the reason. Every download and cache revalidation is checked again before it fetches.
- **`uninstall`'s plan names only what it then removes.** It named `.claude/skills/` when no skill there was the
  CLI's, and the agents folder when no agent there was. A project holding only your own skills, or only an empty
  `.claude/skills`, now gets `Nothing to uninstall.` and is left as it is, the empty folder included. An empty agents
  or skills folder is tidied away when the run removes something else, so a `.claude/` left holding nothing is
  removed rather than kept. Warnings about a `metadata.yaml` that does not parse print before the plan. An unreadable
  one now stops the run before the plan with the read error; it stopped after the plan with
  `Failed to remove local files`. Both exit 1 and remove nothing.
- **`edit --from` reports a project copy added beside a global install once.** Adding a project copy of a skill or
  sub-agent installed globally printed `+ React ([G] → [P])`, as if the global install had moved, and then a second
  line for the same change: `~ web-developer (agent: skills reassigned)`, a tuning line such as
  `defaults → model opus`, a source line or `files rewritten`. Dropping the copy again did the same. Only the
  `+ … [P]` or `- … [P]` line prints now. Retuning an existing pair still prints its tuning line.
- **`eject --output` writes into an existing folder.** It refused any existing path with
  `Output path exists as a file`. Only a file is refused now. `eject all --output <new folder>` copies the skills as
  well: the partials created the folder first, so the skills step found it and skipped.
- **Registering a project no longer rewrites every registered project.** With no stack in the global config, a
  project write whose only global change was the registration list read as a stack change, so every registered
  project was rewritten, its config types regenerated and its sub-agents recompiled.
- **A skill id of `.` no longer deletes the whole skills folder.** It resolves to the folder itself, and only a
  malformed config can carry one. It is now refused like `..` or `/`.
- **`compile` counts a plugin installed at both scopes once** in `Discovered N skills (P from plugins, L local)`.
- **An emitted `config.ts` writes an empty array as `[]`.** Where the key's line passed 100 columns, it printed `[`
  and `]` on two lines.
- **An external skill added in the editor gets a `cliDescription` that keeps a last word that fits.** Where the room
  ended exactly on a word, the label dropped it: `…with tracked…` for `…with tracked changes…`.
- **The worker's crawl takes no description from an empty `#` heading** or from the line under it.

## Added

### REPO-44 — mutation testing

- **StrykerJS mutation testing runs from the repository root.** `bun run mutation` runs the CLI's first pass
  (`stryker.config.json`). Each workspace has `stryker.<workspace>.config.mjs` and a static pass beside it, run with
  `bun run mutation <file>`. Reports go to `reports/`, which git ignores. It is not a gate: a surviving mutant is a
  weak test to look at, not a score to hold.
- **The specs catch what the mutants showed they missed.** Share of mutants caught, before → after:

  | Workspace        | Caught        | Tests before → after      |
  | ---------------- | ------------- | ------------------------- |
  | compile          | 40.3% → 97.4% | 138 → 390                 |
  | matrix           | 81.2% → 98.0% | 352 → 401                 |
  | api              | 91.7% → 100%  | 13 → 14                   |
  | api-mocks        | 40.2% → 85.6% | 29 → 102                  |
  | ui               | 0.5% → 6.3%   | 23 → 55                   |
  | editor           | 30.1% → 42.9% | 669 → 889                 |
  | server           | 47.9% → 70.2% | 95 → 149                  |
  | cli library code | 66.8% → 96.0% | 7,067 → 8,257 (whole CLI) |
  | cli commands     | 40.8% → 94.6% | (in the line above)       |

  The ui and editor figures are low because most of their code runs only in a browser, which Stryker's in-process
  runs do not reach; of the mutants their tests do reach, both catch about 96%.

## Changed

- **The commit hook formats `.mjs` and `.cjs` files.** Its Prettier pattern listed `.js` only, so a root
  `stryker.*.config.mjs` reached the tree unformatted. (REPO-44)
- **Comments across every workspace say only what the code cannot.** No shipped behaviour changed; the vendored
  matrix types were regenerated to match. (REPO-44)

## Backlog

Not filed as tickets yet.

- `eject skills`, or `eject all --output` into an existing folder, copies no skills without `--force` and warns
  `Skills already exist`, even when the folder is empty.
- `eject --output` naming a link to a folder fails with exit 1 and fs-extra's error.
- `uninstall` without `claude` on the PATH names a plugin in its plan, deletes its folder and leaves its
  registration, with no warning.
- `uninstall` prints `Skipping '<skill>'` for each of your own skills before `Nothing to uninstall.`; whether it
  should is open.
- `edit --from` prints `Switching 1 skill(s) to …` when a project copy in another install mode is added, though the
  global copy is kept. Not reproduced: it needs a plugin install.
- The private-address check reads the URL's text, so it cannot see a redirect, a `.json` source naming another URL,
  a name that resolves to a private address, or a marketplace the host already registered and refreshes by name.
