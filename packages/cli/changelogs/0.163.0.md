# Release 0.163.0 (2026-09-04)

Every compiled sub-agent gets a slimmer, cacheable prompt and a deterministic completion gate, and a skill's own trigger sentence finally reaches the agent that loads it (CLI-872, CLI-874, CLI-876, CLI-884, CLI-888)

**The recurring shape of this release is a value arriving by a route that made the defect indistinguishable from the design.** A skill's `usageGuidance` was stripped by a schema that never named it, so the category-derived placeholder looked like what the product had always meant to write. `compile` never seated its catalogue, so a local skill's stated guidance fell back to that same placeholder and the next `compile` wrote it back — two commands undoing each other, both correct-looking. A fan-out derived each project's type unions from the catalogue of the command that triggered it, so the project's own `compile` restored them and the fight was invisible from either end. And a carried skill installed over a catalogue id inherited the incumbent's `displayName`, `slug` and `category` on the next load, so the impostor rendered under the catalogue's own name. In every case the wrong value was well-formed, and what found it was asking where the value came from rather than whether it looked right.

**Two rows were settled by owner ruling rather than built.** CLI-874 proposed dropping the researchers and testers to `sonnet`; the ruling went the other way and the fleet is uniformly Opus 5 at 18 of 18. CLI-876 asked which number the `SKILL.md` budget should take once converted from lines to tokens; the answer is neither, and the number is gone from all six sites that carried it.

## Added

### The summoner context-engineering programme

The owner's five rules for frontier models — positive framing, progressive disclosure, a cache-stable prefix, single-writer reviewers, deterministic gates — applied to `agent-summoner`, `skill-summoner`, the shared template and the four standards that govern them.

**The baseline is the part of a compiled agent that comes from the template rather than from the agent's own five files, so every byte of it is carried eighteen times.** Six methodology partials become one `operating-principles.liquid`; the shouted core-principles block and the skill-activation harangue go with them. Both summoner playbooks fall from roughly 1,460 lines to a few hundred, and the rendered baseline drops about 85% in the no-skills posture.

**The volatile half moves to the end, and that is a cache decision before it is an editorial one.** A compiled agent IS a sub-agent's system prompt, so the file's leading bytes are the cacheable prefix of every invocation. The skill list is the one block that moves without the agent's role moving — it is rewritten whenever a user edits their stack — and while it sat mid-body, every such edit invalidated the playbook and the output format beneath it.

**A writing sub-agent now stops against a gate rather than a promise.** "Check your work before stopping" is advice a model may decline to take; a `Stop` hook running the project's typecheck is a process that runs whether it does or not, and exit 2 returns the compiler's own output so the agent iterates instead of reporting done. It is inert where it cannot be right — no npm, no `package.json`, no `typecheck` script — and it is **typecheck only** by owner ruling: a type error is the one failure a stopping agent must not report as done, while a lint finding or a failing test is the project's own judgement to gate on, and a project's suite can exceed the 600 s hook timeout and fail open. A project declaring its own completion gate replaces this one rather than running beside it. It is **composed** with the agent's declared hooks rather than branched against them, which is what the template's old `if`/`elsif` pair got wrong: an agent declaring any hook at all — a `PostToolUse` formatter, say — silently lost the gate, with nothing reporting it.

The frontmatter spelling is `Stop`, not `SubagentStop`, and that was read from the shipped binary at 2.1.259 rather than from published documentation. Claude Code rewrites `Stop` to `SubagentStop` when registering a sub-agent's frontmatter hooks, so either spelling fires there — but an agent run as the main session through `--agent` has its hooks stored raw, where only `Stop` fires. `Stop` is correct in both modes.

Reviewers lose `Write` and `Edit`. The verifier is never the fixer: a finding repaired in the same pass is a finding nobody else ever reads.

Thirty review passes plus a seven-lane owner review. The record, rulings, corrections ledger and final gates are in [`plans/summoner-context-engineering-2026-09-03.md`](../../../todo/plans/summoner-context-engineering-2026-09-03.md); the review is in [`plans/summoner-review-2026-09-03.md`](../../../todo/plans/summoner-review-2026-09-03.md).

### `isolation` and `experimental.cacheTtl` reach compiled frontmatter end to end

`AGENT_ISOLATIONS` and `CACHE_TTLS` join the frontmatter vocabulary `@workspace/matrix` vendors, so the CLI and the editor spell both keys identically — a browser rendering a compiled agent has to, or the two front doors emit different frontmatter for the same agent. All four schemas that read an agent accept them, the loader and the resolver forward them, and the sanitiser strips them.

**`cacheTtl` is emitted only when an agent declares it and is deliberately never defaulted.** `5m` is Claude Code's own default; `1h` bills cache writes at a higher rate, so a generator setting it for every agent it wrote would raise the bill of everyone who installed one without being asked — and it is ignored outright while a subscription runs on usage credits, so the cost would sometimes buy nothing. Whether the trade is worth it depends on how the agent is used, which is the installer's knowledge rather than the author's.

**No shipped agent carries `isolation`.** The CLI supports the key because Claude Code's frontmatter documents it and a consuming project may want it; the owner does not use worktrees (ruling 2026-09-03). Supporting a key and using it are separate decisions.

### CLI-872 — a skill's own trigger sentence reaches the sub-agent that loads it

Every one of the 238 catalogue skills states a specific `usageGuidance` — `meta-design-expressive-typescript` says "Use when writing or refactoring TypeScript functions, data transformations, store actions, or any code that mixes logic levels" — and the compiled agent said `when working with meta-design` instead, derived from the category key. That line is the only thing telling a sub-agent when to reach for a dynamic skill, so the whole mechanism rested on a sentence about the filing rather than about the skill. It is the inverse of the standing rule against deriving stated metadata from an id or a path.

**Two zod schemas in `packages/matrix` were stripping the field, which is why the fallback looked like the design.** `usageGuidance` is optional on `SkillCore`, so a schema that omits it delivers the same value by a route nothing can tell apart from the skill stating nothing — and omitting it from `matrixSkillSchema` stripped it from every fetched `catalog.json`, making every marketplace look like it states none.

A **blank** sentence counts as none, and `??` alone does not say so: the field is `z.string().exactOptional()`, so a catalogue stating an empty string is valid, and an empty bullet is a row of the activation protocol saying nothing — strictly worse than the category sentence it displaced.

The editor's preview mirrors `statedUsageFor` sentence for sentence rather than importing it, which is that file's standing contract: the two front doors draw the same bullet for the same skill or the preview is wrong about a line a reader can diff.

Only half (a) of the row landed. The `SKILL.md` `description` half needs scoping first, since those files live in `agents-inc/skills`, so the row stays open.

## Changed

### CLI-874 — the shipped fleet runs uniformly on Opus 5

Retired by owner ruling: "just make everything opus 5, that's easier." `convention-keeper` and `tester/api-tester` were the only two not already there, so the fleet is 18 of 18. `prompt-bible.md` section 4's rule — match the model to the hardest judgement the role makes — stands as authoring guidance for a consuming project's own agents, and now records that this product's own fleet does not vary the axis.

**A uniform roster costs the model assertions half their reach, and two specs were rewritten rather than left reading as rigorous.** No `defaultModel` can now distinguish "the compiler read THIS agent's metadata" from "it read some other agent's" or "something invented that value" — a resolver answering a hardcoded `opus` produces the same byte as one reading the metadata. The assertions still catch a default that is _dropped_, because `agent.liquid` writes `model: {{ agent.model | default: "inherit" }}`. Where a spec needed proof that an override _arrived_ rather than coincided, it moves to `config.ts`, where an override that never arrived writes no key at all.

### CLI-876 — the `SKILL.md` budget number is gone rather than converted

Retired by owner ruling: "we don't need a skill budget number." The numeric target leaves all six sites that carried it — `skill-atomicity-bible.md`'s Content Standard paragraph, the `core.md` target-size row, the no-extraction-needed row, the migration checklist and the single-`core.md` test, plus `skill-summoner/playbook.md`.

**The audit that preceded the ruling is the argument for it.** The proposed ~1,500 tokens could be reached by **0 of 238 skills** — the smallest is 7,141 characters — while the existing ~500 lines flagged 42. Two numbers three times apart, both defensible, neither measuring the thing that matters. A threshold invites trimming to the number rather than to the job. What replaces it is the rule the number was a proxy for: `SKILL.md` is the decision layer, and code moves out when a reader looking for which approach to take has to page past implementations to find it.

### The provenance marker's bytes are constant across releases

`<!-- Generated by agents-inc — do not edit; compile rewrites this file -->`. The marker carried the CLI's version, so it moved on every release and invalidated the whole prompt prefix of all eighteen agents for a string nothing reads back. The version still travels, in the trailing volatile block where a change to it costs nothing. `hasProvenanceMarker` matched on the marker's **shape** while the text varied and still does, so an agent compiled by any release — before this change or after it — is recognised by any other, and `stampProvenanceMarker` rewrites rather than stacks, which is what upgrades an agent stamped by an older release.

### A refused frontmatter names what actually failed

Both plugin compilers printed `Required fields: 'name' and 'description'` whatever had gone wrong, so an agent rejected for an unknown key or a bad enum value was reported as missing two fields it had declared correctly — and that throw is the only thing a `build` run surfaces for a failed agent. The agent side carries the reason out of the parse; the skill side drops the hard-coded sentence and leans on the `warn` `parseFrontmatter` already emits, because five of its six call sites skip rather than throw.

## Fixed

### CLI-884 — a carried skill cannot install itself over a catalogue's own

`init --from` installed a skill carried inside a shared configuration over an id the loaded catalogue already owned, writing the payload's bytes into the catalogue skill's own directory. **The run exited SUCCESS and `doctor` reported no warnings**, and nothing afterwards could tell the two apart: the local-skill merge inherits an incumbent's `displayName`, `slug` and `category` on the next load, so the impostor rendered under the catalogue's own name and placement. Found by driving all 51 rows of `standards/e2e/user-journeys.md` by hand against the real binary and the live store.

Root cause: `seatExternalSkill` was the only writer of `matrix.skills` that took an id unconditionally — one line before calling `claimSlug`, which refuses exactly that collision on the slug axis.

**Three refusals now, and each answers what the others cannot.** The _loaded_ catalogue catches a collision one marketplace along, with ids the shipped set has never heard of. The _shipped_ catalogue is the half no payload can move — `payload.marketplace` steers which catalogue is loaded, so a payload naming a marketplace that does not ship the id it impersonates meets no incumbent in the loaded matrix at all. And the _disk_, because the matrix cannot answer for bytes: the `local` carve-out that keeps `edit --from` re-appliable also exempts a skill the user wrote by hand or ejected from a marketplace, and a directory with no readable `metadata.yaml` never reaches the matrix to be asked at all. `forkedFrom.path` is the discriminator there, being written only by the shared-configuration route.

Both catalogue refusals are decided before anything is seated, and every destination is judged before any is written: the seat writes into `matrix` in place, and a guard that threw on the first collision it met would have overwritten whatever it did on the way there.

An external skill's default usage line now calls `defaultUsageGuidance` rather than spelling the sentence itself — the same _call_ rather than the same words, because this file had drifted on both halves and one carried skill's cue read `Use when working with Brainstorming` off disk and `Use when working with web-tooling.` during the run that installed it.

Finding: [`agent-findings/2026-09-03-the-external-skill-seat-is-the-one-writer-of-the-catalogue-that-takes-an-id-unconditionally.md`](../.ai-docs/agent-findings/2026-09-03-the-external-skill-seat-is-the-one-writer-of-the-catalogue-that-takes-an-id-unconditionally.md). It stays `partial`: an independent re-verification lane defeated the first guard with the original repro plus one extra field, which is CLI-887.

### CLI-888 — a fan-out writes each project from the project's own catalogue

`propagateGlobalChangesToProjects` and `pruneGlobalEntriesFromRegisteredProjects` derived each registered project's `config-types.ts` unions from the **triggering** command's catalogue, so a skill only that project's catalogue carried lost its category and domain on every global fan-out — and the project's next `compile` put them back. Two commands fighting forever, with neither end able to see it.

A registered project's own local skills, and the skills of the marketplace _its_ config names, are in that project's catalogue and in nobody else's. Three readers depend on it and none can be satisfied by the triggering command's: which of the project's entries survive is decided by their categories, `buildProjectTypesExtras` derives the project's `Category` and `Domain` unions from them, and the config half's writer reads the seated singleton directly with no argument reaching it.

**Fixed by deleting the `matrix` parameter outright rather than correcting the value passed.** Each project's catalogue is seated per project by `withCatalogueSeatedFor`, lifted out of `operations/project/recompile-project-agents.ts` into `loading/catalogue-seat.ts` — so the defect is unrepresentable rather than repaired, there being no argument left to get wrong.

**The uninstall sibling needed it most.** It runs after the global manifest is gone, so the project falls back to the standalone types form, which declares its unions from the catalogue outright rather than extending an imported one. Derived from the uninstalling command's catalogue, a global uninstall would have taken a project's own taxonomy with it.

The regression is the byte comparison no per-installation check can make — the project's `config-types.ts` identical across global → project → global — paired with a permitted case where a global addition legitimately widens the union. Finding: [`agent-findings/2026-09-03-a-derivation-read-the-catalogue-of-the-command-that-triggered-it-rather-than-the-project-it-was-writing.md`](../.ai-docs/agent-findings/2026-09-03-a-derivation-read-the-catalogue-of-the-command-that-triggered-it-rather-than-the-project-it-was-writing.md).

### `compile` renders against the catalogue it is compiling

The defect CLI-872 exposed. `compile` never seated the merged matrix, so the module-level singleton stayed at its process-start default — `BUILT_IN_MATRIX`, which never carries a local skill — and a locally-installed skill's stated guidance fell back to the per-category placeholder. Different bytes from what `install` last wrote, so the following `compile` rewrote every agent carrying one.

The seat is scoped to the pass's `projectDir`, never the invoking `cwd`, and is **returned** as well as seated so the two halves can take the postures they each need. The render degrades. The type refresh **aborts**, because every union there is derived from the catalogue: with none loaded it would narrow them to the built-in catalogue's own categories while `config.ts` beside it still keys its `stack` under the ones that just vanished — not a degraded answer but a pair that stops type-checking.

### The compiled-agent frontmatter schema accepts the keys its own template emits

`.strict()` means a key the schema does not name is not merely ignored: `validate` reports the agent as invalid, and the plugin compiler refuses the parse and throws on the agent it was asked to package. Two of the three keys the template emits were refused for as long as it took one change to reach three of the four schemas that needed them. Quiet, because no agent this repository ships declares any of the three. Finding: [`agent-findings/2026-09-03-the-schema-validating-a-compiled-agent-refuses-two-keys-its-own-template-emits.md`](../.ai-docs/agent-findings/2026-09-03-the-schema-validating-a-compiled-agent-refuses-two-keys-its-own-template-emits.md).

### An agent `metadata.yaml` the loader refuses is named, with its reason

The loader threw a `ZodError` whose own message is a JSON dump of its issues, and the warning it produced was the only place a user is told which `metadata.yaml` is wrong. It now names the path and formats the issues — this is the last boundary that still knows which file the value came from, since everything downstream reports against a compiled `.md` the user never wrote. The loader also stopped silently dropping `effort`, `disallowedTools`, `permissionMode`, `outputFormat`, `hooks`, `isolation` and `experimental` on the way through.

### A hook definition carrying no actions is refused rather than emptied

`AgentHookDefinition.hooks` was optional while the loader's schema was too, so a block written with its actions one level flat was stripped to `{}` with no error, `agent.liquid` emitted the empty definition, and the refusal arrived from the frontmatter reader against a compiled file the user never wrote. `plugin.json` keeps `Partial` of the type at its own boundary, because nothing in this CLI reads a manifest's hooks and refusing a shape we never read would drop the whole plugin from discovery.

## Proposed standards

**Two clauses for `packages/cli/CLAUDE.md`'s "Test Assertions", both raised by lanes that hit the gap and both left to the owner** — that file is theirs to curate. They are CLI-875.

**(a) Binding an expectation to repo-internal generator input.** The existing rule offers two rows — bind a symbol whose deletion should break the test, or keep the literal for text the product renders — and a value a generator copies out of a source file _in this repository_ is in neither, so it resolves to the second and the pasted form is what the rule appears to ask for. Two expectations in `scripts/generate-matrix-package.test.ts` each pasted an agent's whole `description`; the first reddened the moment that description was reworded. Proposed: read it from the source file, because the mirroring argument behind `e2e/pages/constants.ts` does not apply when the source file _is_ the authority.

**(b) Presence rosters over optional files.** The count rule governs _how_ to assert a roster and is silent on _whether_ one is owed. `agent-partials.test.ts` asserted that every agent directory holds `critical-requirements.md` and `critical-reminders.md` while the reader takes both through `readFileOptional` and the template guards both — so an agent authored by following the shipped playbook's own optionality reddened the suite. Proposed: never assert a presence roster over files the product treats as optional; put the mechanism that makes the absence legal under assertion instead, which is the stronger claim.

**A defect in the release checklist itself.** `commit-protocol.md`'s findings-path check —

```
grep -o '[^ )]*agent-findings/[^ )]*\.md' packages/cli/changelogs/{version}.md
```

— does not strip markdown link syntax, so it captures ``[`agent-findings/x.md`](../.ai-docs/agent-findings/x.md`` as one path and reports **every** citation as MISSING. Re-derived against the shipped 0.162.0 and 0.161.1 notes, where every cited file exists: both report all paths missing. The form that works, and that was run for this release:

```
grep -oE '\]\((\.\./)?\.ai-docs/agent-findings/[^)]*\.md\)' packages/cli/changelogs/{version}.md \
  | sed -E 's/^\]\((\.\.\/)?//; s/\)$//' | sort -u \
  | while read -r f; do test -f "packages/cli/$f" || echo "MISSING $f"; done
```
