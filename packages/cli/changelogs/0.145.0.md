# Release 0.145.0 (2026-07-29)

Wizard interaction contract, cross-scope propagation, uninstall, and the non-interactive command surface (D-226, D-240, D-256, D-257, D-258, D-259, D-260, D-261, D-262, D-263, D-264, D-265, D-268, D-269, D-270, D-271, D-272, D-273, D-274, D-275)

Most of the command-surface fixes below came from a multi-agent sweep that drove the built binary through every common use case in sandboxed environments, verifying `config.ts` and `config-types.ts` at both scopes plus the `.claude/` filesystem after every mutating step. Defects that only appear when you actually run the CLI — a `validate` that fails on a healthy install, a `list` header reading `vplugin`, a global uninstall that orphans registered projects — are the kind a passing test suite will not surface.

## Added

### D-240 — agent recompilation propagates to registered projects

Propagating a global change rewrote each registered project's `config.ts` but never recompiled its agents. `writeScopedConfigs` now returns the propagated project paths and `init` and `edit` feed them to a new `recompileRegisteredProjectAgents` operation, which recompiles each project at project scope with per-project failure isolation.

### D-258 — the sources step marks newly added skills

Skills added during the session now carry a green `+`, using the same shared symbol as the info panel, complementing the removal marker from D-257.

### D-275 — compile hints at global-scoped agents

Compiling from a project whose agents are all global-scoped printed only "No agents to recompile", which reads like there was nothing to do. It now names the count and says where to run compile to rebuild them.

### `compile` regenerates `config-types.ts`

The documented workflow is to hand-edit `config.ts` and then run `compile`, but the type unions that give that edit its safety net were never regenerated, so a skill added by hand stayed an invalid `SkillId`. Every pass now regenerates the unions for the scope it compiled, matching the wizard write path exactly — standalone narrowed unions at global scope, import-and-extend at project scope — including the early return where the scope has no installed skills, since the config is what drives the unions. A failed refresh downgrades to a warning; the compiled agents are already written.

These refresh loads use a new `matrixOnly` option that skips the source clone for the default source, keeping `compile` offline on a cold cache. Together with `skipExtraSources` it is byte-identical to the wizard's fully tagged load, pinned by a parity test.

## Changed

### D-260 — `s` is the sole dual-scope toggle (breaking)

Spacebar and `s` both acted on dual-scope pairs with different semantics, which needed session-rebuilt bookkeeping to stay coherent. `s` now round-trips `[P][G]` to `[G]` and back on its own, for skills and agents alike, and spacebar is inert on any globally-backed row, emitting the global-locked toast instead. The persisted-pair guards, the `_sessionRebuiltScopePair*` fields, the `INSTALLED_AT_BOTH_SCOPES` toast and `collapseDualScopeAgent` are gone.

**Breaking:** spacebar no longer collapses a dual-scope skill or agent.

### D-274 — uninstall removes the config manifest by default (breaking)

Uninstall left `.claude-src/config.ts` and `config-types.ts` behind unless `--all` was passed, so the default uninstall claimed success while leaving the manifest that makes a project look installed. The manifest is now always removed and listed under its own `Config:` section in the removal plan; `.claude-src/` itself is removed once empty. A project uninstall always deregisters itself from the global project registry, and a failure there warns instead of being swallowed. A global uninstall additionally prunes the inlined global-scoped entries from every registered project and regenerates each project's `config-types.ts`, capturing what it needs before removal since that data lives in the config being deleted; unreachable projects are warned and skipped and can never abort the uninstall.

**Breaking:** `uninstall --all` is removed. Plain `uninstall` now does what `--all` used to do.

### D-272 — build grid order is stable

Cell order followed matrix and readdir insertion order, so it shifted between runs. Cells are now sorted alphabetically by display name. Focus is dispatched from a mount effect and the seed falls back to the first domain, so the store's focused skill always matches what is drawn and `s` works on a cold entry into the step.

### D-261 — compact source-change marker on the confirm step

The verbose `agents-inc → eject` transition text wrapped out of its row. It is replaced by the compact `~` marker the row already carried.

### D-269 — the filter-incompatible hotkey is behind a feature flag

`F` is gated behind `FEATURE_FLAGS.FILTER_INCOMPATIBLE` (default off) because of its dual-scope collapse bug. The keypress and the footer hint are hidden while the store action stays dormant for a one-flag re-enable.

### D-270 — reference documentation matches the shipped contracts

The store map, state transitions, tombstone and guard patterns, scope system and agent system described the pre-D-260 model. They now describe `s` as the sole toggle with an inert spacebar, and the superseded finding is marked as such. The e2e infrastructure reference and anti-patterns gain the scope-and-HOME model and a rule for choosing a wizard launcher by scope.

## Fixed

### D-273 — a corrupt config silently compiled every built-in agent

`loadProjectConfigFromDir` returned `null` both for "no config file" and for "config file that cannot be parsed", so a corrupt `.claude-src/config.ts` was detected as a phantom eject installation and `compile` rebuilt all 23 built-in agents. A missing file still returns `null`; a load failure, non-object export or loader-schema violation now throws `ConfigLoadError` carrying the path and reason. `compile` hard-errors before any write, `detectProject` converts it to `null` so `doctor` and `edit` report a config problem, and `detectInstallationInDir` no longer fabricates an installation.

### A content-less config counted as an installation

A config declaring neither skills nor agents now reads as not installed, so `init` routes to the setup wizard instead of the dashboard.

### D-264 — a global install over-installed sub-agents

Two causes. `resolveAgentNames` keyed on `projectConfig?.agents?.length`, so a config declaring `agents: []` fell through to the compile-everything branch; it now keys on config presence and compiles zero. And a recompile left previously-compiled agents on disk after they were removed from config, so each authoritative pass now prunes stale built-in agents from its own scope directory. Hand-authored agent files are matched against the built-in names and preserved.

### D-259, D-268 — tombstoning depended on install order

A project owning a skill or agent at project scope got no global tombstone when the same id later became active globally, so global-first and project-first installs disagreed. Both paths now synthesize the `{ scope: "global", excluded: true }` entry on the push side, symmetrically for skills and agents, and render `[P][G]` either way.

### D-256 — a global plugin-to-eject switch left stale compiled references

Registered projects kept the `name:name` plugin reference in their compiled agents after the global source switched to eject, because propagation rewrote config but never recompiled. Fixed with D-240.

### D-262 — a dual-scope source change leaked across scopes

Source selection was keyed by skill id alone, so changing a source on a dual-scope pair also rewrote the global tombstone's source. It is now keyed by `(id, scope)` and skips excluded entries. The plugin uninstall performed during a mode migration is now scope-precise, so switching a project to eject leaves a still-registered global plugin alone.

### D-265 — the set-all-sources hotkeys flipped tombstones

`setAllSourcesEject` and `setAllSourcesPlugin` rewrote excluded entries too; they now apply only to active ones, the same guard class as D-262.

### D-257 — a deselected skill vanished from the sources step

A skill deselected from a saved config disappeared from the sources tab entirely, so there was no way to see what the save would remove. It now stays visible as an inert row carrying the red removal marker, pinned to its persisted scope and source.

### D-263 — wizard content bled outside its box

Long content escaped its border at short terminal heights. Clipping is now unconditional and the size gate applies only to the affordance, which is a shared text-only "N more below" / "N more above" hint. The sources column header is pinned outside the clipping viewport.

### D-271 — the sources step clipped rows that could not be reached

Trailing rows were clipped with no indication and no way to reach them: the viewport only followed focus, so a trailing row that was locked or disabled was permanently unreachable — including the pending-removal row from D-257, exactly when it mattered. `useSectionScroll` now measures the content box, separates focus scrolling from overscroll, and exposes `scrollBy` so the grid scrolls when no focusable row remains.

### `validate` exited 1 on a healthy install

Immediately after a clean install from the official marketplace, `validate` reported 45 errors and 177 warnings across 222 skills and exited 1, while `doctor` passed on the same state. Three causes:

- An over-length `cliDescription` was a hard error, but the runtime schemas accept any length and the value only feeds wizard description text. It is now an advisory warning carrying the actual length; the strict schema keeps `max(60)` as the declared contract, and an empty or missing value stays an error.
- The directory-name rule compared `displayName` against the directory name, which the marketplace convention can never satisfy — human display names in `<domain>-<category>-<slug>` directories. It now compares the directory name against the skill's machine id from `SKILL.md` frontmatter, and runs independently of whether the metadata validated.
- The plugins pass only inspected direct children of the plugins directory, so the claude CLI cache layout (>= 2.1.220, recorded in `installed_plugins.json`) was invisible and installed plugins were never validated. It now reads the v2 registry and validates each recorded install path, falling back to the direct-children scan when the registry is absent or empty. A recorded path that no longer exists surfaces as an invalid plugin; an unreadable registry is an error rather than something to scan around.

### 38 category definitions were missing

The generated `Category` union carries 89 members while `defaultCategories` defined 51, so `tsc --noEmit` failed with TS1360 and every undefined category was auto-synthesized at load time with a humanized name ("Api Graphql"), order 999 and `exclusive: false` — which is what the wizard rendered. The missing definitions are derived from the marketplace matrix; eleven are exclusive, and the mobile, desktop and infra groups are ordered importance-first. A test now pins the definitions against the generated union so the two cannot drift again.

### `list` rendered the install mode as a version

The header read `Installation: agents-inc vplugin` because `getInstallationInfo` stored the mode in a `version` field that the formatter prefixed with `v`. There is no version to show, so the field is gone and the mode is rendered once.

### Settings warned about a key this CLI writes

Every run after a plugin install warned about an unknown settings field, `extraKnownMarketplaces`, which this CLI writes itself during its own plugin-install path. It is now expected; genuinely unknown fields still warn.

### D-226 — the e2e sandbox collapsed HOME onto projectDir

Sessions pointed `HOME` at the project directory, so every project-versus-global distinction disappeared and the scope hotkey silently vanished because the wizard believed it was running at global scope. Sessions now allocate a sibling HOME by default, `launchInProject` and `launchInGlobal` state the intent at the call site, and the `globalHome` getter throws when a test that needs the distinction used a plain `launch`.

## Removed

- `uninstall --all` — manifest removal is unconditional (D-274).
- The `setSkillSource` store action, made redundant by the scope-keyed `setSourceSelection` (D-262).
- `InstallationInfo.version`, which only ever held the install mode.

## Internal

- Eighteen new e2e specs, one per shipped fix, each asserting config and filesystem state rather than exit codes. The three dual-scope specs whose names described spacebar behaviour are renamed to match the `s` contract.

- `focusSkill` in the e2e page objects was rewritten closed-loop. It had dead-reckoned rows and assumed arrow-down resets the column, which the real grid preserves and clamps, so a second `focusSkill` in one domain toggled the wrong skill. The focused cell has no text signal under `NO_COLOR`, but the focused category header does, so the walk now Tabs between categories and re-reads the screen after every press before walking right from a verified column zero. Cell labels are matched exactly, so "React" no longer matches a "React Query" cell.

- `createPermissionsFile` merges into `settings.json` instead of overwriting it, which had been wiping `enabledPlugins` and `extraKnownMarketplaces` mid-lifecycle. `TIMEOUTS.WIZARD_LOAD` went from 15s to 45s: `init` against the real marketplace under full-suite parallelism can still be loading well past 15s.

- Closed without code changes: the two README items were verified as needing none (D-109, D-110); the dual-scope layer ticket was superseded by D-260 (D-233); the request to rewrite every project's stack on a global skill addition was declined as intended behaviour (D-255); and an inherited-global skill showing as selected was verified by code trace as correct — scope is carried verbatim from the skill config and never derived from the domain selections, so a no-op save cannot silently adopt it into the project (D-267).
