# Release 0.149.1 (2026-08-04)

Schema addresses follow the CLI's new location, and three shipped prompt files are repaired

## Changed

### The JSON schema address moved

The CLI writes a `# yaml-language-server: $schema=…` line into every metadata file it generates, pointing into this repository on GitHub. That address assumed the CLI's sources sat at the repository root. They now sit under `packages/cli/`, so it is `https://raw.githubusercontent.com/agents-inc/cli/main/packages/cli/src/schemas`.

Nobody asked for this — it is a consequence of the repository becoming a monorepo, and the address had to move with the files.

**Files generated from this release carry the new address** and validate in your editor exactly as before. The 23 agent metadata files shipped inside the package carry it too.

**Files generated by an earlier version carry the old one**, which stops resolving. The failure is quiet: no error, no warning, the editor simply stops validating that file. Regenerating or running `npx agents-inc compile` fixes it.

## Fixed

### Three shipped prompt files had a closing tag swallowed into a table

Moving off `package-lock.json` took Prettier from 3.8.1 to 3.9.6. In three files a closing tag sat on the line directly below a markdown table with no blank line between them, and the newer Prettier read it as another table row and absorbed it:

- `src/agents/meta/agent-summoner/playbook.md`
- `src/agents/researcher/api-researcher/output.md`
- `src/agents/researcher/web-researcher/output.md`

These ship inside the package and are prompts an agent reads, so those tags are structural markers rather than decoration — one absorbed into a table cell stops marking anything.

The repair is a blank line between the table and the tag, which is the separation Prettier itself chose elsewhere in the same tree.

Practical impact was limited: no agent metadata declares the fields these particular sections govern, so nothing was reading past a broken marker in practice. It would have started the moment one did.
