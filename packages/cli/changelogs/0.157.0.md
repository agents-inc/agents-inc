# Release 0.157.0 (2026-08-23)

Scope reaches the sub-agents that hold it, every command prints the name the installation configured, and a run that cannot finish says so (CLI-355, CLI-356, CLI-358, CLI-363, CLI-492, CLI-502, CLI-538, CLI-544, CLI-562, CLI-566, CLI-574, CLI-581, CLI-587, CLI-588, CLI-589, CLI-591, CLI-592, CLI-601, CLI-602, CLI-605, CLI-607, CLI-608, CLI-611, CLI-612, CLI-614, CLI-616, CLI-618, CLI-626, CLI-627, CLI-644, CLI-649, CLI-657, CLI-658, CLI-660, CLI-661, CLI-662, CLI-663, CLI-664, CLI-669, CLI-671, CLI-673, CLI-675, CLI-680, CLI-681, CLI-686, CLI-696, CLI-699, CLI-702, CLI-708, CLI-756, CLI-773, CLI-800, CLI-811, EDITOR-02, EDITOR-08, REPO-09, SERVER-04, WWW-04, WWW-07, WWW-10)

The accuracy programme's four phases land together. Phase A worked a 28-item worklist; Phase B walked all 39 user journeys by hand against the real binary, the real editor and a real worker; Phase C worked the findings the worklist filter had excluded; Phase D re-opened 54 rows after the owner overturned a scoping call — **a guard is not a feature** — and found nine live defects while building guards for things already believed fixed.

Two hundred and thirty-seven tracker rows closed. Most were retired by verification rather than by work: ALREADY-DONE, MISDIAGNOSED, MOOT or withdrawn. Those are recorded in `todo/archive.md` and are not repeated here. What follows is what changed.

The measurement worth keeping: **every agent that checked one of the orchestrator's figures found at least one wrong** — a membership count stale within the hour, a "four documents" that was five, an enum precedent naming a value that does not exist, a census scoped to four directories that missed a fifth. None was caught by review; all were caught by re-deriving from source.

## Added

### CLI-702 — `branding.name` reaches every command's output

Seven sites across six commands. `BaseCommand.resolveBrandingName` resolves it once on the command spine, and `initSucceeded` and `notInstalledHere` became builders rather than constants because the name is per-installation and cannot be baked in at module load.

### CLI-773 — the configured name reaches the interactive dashboard

The last surface still printing the shipped name while the run around it printed the configured one.

### EDITOR-08 — a project-scoped skill cannot be held by a global sub-agent

`reachesAgent` decides whether a scope can reach an agent; a pair that cannot is marked on the row and blocks the install with a notice naming how many sub-agents need project scope. Previously the editor would mint a payload the CLI refuses.

### EDITOR-02, SERVER-04 — the share round trip carries scope end to end

The seed payload gains a scope vocabulary in `@workspace/matrix` — `seedScopeSchema`, `seedAgentScope`, `isSeedScopePairWritable`, `unwritableSeedAssignments`, `installableSeedPayloadSchema` — and the editor, the worker and the CLI all read the same one.

### WWW-07 — the landing page and the documentation read as one product

Code blocks lose Expressive Code's macOS terminal chrome (`frame: "none"`), and syntax colour is ranked by lightness off the existing ink ramp instead of Night Owl Light's blues, which appear nowhere else in the design system.

### CLI-566, CLI-589 — the briefing contract, and a gate that reads it

`standards/briefing.md` is the contract binding both ends of a dispatch; `check-briefing-contract.ts` holds it against the root `CLAUDE.md`'s restatement of its four load-bearing rules.

### CLI-587, CLI-588, CLI-562, CLI-605 — the checker-gates lane

Four gates over surfaces no checker had opened: spec-name vocabulary, symbol citations, spawn doors, and refusal expectations derived from the real binary rather than restated.

### CLI-627, CLI-626, CLI-544, CLI-581 — findings and citation checkers

A citation resolver over the findings corpus, and frontmatter validation that fails on a dangling reference rather than leaving it for a reader to notice.

### CLI-616 — the skipped-spec gate

A skipped spec is indistinguishable from a passing one in a summary line. The gate landed green and the offender it was built against is fixed.

### CLI-658 — a gate for the exported symbol only tests invoke

The brief's central premise was false, and disproving it is the value: the roster came down from 23 to 3.

### CLI-664 — the hand-written producer roster is derived

`producer-rosters-are-derived.test.ts`, with an empty exception list, so a new producer joins the roster or fails the gate.

### CLI-671, CLI-699, CLI-708 — the suites refuse a build that moved under them

Three guards, because they answer three different questions. `assertDistIsFresh` refuses a run whose `dist/` predates the tree compiled into it. `assertDistIsPresent` refuses a spec file that begins with no build to spawn — reachable from `beforeAll`, which the per-test guard is not. `guardAgainstDistReplacement` refuses a spec whose build was replaced mid-flight. tsup builds with `clean: true`, so a `bun run build` started from anywhere empties the directory a running suite is executing out of, and every symptom of that race is an ordinary assertion failure that reads as a regression the change under test caused.

### CLI-355, CLI-356, CLI-358 — three gates the repository had decided by incident

`reportUnusedDisableDirectives` as an error, `eslint-plugin-react-hooks` with `rules-of-hooks` and `exhaustive-deps`, and the code generators under a gate that does not depend on git state.

### REPO-09 — the deployed editor's address is committed rather than assembled

`apps/editor/.env.production` is committed and Vite ranks it above a local `.env`, so a developer's own address can no longer reach a production bundle. `bun run deploy` reads `dist/` and refuses to upload a bundle that disagrees with it. The `VITE_API_URL` that CI used to set on the deploy step is gone, because a shell value outranks every `.env` and two copies of one address must never disagree.

The app was a single 1.03 MB file, so a one-line copy edit re-hashed React, the catalogue and every brand icon. Split seven ways, the app's own code is 29 KB and an ordinary deploy leaves the other six alone. First paint pays 0.6 KB — 310.9 KB gzipped before, 311.5 KB after, both measured under Node, which is part of the figure rather than a footnote: Node's and Bun's zlib disagree by about 2% on the same bytes.

## Fixed

### CLI-800, CLI-811 — two product defects found by driving the CLI

Each now fails a journey that would have caught it.

### CLI-607, CLI-612, CLI-618 — a run that cannot finish says so and exits non-zero

A failure that leaves the exit code at zero is invisible to everything but a reader. The run now names what it could not do and the one command that finishes it — both halves required, because a run that names a failure and no way out has told the user nothing they can act on.

### CLI-363 — `edit` decides its scope once

It had answered its own scope question six times, and two of the answers disagreed.

### CLI-611, CLI-502 — a marketplace an author builds is one its own reader will name

`build marketplace` refuses rather than writing a manifest its own loader rejects. A `ManifestState` union — `absent` / `unreadable` / `named` — is read off the throw's type through an exhaustive switch. A fourth defect was found first: the absence guard named `marketplace.json` and tested `.claude-plugin/`, so a repo shipping only `plugin.json` read as present.

### CLI-644, CLI-675 — a closed union refused a marketplace's own slug

It answered with somebody else's catalogue. Closed on the owner's ruling that `custom: true` is the documented mechanism. The kebab-case rule had been stated twice in `schemas.ts` with the two spellings disagreeing.

### CLI-538 — `splitConfigByScope`'s comment was the defect, not the code

The comment claimed the project partition clears `selectedDomains`; the code has always copied it onto both. The owner ruled the code right — a project owns its own domain selection. The field had zero test coverage, which is why the contradiction survived: both project writers recompute it before writing, so no emitted config could tell the two stories apart. A test now pins it on both partitions, verified non-vacuous by mutation.

### CLI-614 — the seed schema accepted payloads the CLI throws on

The owner ruled the CLI and the editor should share one schema.

### CLI-602 — `eject` no longer discards an unreadable config

`recordSource` read `(await loadProjectSourceConfig(dir)) ?? {}`, which on an unreadable config handed the writer an empty object and wrote over what it could not read.

### CLI-591, CLI-592 — the wizard's warnings reach the screen

`startupBand()` sorts warnings and errors ahead of the rest, and a warning raised after the wizard mounts reaches a toast instead of being lost off the top of the screen.

### CLI-660, CLI-661, CLI-662, CLI-756 — four specs that could not fail

Two store guards unreachable with two specs pinning them and the reachable refusal asserted nowhere; a spec asserting an end state without establishing the precondition it was named for; two seed fixtures encoding a payload the product refuses to mint; and two negative assertions that could no longer fail. Every repair is mutation-proved — the old assertion stays green on the same mutation the new one catches.

### CLI-686 — the unit suite no longer depends on the developer's shell

`chalk.level = 0` pinned in `vitest.setup.ts`, structurally rather than per-spec.

### CLI-696 — one unescaped pipe deleted a whole journey row

Escaping it alone would not have fixed anything, and that is the finding.

### CLI-601, CLI-608 — the dual-scope contention flake, and four specs pressing Space at a toggle that refuses

`selectSkill` confirms the press landed by re-reading the cell's rendered text and re-presses if it did not — the closed-loop shape Tab and Enter already had, applied to the one key that never had it. Closed as recovery rather than prevention, knowingly. Three candidate fixes were closed off first, and one of them — the userland stable-handler-ref sweep — was executed to zero changes because Ink 7 routes `useInput` through React 19's `useEffectEvent`.

### The editor's add-skill keyboard tests pressed before they looked

The skill index is a network call and the dialog renders `loading skills…` until it lands, so Tab fired before any result row existed and focus never reached one. The failure was silent about its cause: the row exists by the time the assertion retries, so it reported a row that was merely `inactive`. Reproduced by delaying the stubbed index 600 ms, at which point both tests fail every run; both pass with the observation restored.

## Findings

Fifty-five findings written 2026-08-20 → 2026-08-22, and the corpus pruned 282 → 154 across three passes. The deletion protocol is now explicit that a finding's `INDEX.md` row is its surviving record and is never removed — learned the hard way, after an earlier batch left 64 dangling citations across 39 files and the link-integrity scan caught exactly one of them.

Two lessons became `root_cause` values rather than prose:

> A rule that was wrong when written fails review; a rule whose premise expires passes review forever, because the reasoning still reads as sound and only the world has moved.

That is `premise-expired`, and the countermeasure it proposes is not more review but naming, inside the rule, the fact the rule depends on — so a change to that fact has something to collide with.

## Proposed standards

- **Observe before press.** `standards/e2e/page-objects.md` carries it as one of the walk algorithm's two load-bearing properties, alongside lap termination. `standards/e2e/anti-patterns.md` gained the press-budget anti-pattern: a walk length tuned to the catalogue size on the day it was written.
- **`standards/editor-and-worker.md`**, on a real thesis — every defect it covers was green in both workspaces' type systems and both suites, and visible only to a real browser or a second machine.
- **Three rules were refused rather than written**, and each refusal was correct. The `eslint-disable` rule as briefed would have condemned 55 of 57 live directives; a corollary about `validateSelection` was false on both of its claims and would have condemned live code; and a proposal prescribing a task ID in a negative claim was refused outright. Two greps were built, tested and deliberately not shipped — both rules ship without a check rather than with a bad one.
