# Release 0.153.0 (2026-08-09)

One marketplace at a time (CLI-389, CLI-390, CLI-398, CLI-399, CLI-400, CLI-428, CLI-438, CLI-439, CLI-440, CLI-441, CLI-442, CLI-443, CLI-444, CLI-445, CLI-446, CLI-450, CLI-451, CLI-452, CLI-457, CLI-458, CLI-459, CLI-460, CLI-461, CLI-465, CLI-466, CLI-471)

## Added

### CLI-465 — Sources revalidate by ETag

The cache stops trusting itself blind: one conditional request per source per process classifies the cached copy as current, superseded, unrecorded or unreachable. Stale-if-error keeps offline work working, capped at five seconds; the current-copy arm measures ~1.15s. The `--refresh` flag this replaces is under Removed.

### CLI-389 — Relationship coverage across the catalog

The skill relationship rules (`requires`, `compatible-with`) now cover the full catalog, and a contract-scenario suite in the matrix package replays the same selection semantics in every consumer — the CLI and the editor answer selection questions from one table.

### CLI-390 — Preload defaults derive from the catalog

`stack-preloads.ts` — generated output whose generator was retired — is replaced by a read-model module that derives the same answers from the catalog at load time. One less artifact to drift.

### CLI-444 — A journeys canon, and a suite that answers to it

`​.ai-docs/standards/e2e/user-journeys.md` documents 28 user journeys with four assertion surfaces each (compiled agents, CLI render, config.ts, config-types.ts). The whole e2e suite was audited against it: flows are driven from scratch rather than planted as fixtures, vacuous assertions were removed, and journey 26 (mixed sources across scopes) is explicitly marked still-to-be-decided.

## Changed

### CLI-428 — update wraps Claude's own plugin update

The Ink update wizard is gone. `update` now delegates to `claude plugin update`: plugin skills update through the machinery that installed them, sub-agents keep referencing them by pointer with no recompile, and ejected skills are untouched by construction.

### CLI-451 — Stacks scope to the source that declares them

A stack shown in the wizard belongs to the marketplace being loaded, and a custom source with no stacks gets no stack step rather than the built-in list masquerading as its own.

### CLI-466 — --source is an init flag

Choosing a marketplace happens at `init`, so that is where the flag lives. Every other command reads the source the configuration records; the shared `--source`/`--refresh` flag pair on the base command dissolves.

### CLI-398 — One PM serves every domain

The four per-domain planning agents collapse into `planning/pm`, parameterized by the domain skills it carries.

### CLI-399 — One reviewer serves every domain

The five per-domain reviewer agents collapse into `reviewer/reviewer`, same shape: the checklists arrive as per-domain skills, the agent is singular.

### CLI-400 — The agent roster sheds its dangling references

`pattern-scout`, `web-pattern-critique` and `web-architecture` retire; `ai-researcher`, `cli-researcher` and `ai-tester` arrive; surviving identities lose their references to agents that no longer exist.

### CLI-457 — pretest builds, so a green run means the current build

The unit suite executes `dist/`; `pretest: "bun run build"` makes `bun run test` and `npm test` statements about the source you just edited, not the last build.

### CLI-458 — turbo already hashes matrix into the build key — measured and recorded

Filed as a cache-invisibility bug, disproven by measurement: turbo puts a task node in the graph for a dependency with no build script and hashes its files anyway. The proof lives as a comment in `turbo.json` so the next reader does not re-file it.

### CLI-460 — A direct vitest run refuses a stale dist

No script hook can see `npx vitest run <file>`, so the config's globalSetup throws before collecting a single spec when `dist/` is older than `src/` or `packages/matrix/src`. Refuses rather than rebuilds — a direct run stays fast and deliberate.

## Fixed

### CLI-438 — A project compile stays inside the project

A project-scope compile wrote into the global install and into every registered project. It no longer leaves the project directory.

### CLI-442 — A fresh pick during a project edit defaults global, overridable

The scope a fresh skill lands in during a project edit is global by default and per-skill overridable — the behavior that had regressed.

### CLI-443 — Removing the project half of a dual-scope pair removes exactly that half

A `[P][G]` pair loses its `[P]` without touching the `[G]`.

### CLI-441 — The stack's declared roster is what installs

A stack that declares its sub-agents installs those sub-agents; the domain roster no longer overwrites the curated list before install.

### CLI-439 — Plugin banners render identically on init and edit

The banner a plugin install prints is the same banner on every entry point.

### CLI-440 — The propagated-recompile summary reports what actually recompiled

The four hand-rolled copies of the fan-out summary collapse into `messages.ts`, and the numbers it prints are the numbers that happened.

### CLI-445 — Unparseable local skill metadata is a hard error

A local skill whose metadata cannot be parsed stops the command with the file named, instead of half-installing around it.

### CLI-446 — Schema-invalid metadata dies just as loudly

Parseable-but-invalid metadata gets the same treatment: hard error, file named, nothing persisted. `edit` refuses to open over one; `doctor` validates content it previously waved through.

### CLI-471 — Built-in rules narrow to the marketplace being loaded

The CLI's built-in relationship rules name public-catalog skills; applied whole to a custom marketplace they produced 2384 warnings about skills that source never claimed to have. Built-in rules now narrow to the skills the loaded source carries — source-authored rules are never narrowed — and the warnings went to zero with behavior on the public catalog proven identical.

## Removed

### CLI-450 — Source switching is gone

The wizard's source-switching surface — the settings step, per-skill source selection, the source search modal — and the machinery behind it (`source-manager`, `source-switcher`, their hooks and suites) are deleted. The CLI models one marketplace at a time.

### CLI-452 — import, new and validate retire, and the feature flags with them

`import skill`, `new agent`, `new marketplace`, `new skill` and `validate` leave the command surface; the editor is the intake path. The feature-flag module leaves with its last readers.

### CLI-459 — Dead operational helpers deleted

`assert-dir-overwritable`, `compare-skills`, `find-skill-match`, `collect-scoped-skill-dirs` and the skills generators — all without production callers — are gone.

### CLI-461 — The dead stack installer is gone

`stack-installer` and `stack-plugin-compiler` had no production caller and took required arguments anyway; deleted with their suites.
