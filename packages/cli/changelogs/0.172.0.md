# Release 0.172.0 (2026-10-22)

`init --from`, `edit --from` and `uninstall` show the summary panel at the question, the editor names the sub-agents a
skill switches and holds a project link's global entries, links are version 7, and agentsinc.sh/ opens the editor
(REPO-44, CLI-925, CLI-908, CLI-915, EDITOR-97)

**Before you upgrade.**

- **Share links are version 7 only.** The payload gained a field that marks a link a bare `edit` mints inside a
  project. Links and saves made before this release must be made again, and an earlier CLI cannot share or install
  through the updated store.
- **`AGENTS_INC_EDITOR_URL` does nothing now.** When `AGENTS_INC_API_URL` names this machine, every editor address the
  CLI prints or opens is the local editor, `http://localhost:5173/editor`.
- **`doctor` no longer passes on the saved marketplace copy.** Offline, or when the marketplace refuses, its
  `Marketplace Reachable` row fails and it exits 1. Other commands still fall back to the copy.
- **`build marketplace` refuses an empty marketplace `config.ts`** and exits 1, where 0.171.0 warned and read the
  default layout.
- **What `init --from`, `edit --from` and `uninstall` print before they ask is a panel**, not the text lists, and a
  global edit's closing line is `Registered projects: N recompiled`. Anything that matched the old lines needs
  updating.

## Added

### CLI-908 — the info table at the question

- **`init --from`, `edit --from` and `uninstall` show the summary panel where they ask**, in place of the text lists,
  with no key line.
  - A sub-agent that changes without arriving or leaving is marked `~`, with one line under the panel saying what
    changed: `~ web-tester: gains Visual Regression, model default → opus`.
  - Skills about to be written over are marked `↻`, among them the ejected copies a switch to plugins deletes.
  - Where nothing is asked (no terminal, `--yes`), the panel prints at that point.
  - In a project, `init --from` lists the whole global install, with what the project inherits unchanged under Global.
  - `uninstall` names each removed copy by its own name, and lists the config files it deletes under the panel.

### REPO-44 — the card rework in the editor

- **A skill that switches sub-agents on raises a toast naming them**: the first three, then "and N more", as in
  `web developer, web researcher, web tester and 2 more switched on: React added`.
- **Deselecting a sub-agent's last skill switches it off, with a toast saying why**, in a selection made in the editor:
  `web tester switched off: Tailwind CSS removed`. A stack's sub-agents stay on (see Backlog for a link the CLI made).
- **A link a bare `edit` mints inside a project holds its global entries.** The editor draws the global skills and
  sub-agents disabled, with the reason:
  - they can be switched to project scope, which gives the project its own copy and leaves the global one as it is;
  - they cannot be switched off or retuned;
  - applying a stack, a save, Start from scratch or a composer proposal keeps them, and the stack dialog says so.

  `share` does not mark its link, and neither do the editor's own Share, Install and Save.

## Fixed

### CLI-925 — the wizard removal's follow-ups the owner ruled

- **`doctor`:**
  - asks the marketplace itself rather than read the saved copy. Offline its row reads `Could not reach <source>` and
    Skills Resolved is skipped; a 401, 403, 404 or 5xx fails the row with the reason, such as
    `Repository not found: <source>`. A reached marketplace reads `Reached <source> over the network`. See Backlog for
    one download path;
  - lists skill folders as orphans only when no configuration exists anywhere, so `eject skills` no longer makes it
    warn about every ejected skill. The pass line is `No orphaned agent files`;
  - passes two healthy installations in one scope: the Installations row keeps its `--provider` note and doctor
    exits 0.
- **Sub-agents install without a skill that fails to load.** `init --from` and `edit --from` keep every sub-agent the
  link names, with the warning, even when no skill loads. Its line reads
  `sub-agent(s) installed without <skill>, carrying nothing else this catalog knows: …`. A link that names no sub-agent
  and whose skills all fail is still refused. The editor keeps such a sub-agent on when it opens the link, and its next
  id carries it.
- **A worker on this machine means the editor beside it.** When `AGENTS_INC_API_URL` names `localhost`, `127.x.x.x` or
  `[::1]`, every editor address the CLI prints or opens, help text included, is `http://localhost:5173/editor`.
- **`build marketplace` refuses an empty marketplace `config.ts`**: empty, with no default export, `export default {}`
  or `export default undefined`. It prints the marketplace refusal, exits 1 and writes nothing. A repository with no
  config at all still builds.
- **A global `edit --from` says the registered projects are recompiled to match**, and the line after the run is
  `Registered projects: N recompiled`, with no unchanged count.
- **`edit --from` with no terminal and an id that changes nothing** prints `No changes made.` and exits 0, also when a
  project skill masks a global one.
- **The home refusal's advice loses nothing.** Where re-sharing at global scope would reset a global sub-agent the
  project replaced, it says to change the global install from home with a bare `edit` and apply the id it gives.

### CLI-915 — a project's description

- **`init --from` in a project writes the link's own description, or none when the link carries none**, never the
  global installation's. A link's own description also wins over the stack it applies.
- **A link that opens in the editor as a built-in stack keeps its own description** on the id Install and Share mint.

### EDITOR-97 — a CLI-minted link opens on its stack

- **A link the CLI mints also opens on a signed-in account's save it equals**, as it does on this browser's saves and
  the built-in stacks.

### REPO-44 — the follow-ups and problem fixes

- **Text a link carries prints inert, on one line.** Terminal controls are stripped and each line break becomes a
  space in:
  - a carried skill's display name, in the plan, the confirm and the change lines;
  - a sub-agent's `codexModel` in the not-offered warning;
  - unknown payload keys in the skip warning;
  - a stack id the marketplace does not offer.
- **A marketplace value holding a line break or a terminal control is refused** wherever it is set, with
  `Marketplace values must not contain line breaks or control characters.` The refusal echoes it inert.
- **A carried skill file whose path steps through `..` or holds a null byte is refused** by the payload schema: the
  store answers 400 and stores nothing, a stored one answers 500, and `init --from` refuses before it lists.
- **A carried skill's name may pass 30 characters**, and its slug 50. It installs and `doctor` accepts it, except in
  the case under Backlog.
- **A Codex installation alone at its root has its copied-in skills read from Codex's own skills folder**, so `eject`
  leaves out a skill a Codex global already holds as its own copy.
- **`build plugins --agents-dir` builds an agent plugin as it builds a skill plugin.** It clears the earlier build and
  versions the plugin by the files it ships, so a stray file is removed and a change in what it ships bumps the
  version. It refuses to build into the folder holding the agent's source, or into a non-empty folder no earlier build
  made.
- **`list` keeps long skill names whole.** The Mode and Marketplace labels no longer split, the ⏏ mark no longer covers
  a name's last letters, and a name no longer draws over the table's border.
- **Remedies name the installation they act on:**
  - beside a second installation, a handed-out command names the choice, `--provider <claude|codex>`;
  - over a lone Codex installation, the `init` half names `--provider codex`;
  - the retired `.claude-src/` notice names the folder under its root, once per root, home first;
  - `edit --ui --from` keeps the provider it was given.

## Changed

### REPO-44 — the editor, the site and the tests

- **A stack's sub-agents stay on with no skills.** Picking a stack pins every sub-agent it declares; one whose last
  skill goes stays on, installed as a base agent, until it is clicked off. A link made from an untouched stack now
  carries each declared sub-agent, so its id changes once.
- **agentsinc.sh/ answers 301 to `/editor`, keeping the query**, so an old `agentsinc.sh/?fromId=` link opens in the
  editor. `/docs` is unchanged, the 404 page and the site title link the editor, and the editor's About link opens
  `/docs/why`.
- **The skip warning says `installed without`** where it said `skipped with`.
- **web-tester's typecheck step is worded as the other three testers word it**, and a spec holds all four to one
  wording.
- **Tests:**
  - an e2e case gives a sub-agent that declares only a `PostToolUse` hook the folder-trust notice;
  - `toHaveAgentFrontmatter`'s `completionGate` option is `stopHook`;
  - the editor's arrival wait no longer misses a dialog that opens on arrival, and the toast stories and audits hover
    the toast before they read its ✕.

## Removed

- **`AGENTS_INC_EDITOR_URL`**, from the CLI, the unit setup, the e2e runners and the docs. (CLI-925)
- **`doctor`'s listing of skill folders no config declares**, added in 0.171.0, wherever a config is in play.
  (CLI-925)
- **The text plans of `init --from`, `edit --from` and `uninstall`**, `Will be overwritten:` among them, with the
  removal-plan confirm. (CLI-908)
- **The landing page at agentsinc.sh/.** (REPO-44)
- **`determinePluginVersion`** and its manifest reader, which nothing called once agent plugins version by what they
  ship. (REPO-44)
