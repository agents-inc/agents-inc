# Release 0.162.0 (2026-09-03)

Every compiled sub-agent gains the Skill tool, text the CLI did not author reaches the terminal inert, and a refused share says what the store said (CLI-848, CLI-849, CLI-851, CLI-852, CLI-853, CLI-854, CLI-855, CLI-856, CLI-859, CLI-860, CLI-861, CLI-862, CLI-863, CLI-867, CLI-870, EDITOR-64, EDITOR-66, EDITOR-67, EDITOR-69, EDITOR-73)

**The recurring shape of this release is a double, a harness or a record that differed from production in exactly the dimension something discriminated on.** MSW answered a bare `text/plain` where the worker sends `charset=UTF-8`, so no fixture could tell a correct `.startsWith` from a broken `===`. `runCliCommand` stripped ANSI before returning, so an assertion that stdout carried no escape could not fail. A write-route double minted what the worker refuses. A test fixture derived a stack id from a name where the worker mints a UUID. In every case the code was right and the thing measuring it was blind, and in every case the blindness was found by mutating the implementation and watching the suite stay green rather than by reading.

**Two rows were destroyed by the lanes sent to build them, and both refusals were correct.** CLI-855 was filed against the store's 429 body; `Too many requests` is the HTTP reason phrase for 429 verbatim, so the status the row named must not be quoted and the 503 it dismissed was the only one that qualified. CLI-857 claimed a test-cache hazard; instrumenting every request across 7,432 tests found zero marketplace calls and exactly one escape, which became CLI-870.

## Added

### CLI-854 — one sanitiser, three chokepoints, and the census that was wrong three times

Text this CLI did not author — a remote HTTP body, a piped payload, catalogue metadata authored by whoever wrote a skills repository — reached the terminal with no control-character stripping. A short `text/plain` body could carry escape sequences a terminal acts on, and `--marketplace` makes a third-party repository a supported product input rather than a MITM.

`stripTerminalControls` in `utils/string.ts` sits behind three chokepoints: `truncateText`, `getErrorMessage` and `formatZodIssue`. **Newline and tab survive**; C0, C1, DEL and every escape sequence do not. Words are never removed, so a forged sentence survives as visibly ordinary text.

**The census was wrong three times, and the third correction is the general one.** The row named three boundaries; the dispatch corrected it to five; the two that mattered were in neither — `getErrorMessage` at 74 call sites and `formatZodIssue` at 18. The right census is keyed on **which renderer foreign text funnels through**, not on where it is printed.

**Strip happens before truncation, and the order is owned inside `truncateText`** rather than left to its five callers, because there is a wrong way round: a cut taken first can land inside a sequence, and the fragment is worse than the whole — a terminal holds it open and eats the ellipsis and the next line.

The sharpest find got past the lane's own first implementation: the stdin excerpt was sanitised and the parse **reason** was not, because a V8 `Error` looks like the CLI's own text while `JSON.parse` writes the offending input into it verbatim. **Provenance follows the bytes, not the object.** Finding: [`agent-findings/2026-09-02-a-parsers-error-message-carries-the-input-that-broke-it.md`](../.ai-docs/agent-findings/2026-09-02-a-parsers-error-message-carries-the-input-that-broke-it.md).

### CLI-870 — the one request that leaves the unit suite is made by a process no mock can reach

Instrumenting every `fetch` and `http/https.request` across 222 files found exactly one request leaving the process: `@oclif/plugin-warn-if-update-available`'s **detached child** GETting the npm registry. `vitest.setup.ts` now pins `AGENTS_INC_SKIP_NEW_VERSION_CHECK` process-wide — the variable names no home, so setting it per fake home was what left every self-built home open. Off-machine requests 1 → 0; `/tmp/vitest-home-*` survivors 1 → 0, which is the other half of this suite's `ENOTEMPTY` failures. No in-process interceptor could ever have caught it.

## Changed

### CLI-855 — a refused share carries the store's own account, unless that account only restates the status

`publish-seed.ts` reads a refusal body for every status, tries the Zod envelope first, and falls back to quoting plain prose behind a content-type gate. **It suppresses a body equal to its own status's reason phrase**, compared against `node:http`'s `STATUS_CODES` trimmed and case-insensitively — which is what makes it a rule about the class rather than a hand-list: 413 and 429 needed no special case and neither will a fourth. A 503 now renders `The store said: Could not store this config`. Finding: [`agent-findings/2026-09-02-a-refusal-body-that-restates-its-own-status-reason-phrase-explains-nothing.md`](../.ai-docs/agent-findings/2026-09-02-a-refusal-body-that-restates-its-own-status-reason-phrase-explains-nothing.md).

### CLI-848 — a refused share stops discarding the body that names the skill

`HTTP ${status}` threw away a body naming the offending skill and sub-agent. The store's `message` field is itself a JSON document, so quoting it verbatim would have printed `[\n  {\n    "code": …` — the implementation parses one level further in, and degrades to status-only for a non-JSON, empty or foreign body.

### CLI-852 — the write half's 409 says a reload fixes it

A contract mismatch and an out-of-date bundle are different refusals with different remedies, and only one of them is fixed by reloading. The 409 branch says which.

### CLI-863 — the push hook runs the suites again, one turbo invocation at a time

`.husky/pre-push` runs lint, unit and e2e for whichever side moved. **The invocations stay separate deliberately**, against a measurement rather than by accident: the concurrent form buys 4% (376s against 392s) and costs a 1-in-10 spurious red from a shared-singleton isolation defect. The two rejected alternatives both reach further than the file — `--concurrency=1` would serialise the web side's eight workspaces, and a `dependsOn` edge would change what `bun run test:e2e` means everywhere.

### CLI-867 — two reference documents stopped arguing for the state CLI-863 undid

Both described the hook as lint-only, and — the half that mattered — both carried standing arguments that the suites do not belong in it at all. A reader acting on either takes them back out. Deleted rather than rewritten. **A fifth defect site was found that the row did not name, and a sixth turned out to be a stale absence of exactly the class being repaired.**

### EDITOR-64 — a query outranks the domain tab rather than compounding with it

The two used to intersect, so a query could only match inside the tab you were already on. A skill is findable by name without knowing which domain holds it, and clearing the query leaves the chip where it was.

## Fixed

### CLI-851 — the editor refuses an unwritable configuration before the POST

A project-scoped skill assigned to a sub-agent resting at global has nowhere to be written. `createSharedConfig` refuses it before the request and names the rows to fix, rather than spending a write to be told no.

### CLI-849 — a write-route double stopped minting what the worker refuses

The double validated nothing, so every editor spec asserting a successful share was asserting about a payload the deployed worker rejects. Making it parse was forbidden — stripping unknown keys would grant `model`/`effort`-absent assertions for free — so the shape is validate-then-forward-raw.

### CLI-861 — the double records what was SENT, not what was accepted

Recording only accepted bodies would let `expect(posted).toStrictEqual([])` be satisfied by an app posting the very payload the guard exists to stop, which is a worse vacuity than the one being removed.

### CLI-853 — the unit suite stops downloading a GitHub marketplace once per test

31 tarballs a run, and the only symptom was a timeout that read as flake. One shared checkout per machine; 90s → 31s.

### CLI-862 — a fixture at a machine-wide path gets a rule about who may write it

Both suites keep a fixture at a fixed `os.tmpdir()` path, because `globalSetup` runs in vitest's own process while specs run in forked workers. A fixed path belongs to the machine, not the run, so a fixture is written by the runner that owns it and by nothing else — held against a walk of the tree.

### CLI-859 — the family's second member repeated the first's silence

The proposed one-line fix was verified **correct and deliberately not taken**: moving the write above the rename is observable only by mocking `fs/promises` at the real shared path, which CLI-862 forbids.

### CLI-860 — the pin the family had been missing

A record write made unconditional, so the checkout's own bookkeeping cannot disagree with what is on disk.

### CLI-856 — a spec directory's kind is stated rather than read off what sits in it

`classify()` inferred a directory's kind from whether it currently held a spec, so the first spec written under `e2e/fixtures/` reddened four gates naming a journey row and a helper that had not moved. **The failure named the wrong file**, which is what made it expensive. Verified end to end: five reds with the derivation restored, one after.

### EDITOR-69 — an over-long sentence is named rather than blamed on a model that was never called

Three defects, two causes. The client read `response.status` where `/compose`'s discriminator is the **body**, so a length refusal rendered as "The model did not answer. Nothing changed." while the worker's own comment says the guards run before the model. Independently, the rate limiter sat **above** the length guard, so eleven over-long pastes exhausted a ten-a-minute allowance on requests that reached no model — and `reportIssue` fired on the branch reserved for the route that spends money on every call. **The field does nothing at the limit, deliberately**: blankness is a predicate the client can evaluate, a cap is a number only the worker owns. Finding: [`agent-findings/2026-09-02-a-rate-limiter-above-a-free-guard-charges-for-work-it-refused-to-do.md`](../.ai-docs/agent-findings/2026-09-02-a-rate-limiter-above-a-free-guard-charges-for-work-it-refused-to-do.md).

### EDITOR-67 — signing in stopped deleting the work it exists to preserve

`adoptLocalStack` mints the local slot on first sign-in; CLI-851 gave that mint a refusal; the guard receiving it returned the stack list, which is empty precisely because adoption only runs against an empty list. So the grid drew neither, and the only trace was a console line no person sees — under a docblock reading **WITHOUT THIS, SIGNING IN LOOKS LIKE LOSING YOUR WORK**. Finding: [`agent-findings/2026-09-02-a-replacement-that-fails-leaves-the-user-with-neither.md`](../.ai-docs/agent-findings/2026-09-02-a-replacement-that-fails-leaves-the-user-with-neither.md).

### EDITOR-73 — and it re-opened one save later

The fix closed the sign-in moment; `save` cleared the reason on **any** save, so the kept slot vanished on the next unrelated one and a reload did not bring it back. Both proposed remedies were refused by the code — clearing only on a local-slot save is unreachable, and recomputing by re-attempting adoption uploads a duplicate every load. What landed: `save` stops writing the field at all, and the branch recomputes the reason from the write contract **locally, without a request**.

### EDITOR-66 — the write-boundary refusal has now been watched failing

Verified by hand in a harness its own lane deleted, so no spec had ever seen it fail. The empty request log is the claim: a `createSharedConfig` that posts first and maps the worker's 400 back produces **identical words on the button**, and only the log separates it.

## Proposed standards

Three rules landed in `standards/`: quote a refusal body only where this CLI is its audience and only where it beats the status; **where a surface shows A in place of B, the condition hiding B must be "A arrived", never "A was attempted"**; and render text this CLI did not author through the sanitiser, stripping before truncating.
