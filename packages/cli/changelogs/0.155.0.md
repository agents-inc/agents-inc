# Release 0.155.0 (2026-08-18)

The editor and the CLI share one configuration, and the vocabulary finally says marketplace (CLI-354, CLI-407, CLI-408, CLI-409, CLI-411, CLI-412, CLI-413, CLI-454, CLI-462, CLI-463, CLI-470, CLI-475, CLI-498, CLI-501, CLI-503, CLI-504, CLI-505, CLI-506, CLI-507, CLI-508, CLI-509, CLI-510, CLI-511, CLI-512, CLI-513, CLI-514, CLI-515, CLI-516, CLI-517, CLI-518, CLI-519, CLI-520, CLI-521, CLI-522, CLI-523, CLI-524, CLI-525, CLI-526, CLI-527, CLI-528, CLI-529, CLI-530, CLI-531, CLI-532, CLI-533, D-212, D-310)

Six days of work that close the loop between the two front doors. A configuration built in the editor installs through the CLI, a configuration installed by the CLI opens in the editor, and skills that exist in neither catalogue travel between them as content. Underneath that, the word "source" finally became "marketplace" everywhere it was ever going to — in the flags, in the environment, and in the config fields, one of which had been holding the opposite of what its name said.

Every item here was landed the same way: tests written and watched fail first, then the implementation, then an expressive-TypeScript pass, then the real binary run by hand.

**This release is breaking.** `--source`/`-s` is now `--marketplace`/`-m` and the old spelling is rejected rather than aliased; `CC_SOURCE` is now `CC_MARKETPLACE`; and a `config.ts` written by an earlier version is a hard error naming the fields that moved. Re-run `init` or hand-edit the two key pairs.

## Added

### CLI-354 — the CLI can mint a shared id

`share` turns the installation in the current directory into a payload the agentsinc.sh store holds and prints the id it was given, and `edit --ui` mints the same id from the same directory and hands it to a browser. The link is printed before it is opened, because over a pipe, in CI or on a machine with no desktop session there is no browser to be anybody's and a link nobody can copy is the whole loss.

The id is the payload's own content hash, so sharing an unchanged installation returns the id it already had and a retry can never double-store.

### CLI-462 — `edit --from <id>`, destructive and interactive

Applies a configuration built in the editor to the installation in the current directory, removing whatever it leaves out. The removals are confirmed with a person first, and a run with nobody to answer refuses before the fetch rather than letting an unanswerable confirm become a yes.

### CLI-507 — external skills install

A skill the editor added from a third-party repository exists in no catalogue either side reads, so it travels in the payload as content — its whole directory, inline — and is written out on arrival. This is what makes an editor-built configuration installable rather than merely readable.

### CLI-508 — the round trip leaves what it does not own alone

A skill nobody installed through this configuration is neither carried into a share nor removed by an apply. The install records what it wrote, and only that is owned.

### CLI-509 — carry-back closes the loop

What the CLI installs can be shared again without losing the skills that arrived as carried content, so the round trip survives more than one lap.

### CLI-510 — the stale-id refusal names the remedy

A payload minted against an older contract is refused with the fix rather than a cause the CLI cannot observe: shared ids are never migrated, and re-sharing mints a current one for free.

### CLI-454 — `new marketplace` returns

The command had been withdrawn while nothing it produced could be consumed. What it scaffolds now works end to end: the emitted tree passes the CLI's own loader, `build marketplace` emits from it, and an `init` against it installs.

### CLI-504 — `build marketplace` emits the catalog the editor fetches

`catalog.json` is the artefact the editor loads in the browser, and `build marketplace` had been writing a manifest its own loader refused. It emits deterministically now, so a re-emit with no source change is byte-stable.

### CLI-407 — a locally authored skill installs

Installation resolved through the catalogue, and a skill written by hand in a local marketplace is in no catalogue, so it was loadable and uninstallable but never installable.

### CLI-408 — a custom skill keeps its identity through the install

What marks a skill as locally authored is now what the install recorded, rather than a lookup against a matrix it was never in.

### CLI-409 — one writer answers the custom question

Two branches of the same writer had been answering "is this custom?" differently, which is the defect underneath CLI-407 and CLI-408.

### D-212 — the install half of custom skill support

The authoring half already existed; this is the half that makes what it authors usable.

### CLI-470 — a compiled agent says who compiled it

Every emitted agent opens with a provenance marker naming the CLI version that wrote it, so a hand-edited agent and a generated one are distinguishable and `compile` knows which of the two it is about to overwrite. Legs 2 and 3; leg 1 shipped in 0.154.0.

### CLI-531 — the enumeration-drift checker

Filed five times in eighteen days and built once. An exhaustive table in a reference document had no checker, so a seventh wizard step or a fifth toast guard could land while the document claiming to enumerate them stayed green. `scripts/check-enumeration-drift.ts` binds each documented enumeration to the source const it mirrors.

### CLI-520 — the smoke files are run by something

No command ran them at all: the old `include` excluded them and vitest has no `--include` flag, so three files sat outside every gate for months. `e2e/vitest.config.ts` is now two named projects, `test:smoke` reaches them, and CI runs it.

### CLI-529 — three of the four escape shapes are judgement, and one is a selector

Of the four ways a check can look like a check without being one, three cannot be linted and are recorded as judgement. The fourth is a selector, and it is now enforced.

### CLI-532 — the vacuous-comparison rules reach every workspace

`no-self-compare` moves to `packages/eslint-config/base.js`. `size` and `byteLength` join `length` in the `no-restricted-syntax` selectors, measured before they did: across every workspace all twelve existing comparisons are discriminating, so the widening condemns nothing that exists.

## Changed

### CLI-501 — the config fields say what they hold

`ProjectConfig.source` held a ref and `ProjectConfig.marketplace` held a name, so a flag about to be called `--marketplace` would have written a key called `source`. Both moved, in the only order that works: `marketplace` to `marketplaceName`, then `source` to `marketplace`, and `SkillConfig.source` to `origin` — that last one because it reads `"eject"` half the time and is provenance rather than a marketplace.

The guard took two layers. `.passthrough()` on the loader schemas was only the first; `loadSourceConfig` wrapped its load in a catch that turned every failure into `null`, so a rejected config resolved to the default marketplace instead of failing. A `refuseRenamedFields` refinement now runs in front of both schemas, where it can read the raw document, and `loadConfig` throws a named `ConfigSchemaError` that `loadSourceConfig` re-raises.

### CLI-463 — the surface says marketplace

`--source`/`-s` became `--marketplace`/`-m` on `init`, the only command that ever defined it, and `CC_SOURCE` became `CC_MARKETPLACE`. The old spellings are rejected rather than aliased — `Nonexistent flag: --source`, exit 2 — and `CC_SOURCE` gets no deprecation warning, because an unusable value in a variable nothing reads is not the run's problem. Roughly 96 user-visible strings across 29 files moved with them.

### CLI-498 — two marketplaces can no longer name one skill

Ids are namespaced by the marketplace they came from, which is what lets one configuration carry skills from more than one. The built-in tables keyed on a bare id had to follow, because a namespaced id falls out of every one of them.

### CLI-411 — `catalog.json` becomes deterministic

Emission order followed the filesystem, so a re-emit with no source change produced different bytes and the generated-drift checks could not mean anything.

### CLI-412 — the catalogue entry carries what the editor needs

The CLI half of the contract the editor's added-skill intake reads.

### CLI-413 — the catalogue is emitted from one place

Three generators had to run in the right order and no entry point encoded it.

## Removed

- **D-213** retired — custom agent lifecycle, depending on a compiled agent-summoner. `new agent` is not returning, and the 15 skipped specs that were blocked on this row go with it.

## Proposed standards

- An exhaustive table in a reference document must name the source const it mirrors, so `scripts/check-enumeration-drift.ts` can bind them. Landed in `documentation-bible.md`.
- A claim about behaviour must cite a symbol rather than describe a shape — a description outlives the code it describes, and five documents did exactly that.
