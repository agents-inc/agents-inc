# Release 0.177.0 (2026-11-04)

A refused `init --from` takes back every file, folder and marketplace registration it created and left empty, `uninstall` leaves what the global installation still holds and removes the trust and empty files its install added, `doctor`'s tip for a missing skill names only ways out that work, `edit` hands out the link it mints as `edit --from`, a switched-off Codex plugin left switched on exits 5, and `build plugins --agents-dir` is removed (REPO-50, REPO-55, REPO-57, REPO-60, CLI-1016, CLI-1018, CLI-1019, CLI-1021, CLI-1022, CLI-1023, CLI-1024, CLI-1025, CLI-1026, CLI-1027, CLI-1028, CLI-1029, CLI-1030, CLI-1031, CLI-1032, CLI-1033, CLI-1034, CLI-1035, CLI-1047, CLI-1048, CLI-1053, CLI-1058, CLI-1061, CLI-1074, CLI-1075, CLI-1076, CLI-1077, CLI-1078, CLI-1079, CLI-1083, CLI-1085, CLI-1086, CLI-1087, CLI-1088, CLI-1095, CLI-1098, CLI-1099, CLI-1102, CLI-1105, CLI-1107, CLI-1108, EDITOR-80, EDITOR-81, EDITOR-82, EDITOR-83, EDITOR-84, EDITOR-86, EDITOR-87, EDITOR-88, EDITOR-127, EDITOR-128, EDITOR-134, EDITOR-135, WWW-18)

## Added

### CLI-1053 — every plugin host must carry a take-back

- Each plugin host must carry the marketplace take-back a refused `init --from` runs: a host without one no longer compiles, and the host contract test fails on one set to null.

### CLI-1075 — a stand-in Claude case for the emptied settings files

- An end-to-end case behind a stand-in `claude` proves a refused `init --from` deletes the settings files it created and left empty, so CI covers what only real-Claude cases did.

### CLI-1021 — the withheld success lines are pinned

- Specs pin that `init --from`, `edit --from` and `update` withhold their success line when a switched-off Codex plugin is left switched on, one entry per plugin, and tie the commands that exit 5 to the warnings they print. Tests only.

## Changed

### CLI-1016 — a switched-off Codex plugin left switched on exits 5

- **`init --from`, `edit --from` and `update` exit 5 when Codex switched back on a plugin you had switched off and it could not be switched off again**, listing it under `Completed with 1 failure — the changes above landed, these did not:` with the `enabled = false` line to set in `.codex/config.toml`. They exited 1 before. `edit` still trusts the project and prints its Codex notices in that case. The docs' exit-code lines name `update`.

### CLI-1058 — `edit` hands out its link as `edit --from`

- **A link `edit` or `edit --ui` mints from an existing installation is handed out as `Apply it:    npx agents-inc edit --from <id>`**, with `--provider` where you named one or the folder holds two installations, since `init --from` refuses to install over an installation. `share` keeps `Install it:  npx agents-inc init --from <id>`.

### CLI-1078 — `doctor` names both ways out for a missing ejected skill

- **`doctor`'s tip for an ejected skill missing from disk names both ways out**: `edit` to take it out, or `eject skills` to bring it back, which also copies every other marketplace skill the installation lacks. It covers the project's own skills and global skills at home, in place of `Re-eject the missing skills from the marketplace to restore their files`.

### CLI-1095 — the tip names only ways out that work

- **The tip names only ways out that work.** A global skill missing, seen from a project, gets both ways out to run in your home folder. A project skill the global installation also holds, and an editor-added `external-…` skill, get only the `edit` take-out. `eject skills` is named only where it restores every missing skill the tip covers.

### CLI-1098 — one tip per place

- **With skills missing from both the project and the global installation, `doctor` prints the project's tip for its own skills, then the home-folder tip for the global ones.**

### CLI-1099 — take-out only for a project skill no longer published

- **A missing project skill the marketplace no longer publishes gets only the `edit` take-out tip**, since `eject skills` cannot bring it back.

### CLI-1102 — take-out only for a global skill no longer published

- **A missing global skill the marketplace no longer publishes gets only the `edit` take-out tip**, at home, seen from a project, or both.

### CLI-1026 — `compile` and `doctor` say a Codex plugin is switched off

- **For a Codex plugin you switched off, `compile` warns `Skill '<id>' is configured but its plugin is switched off — agents will be compiled without it.` and `doctor`'s Plugins Installed row says `1 plugin switched off` and `(plugin switched off)`**, where both said the plugin was not found. A plugin removed outright, and every Claude plugin, keep the old wording.

### CLI-1085 — sub-agent files a run created are counted as created

- **`compile` and `edit --from` count a sub-agent file the run created as created**, as in `0 project agents rewritten, 1 created, 2 unchanged`. The count shows only when it is not zero, so a run that creates nothing prints as before.

### CLI-1035 — a refused `init --from` removes the marketplace it registered with Claude

- **When `init --from` cannot save its configuration, it removes the marketplace it registered with Claude** and prints `Removed the marketplace "<name>" it registered, since the configuration could not be saved`. A marketplace registered before the run, or one whose list could not be read, stays.

### CLI-1048 — the same on Codex

- **On Codex, a refused `init --from` removes the marketplace it registered**, with the same line. One that was there before stays.

### CLI-1047 — a refused `init --from` deletes the Claude settings files it emptied

- **A refused `init --from` deletes the project's `.claude/settings.json`, `~/.claude/settings.json` and `~/.claude/plugins/known_marketplaces.json` where it created them and left them holding nothing**, and keeps any that existed before the run.

### CLI-1077 — and Claude's empty plugin registry

- **It also deletes `~/.claude/plugins/installed_plugins.json` holding no plugins and an empty `~/.claude/plugins/marketplaces/` when it created them.** Claude's state file, its backup and its plugin cache are never touched.

### CLI-1076 — Codex leaves its home as it found it

- **On Codex, a refused `init --from` deletes the files and folders it created in `$CODEX_HOME` and left empty**, and keeps what was there before, even emptied. **A Codex project `uninstall` removes `.codex/` and `.agents/` once empty, and a `config.toml` that held only the project's trust.**

### CLI-1024 — a Codex project uninstall removes the project's trust

- **A Codex project `uninstall` removes the project's `trust_level = "trusted"` from `$CODEX_HOME/config.toml`** and says so: `Removed this project's trust from your Codex configuration: deleted trust_level = "trusted" under [projects."<dir>"] in <file>.` Another trust level, no file, or a Claude uninstall leave it.

### CLI-1025 — a Claude uninstall deletes an emptied `settings.json`

- **A Claude `uninstall` deletes a `.claude/settings.json` holding only an empty plugin list, and `.claude/` when that leaves it empty.** Anything else in the file keeps it.

### CLI-1086 — a project uninstall deletes a home config left listing nothing

- **A project `uninstall` that leaves the home config listing nothing beyond what an install writes deletes its `config.ts` and `config-types.ts`, then `~/.agents-inc/<provider>/` and `~/.agents-inc/` once empty**, on Claude and Codex, without a line. A home config listing another project, a global installation, or anything set by hand stays. Uninstalling after a refused `init --from` and running the same `init --from` again now repeats the first install, apart from the marketplace staying registered.

### CLI-1023 — the stacks schema lists the built-in categories

- **`stacks.schema.json` lists the built-in categories**, so an editor pointed at it flags any other category name in a stacks file. Nothing in the CLI points a stacks file at the schema.

### CLI-1022 — CI's CLI e2e job at a long `.claude` temp path

- CI's CLI end-to-end job reaches its temp folder at a long path under a `.claude` folder, through a symlink. The CI recipe's exit-1 row and the troubleshooting page say `update` may already have moved other plugins when it exits 1, and can be run again.

### CLI-1027 — CI's unit job at the same path

- CI's CLI unit job runs at the same long `.claude` temp path as the end-to-end job.

### CLI-1018 — the CLI e2e job with a symlinked temp folder

- CI's CLI end-to-end job runs with its temp folder behind a symlink and passes the environment through, as the unit step does. The helper that drops the temp folder from output moved beside `compactCliOutput`, with tests a suite runs.

### REPO-57 — git ignores `bun/` and `workboard-export.json`

- `.gitignore` ignores `bun/` and `workboard-export.json`.

### REPO-60 — when to raise `SEED_VERSION`

- `docs/architecture.md` and `seed.ts` say to raise `SEED_VERSION` when an older reader would refuse or misread a link; an optional mark it can drop needs none. It stays 7.

### REPO-50 — comments trimmed

- Comments added since 0.175.0 are trimmed across the CLI, its tests and scripts, CI, the apps and the shared packages. Comment-only, checked by token comparison: no change in behaviour.

### CLI-1061 — the journey page gains rows 86–99

- `user-journeys.md` gains rows 86–97 and 15 legs from four sweeps for journeys it lacked, then rows 98 (a deleted skill folder and `doctor`'s ways back) and 99 (a minted link opened in your own editor).

### CLI-1034 — journey rows match the tree

- Journey rows 14 and 48, and rows 24, 31, 32, 37, 45, 64 and 66, match the tree; the docs site, `docs/architecture.md` and the e2e README follow this release's changes.

### CLI-1105 — journey 13a's way out

- Journey 13a's way out says the reinstall gets what a clean folder gets, apart from the marketplace staying registered with Claude or Codex; journeys 2, 13, 38 and 51 are corrected with it.

### CLI-1083 — the journey page names the spec behind each row

- The journey page names the spec behind each row this release's lanes changed, six specs come off the list of specs belonging to no journey, and the exit-127 comments say it is oclif's unknown-command exit.

### WWW-18 — the docs site's false claims

- The docs site's capabilities page says a sub-agent the catalogue lacks can be added by hand, with the steps; the custom-skills guide says a skill whose slug the public catalogue lacks needs `custom: true` in its `metadata.yaml`, or `doctor` refuses it; and the architecture page gives `init`'s marketplace order as `--marketplace`, then the link's, then `CC_MARKETPLACE`, then the public one.

## Fixed

### CLI-1108 — the home-folder tip names `--provider`

- **From a project, `doctor`'s tip to run `edit` or `eject skills` in your home folder names `--provider <p>` exactly when the home folder holds more than one installation, as `doctor` at home already does.** With Claude and Codex at home, `edit --provider claude` and `eject skills --provider claude` run there as written, and both `doctor`s are clean after; the bare commands it named before exited 2 there. A home folder holding one installation or none gets no `--provider`, and the project's own tip is unchanged.

### CLI-1107 — `doctor` reads the marketplace's own skill list

- **`doctor` judges whether the marketplace still publishes a missing skill against the marketplace's own skill list**, not the loaded one, which also holds every copy on disk. So a global skill a project holds its own copy of gets only the `edit` take-out tip, run in your home folder. Where Skills Resolved stood down, the project's tip keeps both ways out.

### CLI-1028 — a Claude project under a home holding Codex

- **In a Claude project inside a home holding a Codex installation, `init --from` without `--provider` reads Claude's global installation at every step**: its install line counts the sub-agents it compiles, a global skill lands in `~/.claude/skills`, and the first `doctor` reports nothing missing. A broken Codex global config no longer blocks a Claude project.

### CLI-1029 — `doctor` fails an unreadable global Codex config

- **`doctor` fails the Codex block's Config Valid row when `~/.agents-inc/codex/config.ts` exists and cannot be loaded**, as it does for the project's own file, skips Placements Offered, and exits 1. Every row passed with exit 0 before.

### CLI-1030 — a refused `init --from` leaves no blank config or empty folder

- **A refused `init --from` leaves no blank global configuration and no empty skills or config folder that it created.** A folder that existed before the run is never touched.

### CLI-1074 — a plugin it cannot tell it held is kept

- **When the plugin host cannot list its plugins, a refused `init --from` keeps a plugin it installed and says so**: `Kept the plugin "<ref>" it installed, since it could not tell whether the plugin was there before this run`. Before, it left that plugin without a word, and could uninstall one you already had.

### CLI-1087 — and that plugin's marketplace

- **A refused `init --from` that keeps such a plugin also keeps the marketplace it came from**, so the Kept line is true on Claude, where removing the marketplace took the plugin with it.

### CLI-1088 — Codex's can-not-list warnings

- **Codex's warnings that it could not list its plugins or marketplaces no longer say `so this run is treating it as having none`**, which contradicted the Kept line beside them.

### CLI-1031 — a project uninstall leaves what the global installation holds

- **A project `uninstall` leaves a plugin the global installation still holds registered and switched on.** A leftover user-scope registration no global installation holds is still removed.

### CLI-1032 — a Codex uninstall leaves `.claude/` alone

- **A Codex `uninstall` leaves the project's `.claude/` alone and says nothing of it.**

### CLI-1033 — the eject mark at 80 columns

- **`list`'s ⏏ eject mark stays beside the skill's name at 80 columns**, and a wrapped name's next line starts under its first letter, in `list` and in the `init`, `edit` and `uninstall` confirm panels, plugin rows included.

### CLI-1019 — `share --stdin` refuses a carried skill without `external-`

- **`share --stdin` refuses a piped configuration carrying a skill whose id does not start with `external-`**, with the installer's own message and exit 1, before anything is sent. It published a link every `init --from` then refused. Found by this release's hand-run of every journey.

### REPO-55 — shared code, and what the rounds over it fixed

- **A count of one reads `1 skill`, not `1 skill(s)` or `1 skills`**, across `edit`'s `Switching` line, the catalogue-collision refusal, `eject`, `share`, the run summary, `doctor` and `--verbose`; a carried-skill refusal naming one skill says `this skill`.
- **`init`, `compile` and `edit` run in the home folder no longer add it to Codex's trusted projects**, nor say they did. A project inside home still is.
- **`eject skills` names each skill it leaves because its copy lives elsewhere**: `Skipped <id>: its local copy at <folder> stays as it is, even with --force.`
- **A config with no name or no skills warns once**, not four to nine times.
- **`doctor`'s Placements Offered row says `No skills configured` for a config with sub-agents and no skills**, is skipped like its sibling rows for an invalid config, and stands down for a second installation whose config cannot be read.
- **`list` without a terminal names the installation's marketplace.** `init --from` under a Codex home with an old `~/.claude-src` names the Claude folder it writes.
- **`update --help`, the quickstart and the command reference say `update` refreshes every marketplace and moves every installed plugin to its newest version.**
- Code repeated across the CLI, the editor, the worker and the shared packages moved into shared helpers, and the editor's and the worker's shared shapes into `@workspace/matrix` subpaths. A hand-run of every command matched 0.176.0.

## Removed

### CLI-1079 — `build plugins --agents-dir`

- **`build plugins` no longer builds agent plugins, and its `--agents-dir` (`-a`) flag is gone**: either spelling gets oclif's `Nonexistent flag` refusal, exit 2, and writes nothing. A full `build plugins` prunes an earlier build's agent plugins, so `build marketplace` builds again.
