# Release 0.146.1 (2026-08-01)

Corrupt-config resilience, symlinked project paths, and a lint gate that can actually fail

No ticketed work ships in this release — it is the output of a sweep over the 0.145.0–0.146.0 working tree. The recurring shape it found is an artefact that looks like verification but cannot fail: a lint gate with no config file, doc indexes pinning counts that only the indexed doc re-validates, an audit whose arithmetic summed correctly while the set it counted was misnamed.

## Fixed

### `uninstall` no longer aborts when the project config is corrupt

A `ConfigLoadError` escaped `run()` and killed the command exactly when the config was unreadable — that is, precisely when a user most needs to uninstall. The only way out was to hand-delete `.claude-src/`.

`loadUninstallConfig` now catches `ConfigLoadError` **only**, warns `Could not read the project config`, returns `null`, and lets the uninstall proceed to remove the manifest and exit 0. Any other error still propagates. This closes the corrupt-**project**-config path alongside the corrupt-**global**-config path that deregistration already handled.

### Symlinked project paths stayed registered forever after an uninstall

`registerProjectPath` and `deregisterProjectPath` normalized their inputs differently, so a project reached through a symlink — macOS `/tmp`, or a `~/dev/repo` pointing at `/data/repo` — was written to the global config's `projects` array under one spelling and filtered under another. The entry survived every uninstall.

`normalizeProjectPath` is now the single normalization for every value compared against that array: both of the above plus the current-project skip in `propagateGlobalChangesToProjects`.

It **throws** when the directory does not exist, deliberately. A path that cannot be resolved is an error, not a cue to fall back to a weaker normalization — a second tier would reintroduce exactly the asymmetry the helper exists to remove. The one caller that must survive it (`uninstall`'s deregistration) already wraps it in a warn-and-continue guard.

## Added

### ESLint gate

The repo carried an `eslint` dependency and a `lint-staged` entry, but no config file — so the gate passed by never executing. This adds the flat config, an `npm run lint` script, and wires ESLint into both `lint-staged` and `prepublishOnly` alongside the `typecheck` step added in 0.146.0.

The gate opens onto a **known non-zero baseline**. It is recorded under "Known Tooling Gaps" in [.ai-docs/DOCUMENTATION_MAP.md](../.ai-docs/DOCUMENTATION_MAP.md) rather than suppressed with directives, so the debt is visible and countable rather than silently disabled.

## Changed

### One key for the `(id, scope)` slot

`skillSlotKey` and `agentSlotKey` are exported from `lib/wizard/scope-diff.ts` so every surface that classifies a wizard change keys on the same slot instead of re-deriving the template literal or keying on the skill id alone. An id can occupy slots at both scopes simultaneously — the normal dual-scope shape, not an edge case — and two surfaces disagreeing on that key is what let one skill read as added on one surface and unchanged on another.

The agent-side helper has no second caller yet. It exists so that one routes through it from the start rather than re-deriving on `name` alone, which is precisely how the skill side drifted.

### Test-harness consolidation

`writeCorruptConfig` replaces a locally-defined config-corrupting helper in the compile error-path spec, joining `writeProjectConfig` / `writeConfigTypes` as their error-path sibling in `e2e/helpers/test-utils.ts`.
