# Release 0.151.0 (2026-08-05)

The CLI now requires Node 22

## Changed

### Node 22 is the floor

The wizard is drawn with Ink, and this release moves Ink from 5 to 7. Ink 7 requires Node 22, so the CLI's `engines` field now says `>=22` where it said `>=18`.

**What this means on upgrade:** on Node 18 or 20, `npm install` warns about the engines mismatch and the CLI is not supported there. Node 18 and Node 20 have both passed end of life; Node 22 is the current long-term-support release. If you are on it already — or on anything newer — nothing changes.

This was the release's one real decision. Everything below is what came with it.

### The wizard renders with Ink 7 on React 19

The terminal UI moved two Ink major versions and one React major version in one step. Nothing about how the wizard looks or behaves changes: every Ink feature the CLI uses survived both versions unrenamed, the unit suite came out at exactly its baseline of 5,266 passing tests, and all 54 end-to-end specs that drive a real pseudo-terminal pass.

Two keyboard behaviours changed inside Ink 7 and both were tested directly rather than assumed: Escape no longer arrives disguised as a meta keypress, and Backspace now reports as backspace rather than delete. Neither needed a code change — text fields already rejected Escape on separate grounds, and both places reading Backspace accepted either spelling.

### Errors now carry their cause

Eight places — in the compiler, the config loader, the stacks loader and the marketplace runner — caught an error and threw a new one with the original discarded, so by the time a failure surfaced, what actually went wrong was gone. All eight now attach the original error as the cause. The messages you see are byte-for-byte identical; the difference is that a stack trace now reaches the real failure underneath.

(Found by ESLint 10's `preserve-caught-error` rule during the toolchain move below.)

### Internal, invisible from outside

- TypeScript moved from 5.7 to 6, ESLint from 9 to 10 — the whole repository now runs one version of each tool instead of two.
- The built-in matrix was regenerated; it had gone stale and was missing categories added to the source since it was last generated. The recovered categories hold no skills yet, so nothing changes on screen.
- The bundler now compiles for Node 22 instead of downlevelling for a Node 18 the package refuses to install on. The shipped output is byte-identical — the source uses no syntax in that band — so this only makes the third statement of the runtime floor agree with the other two.
