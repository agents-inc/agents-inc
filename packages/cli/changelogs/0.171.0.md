# Release 0.171.0 (2026-10-22)

`doctor` reads each installation, `edit --from` names what it deletes and overwrites, a link's carried skill cannot
write outside its folder, and compiled sub-agents carry only the hooks they declare (REPO-44, CLI-925, CLI-908,
CLI-915, EDITOR-97)

**Before you upgrade.**

- **`agentsSource` and `agentsDir` in `config.ts` do nothing now.** Sub-agent definitions always come from the CLI. A
  config that still sets either key loads, and the next run that writes the config drops it.
- **A marketplace URL that carries a username or password is refused**, the way a private address is. The message masks
  the credentials. The NAT64 local-use range `64:ff9b:1::/48` is refused too.
- **Compiled sub-agents no longer get the typecheck `Stop` hook.** `compile` rewrites installed sub-agents without it.
  A sub-agent keeps any hook its own metadata declares.
- **npm's 0.170.2 was packed from a working tree that already held these changes**, so it already behaves as this
  release does. Its own notes describe only what had been committed. 0.171.0 is the first release whose source matches
  the history.

## Added

### CLI-925 — finishing the wizard removal

- **`AGENTS_INC_EDITOR_URL` sets the editor address every printed link opens.** Without it, the address is
  `https://agentsinc.sh/editor`. The e2e runners withhold the variable. The owner has since ruled that it goes, and
  that a local `AGENTS_INC_API_URL` should select the local editor instead; that is not built (see Backlog).
- **`doctor` checks each installation when Claude and Codex share a scope**, one block per provider. The dashboard
  shows each provider's installation too. With two healthy installations, `doctor` still exits 1 (queued).

### REPO-44 — tooling and prompts

- **The four tester sub-agents run the project's typecheck.** Their prompts say to run it once the implementation
  exists, and to fix what it reports in test files.
- **Mutation-testing helpers in `packages/cli/scripts/`, each with its own tests:**
  - `run-mutation-summary.ts` counts a Stryker report;
  - `run-mutation-ranges.ts` prints the `--mutate` ranges a follow-up pass takes;
  - `run-rebuild-loadtime-files.ts` rebuilds the loaded-dist test list, and takes `--output`.

  `docs/architecture.md` › Mutation testing describes the run.

- **CI refuses an unformatted TypeScript file** (`bun run format:check`).
- **Lint rules:**
  - casting an asymmetric matcher is an error in every workspace;
  - so is a task id in a test name or an assertion message;
  - in the CLI, `fast-glob` may be imported only through `utils/fs.ts`.

## Fixed

### CLI-925 — finishing the wizard removal

- **`edit --from` names every change that deletes files before it asks.** That covers:
  - a move from project to global;
  - a dropped project half of a skill installed at both scopes;
  - a plain removal;
  - an ejected copy switched to a plugin.

  Files written over in place are listed under `Will be overwritten:` (CLI-908).

- **From the home folder, `edit --from` names the registered projects it will rewrite.**
  - The line after the run counts a project as rewritten when its config pair changed, not only when its sub-agents
    did: `Registered projects: N rewritten, M unchanged`.
  - A registered project whose config cannot be opened is named as unreadable, and the run still visits the others.
- **A configuration that changes nothing** makes `edit --from` say so and exit 0 without asking.
- **Skipped unknown skills name the sub-agents that were skipped with them.**
- **At home, a selection with no project-scoped content installs.**
- **`init --from`'s closing `Configuration:` block lists every `config.ts` the run wrote**, including when no sub-agent
  is project-scoped.
- **The kept-as-installed message names `edit --from <id>` to run from the home folder**, instead of telling you to run
  a bare `edit` there.
- **`doctor`:**
  - says when it read a cached copy of a marketplace it could not reach;
  - lists skill folders that no config declares;
  - in a marketplace repository whose own `.agents-inc/config.ts` will not load, reports a failed row and finishes
    instead of throwing.
- **`build marketplace` warns when the repository's `config.ts` is empty or exports nothing.** The warning names the
  file, and the build reads the default layout.
- **`share` and `edit --ui` name the store's rate limit and the wait**, for example
  `rate limit reached — try again in 1 minute`, as the editor's Install dialog does.
- **A link's carried skill cannot write outside its folder.** The id must be a single folder name. An id that is empty,
  `.` or `..`, or that holds a path separator or a terminal control character, is refused three times over:
  - by the worker: `POST /configs` answers 400 and stores nothing;
  - when the link is applied, before anything is listed;
  - when files are written.

  An id like `../victim` used to write outside its folder before the confirm.

- **Terminal control characters are stripped wherever the CLI prints** a skill's display name, a validation warning or a
  skipped key.
- **A remedy or `doctor` tip printed beside a second installation names `--provider`**, so the command it hands out
  acts on the installation it meant.
- **The editor:**
  - a reopened Install dialog keeps the id it minted for an unchanged selection, and asks again after a refusal or the
    rate limit;
  - the output preview lists a sub-agent's skills in the order the install writes them.

### CLI-908 — what `edit --from` overwrites

- **`edit --from`'s confirm names the carried skills whose files it writes over**, under `Will be overwritten:`. The
  same section names the ejected copies that a switch to plugins deletes (CLI-909).
- **A carried skill's `metadata.yaml` is rewritten only where it changed**, in the order it was first written.
  Unchanged bytes are not written again.
- The info table the ticket's ruling asks for is not built, so the ticket stays open.

### CLI-915 — a project's description

- **A project config merged over the home fallback keeps the description of the configuration being installed**, not
  the global installation's.
- `init --from` with a configuration that has no description still writes the global installation's description, so
  the ticket stays open.

### EDITOR-97 — a CLI-minted link opens on its stack

- **A link the CLI mints opens in the editor on the built-in stack it equals**: the same skills, options and sub-agent
  roster. Before, it opened on Start from scratch.
- **The configuration's description carries through to the next id the editor mints.**
- A signed-in account's own saves are not matched yet, so the ticket stays open.

### REPO-44 — the owner's mutation-testing answers and follow-ups

- **`uninstall`:**
  - warns once per plugin it cannot unregister, and exits 0:
    `Could not unregister plugin '<ref>': <cli> not found, so it stays registered.`;
  - no longer prints `Skipping '<skill>'` for each of your own skills;
  - stops on a `metadata.yaml` it cannot read, with
    `Cannot read <path>, so uninstall cannot tell whether it made that skill. Fix the file's permissions, or move the skill out, and run uninstall again.`;
  - removes every agent file the CLI marked as its own.
- **`edit --from` says what it does beside a global install it keeps.** It prints
  `Copying N skills into this project (the global plugin stays)` or
  `Installing N skills as plugins in this project (the global copies stay)`, where it printed `Switching …`.
- **`init --from` over a mixed installation lists where its local skill copies went.** It refuses an unusable `--from`
  marketplace before echoing it.
- **`doctor` labels a refused marketplace `Refused`.** Each refusal's examples are written the way the place that set
  the marketplace writes them: a flag, a config line or an environment variable.
- **`eject`:**
  - skips what is already there one skill and one sub-agent folder at a time unless you pass `--force`, and counts
    what it skipped;
  - `eject all` writes the templates once, and obeys `--force`;
  - an `--output` that is a link exits 2 with `Output path is a link: <path>. Name the folder it points to instead.`
- **The folder-trust notice fires for a project sub-agent that declares any hook**: on any event, and written as block
  YAML too. It speaks of hooks rather than a completion gate.
- **`build plugins` removes the files a skill's source dropped.** A skill plugin's version now moves only when the
  files it ships change. Agent plugins still version by their source.
- **Every directory scan lists its matches in bytewise order**, so an unchanged tree answers the same way every run.
- **An empty plugin or agent name is refused**, once, by the schema.
- **A `config.ts` value under a key shorter than five columns** (`name`, `id`, `path`) stays on its key's line, as
  Prettier keeps it.
- **Compiling an installation takes a skill's origin from its active entry**, not from an entry the other scope
  excluded.
- **Test harness:**
  - the stale-`dist/` guard accepts a build stamped up to three seconds before its sources' last write;
  - unit specs draw on a pinned 80×24 terminal, so a run in a wider terminal turns nothing red;
  - every known gap (`it.fails`) runs once, so the retry report lists only flakes;
  - the Codex placement control and the real-marketplace spec pass on CI.

## Changed

### REPO-44 — tech debt

- **Comments across every workspace say only what the code cannot**, and every remaining cast says why.
- **knip sees every tool's entry points.** Every workspace lists exactly the dependencies it imports:
  - `gray-matter`, `hono`, `tailwindcss` and `@better-auth/cli` are gone where nothing imported them;
  - the CLI declares `ansis` and `esbuild`, which its specs and hand-run rig import.
- **One expressive-ts pass over the eight files past 800 lines, then two rounds over the whole repository.** Each round
  is behaviour-preserving, except for the two fixes above: the empty plugin name, and the compile origin.
- **Tests:**
  - specs that pinned implementation assert behaviour through public entries;
  - specs that read source text are split out, so the rest rejoin mutation runs;
  - e2e specs take expected values from `e2e/pages/constants.ts` mirrors rather than from the code they check;
  - Stryker was re-run on the changed lines, and its survivors have specs.
- **The sub-agent prompts and the prompt bible no longer describe a completion gate.** The developer playbooks say to
  run the project's typecheck and linter.

## Removed

- **The `agentsSource` and `agentsDir` config keys**, with the remote agent-partial fetching behind them. The JSON
  schemas are regenerated. (REPO-44)
- **The typecheck `Stop` hook** that compiled sub-agents got by default. CLI-881, which described that hook's block
  cap, is retired. (REPO-44)
- **Code nothing reached** (REPO-44):
  - the newly-added-skill bookkeeping, `copySkill` and the local-skill count;
  - `isCategory`, `isCategoryPath`, `isSkillSlug` and `allSkills()`;
  - matrix's `typedEntries`;
  - `normalizeConfigPreservingOrder`;
  - the exports nothing imported, across the CLI, matrix, compile, the editor and the test helpers.
