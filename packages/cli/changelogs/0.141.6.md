# Release 0.141.6 (2026-07-18)

`build plugins` now prunes stale `dist/plugins` entries instead of leaving them behind forever (D-238).

## Fixed

### D-238 — `build plugins` doesn't prune stale `dist/plugins` entries

Removing a skill's directory from `<skills-repo>/src/skills` and re-running `build plugins`
left the removed skill's compiled output sitting in `dist/plugins/` indefinitely — the
pipeline only ever added or updated plugin output, never deleted it. This had already bitten
the skills repo once via a manual one-off cleanup commit; the underlying pipeline would have
reproduced the same drift on the next skill rename or deletion.

`compileAllSkillPlugins` (`src/cli/lib/skills/skill-plugin-compiler.ts`) now returns
`{ compiled, failed }` instead of a bare array, so callers can tell which skills failed to
compile rather than silently dropping them from the result set. `build plugins`
(`src/cli/commands/build/plugins.ts`) uses this to compute the exact set of skill-plugin
directory names that should exist after a full-scan compile, then removes any
`dist/plugins/<id>/` directory that isn't in that set and whose manifest identifies it as a
skill plugin (agent plugins and non-plugin directories are left untouched).

Pruning is skipped — not attempted with best-effort guessing — in two cases where it would be
unsafe: single-skill compile mode (`--skill <id>`, which would otherwise wipe every other
plugin) and any run where one or more skills failed to compile (a failed skill's plugin
directory is indistinguishable from a genuinely removed one, so deleting it would trade a
cosmetic stale-entry bug for silent data loss).

`new marketplace`'s scaffold command (`src/cli/commands/new/marketplace.ts`) updated to match
the new `compileAllSkillPlugins` return shape.

None filed for this release — this was a scoped, self-contained fix.
