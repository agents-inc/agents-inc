# Release 0.176.0 (2026-10-31)

`update` moves every installed plugin to its newest version, every command checks a saved marketplace copy with no version stamp and falls back to it with a warning when a download fails, `init --from` takes back the skills and plugins it installed when it cannot save its configuration, a skill carried in a shared link must be named `external-…`, and the docs site gains a Releases section (REPO-44, REPO-49, REPO-51, REPO-52, REPO-53, REPO-54, CLI-845, CLI-875, CLI-885, CLI-887, CLI-901, CLI-911, CLI-912, CLI-916, CLI-917, CLI-918, CLI-921, CLI-945, CLI-971, CLI-979, CLI-982, CLI-991, CLI-992, CLI-993, CLI-994, CLI-995, CLI-996, CLI-997, CLI-1000, CLI-1001, CLI-1002, CLI-1003, CLI-1004, CLI-1007, CLI-1008, CLI-1009, CLI-1010, CLI-1011, CLI-1012, CLI-1013, CLI-1014, CLI-1017, EDITOR-58, EDITOR-61, EDITOR-62, EDITOR-74, EDITOR-90, EDITOR-93, EDITOR-96, EDITOR-116, EDITOR-117, EDITOR-118, EDITOR-119, EDITOR-120, EDITOR-121, EDITOR-122, EDITOR-123, EDITOR-124, SERVER-13, WWW-01)

## Added

### CLI-918 — `update` updates installed plugins

- **`update` refreshes each marketplace the installation names, then moves every installed plugin to its newest version**, on Claude Code and on Codex. Ejected skills are left alone. A plugin that fails to update is named (`Could not update plugin …`) while the rest still update, and the closing line counts the listings refreshed and the plugins updated. Before, it refreshed the listings only and said `Installed plugins were not changed.`

### WWW-01 — the docs site lists every release

- **The docs site gains a Releases section**: a page for every CLI release, built from the CLI's release notes when the site builds and listed newest first in the sidebar, in place of the link to GitHub's releases page. Release pages are left out of the site's search.
- Searching the docs for `uninstall`, `doctor` or `edit --from` now leads with the Commands, Troubleshooting and Editing your config pages.

### REPO-52 — a test file nothing runs is refused

- `bun run deps:check` refuses a test file outside `e2e/` that its workspace's Vitest config never collects, naming the workspace and the file. The pre-commit and pre-push hooks also run it when a change only adds a test file.

### REPO-53 — the pre-commit hook has a spec

- A spec runs the real `.husky/pre-commit` against lists of staged files, one case per kind of change that triggers a step, and against each failing step, as the pre-push spec does for `.husky/pre-push`.

### EDITOR-119 — a ruled-out cell's switches are pinned

- A spec pins that a ruled-out skill's install and scope switches leave the Tab order with the cell.

## Changed

### CLI-992 — a saved marketplace copy with no version stamp is checked

- **Every command now checks a saved marketplace copy that has no version stamp against the marketplace**, at the cost of one extra request, not only `doctor`. The docs that said only `doctor` checks such a copy are corrected.

### CLI-945 — a failed download falls back to the saved copy

- **When a marketplace has moved on and its download fails, the run uses the saved copy and warns** `Could not fetch the update from … — using the cached copy, which is out of date.`, for both kinds of marketplace source. The troubleshooting page lists the warning.

### CLI-885 — a skill carried in a shared link must be named `external-…`

- **`init --from` and `edit --from` refuse a configuration carrying skills whose ids do not start with `external-`**, naming each one, with exit 1 and nothing written. The refusal says to re-share with each named skill added again, which gives it such an id.

### CLI-971 — each command's line in a project whose config declares nothing

- **In a project whose config declares no skill and no sub-agent, each command says a line true for what it does there**: `uninstall` that there is nothing to uninstall in this project, `eject` that it works on the project, `init` that it treats the project as holding no installation, and `search` which marketplace it reads. Where home holds no installation, or only an empty config, the line says there is none to work on.

### CLI-993 — six more messages name skills as the panel does

- **Six more messages name each skill the way the `init --from` and `edit --from` summary does**, by the name its install recorded, then the catalogue's, then its id: a skill assigned to no sub-agent, a project-scoped skill on a global sub-agent, `share`'s refusal of ejected skills, skills a shared id leaves behind, the carried skills written, and the project-scoped skills refused at home. The troubleshooting page follows.

### CLI-996 — one line per skills folder for unregistered skills

- **`compile`, `init`, `edit` and the recompile of registered projects say one line per skills folder** for the folders they skipped for lacking a `metadata.yaml`, such as `Skipped 4 skills in '.claude/skills/' that aren't registered with the CLI (no metadata.yaml)`, instead of a warning per folder. The home folder's line reads `'~/.claude/skills/'` and is said once per run; `--verbose` names each folder.

### CLI-917 — the stack refusal lists what the marketplace ships

- **When `init --from` or `edit --from` refuses a configuration naming a stack its marketplace does not ship, the refusal ends `It ships: …`** with the stacks it does ship, or `It ships no stacks.` The public marketplace lists its built-in stacks. Still exit 1, with nothing written.

### CLI-916 — a line when an id names another marketplace

- **`edit --from` with an id naming another marketplace says, before its question, that the skills come from this installation's marketplace**: `This id names the marketplace …; its skills come from this installation's marketplace, ….`

### SERVER-13 — every signed-in action renews the sign-in

- **Every signed-in action (listing, saving, renaming and deleting stacks, and the composer) renews the 90-day sign-in in the browser as well as on the server.**

### EDITOR-61 — a ruled-out skill's controls show disabled

- **On a skill another choice rules out, the ••• button and both switches show disabled**, to the eye and to a screen reader, and leave the Tab order.

### EDITOR-117 — a ruled-out skill's options panel closes

- **A skill's open options panel closes when another choice rules the skill out**, from the keyboard as with the mouse, and stays closed when the clash goes. Its settings are kept.

### REPO-49 — CI splits its two slow suites

- CI runs the editor's browser tests and the CLI's end-to-end tests each as two halves on two machines (`e2e-editor`, `e2e-cli`), every test once. The deploy waits on `check-web` and both editor halves.

### REPO-54 — CI's CLI unit run with a symlinked temp folder

- CI's CLI unit step runs with its temp folder behind a symlink, as on a Mac, and passes `TMPDIR` through to the tests. The guard on how commands report failure works out `BaseCommand`'s recording methods itself.

### REPO-51 — the briefing contract moved

- The briefing contract moved from `packages/cli/.ai-docs/standards/briefing.md` to `docs/briefing.md`, so an agent reading it no longer loads the CLI's guide. Links, its checker, the test task's inputs and the findings that cite it follow.

### CLI-875 — a test reads an expected value from its file

- `packages/cli/CLAUDE.md` gains a test rule: an expected value the code copies out of a file in this repository is read from that file, not pasted.

### CLI-845 — the config-types reader in the test helpers fails loudly

- The test helpers' reader of the generated `config-types.ts` throws instead of returning an empty list, and two fixtures write `config.ts` and `config-types.ts` byte for byte as the CLI does. The compile cases moved to their own spec under journey 11.

### CLI-1003 — two more config layouts are checked byte for byte

- The two long-list config layouts, one skill name per line and a category's list one name per line, join the automatic byte-for-byte check in `emission-scenarios.ts`.

### CLI-994 — two e2e runs at once

- Each CLI end-to-end run builds its shared test data in its own folder, and the next run sweeps folders left by killed runs, so two runs at once no longer break each other.

### CLI-1014 — the unit suite with a symlinked temp folder

- The CLI unit suite passes with the temp folder behind a symlink, as on a Mac: `createTempDir` hands out the real path, and a guard spec catches a regression on Linux.

### CLI-1017 — the e2e suite with a long temp path

- The CLI end-to-end suite passes with the temp folder at a long path under a `.claude` folder, and through a symlink.

### EDITOR-74 — the fake server's stack ids

- The editor's fake server gives every saved stack its own id, as the worker does, so two stacks of one name stay two in tests.

### EDITOR-121 — the editor's "or" list helper

- The editor's helper that joins a list with "or" is renamed `inAnEnglishAlternative`. The editor keeps its own list helper rather than import the compile package's, which would add about 127 KB to its first screen.

### EDITOR-124 — the editor's script tests run

- The editor's test gate collects `apps/editor/scripts/**/*.test.ts`, so the build-script test EDITOR-122 added runs.

### REPO-44 — the guides, the standards and the findings

- `packages/cli/CLAUDE.md` is condensed with no rule lost, and the e2e standards and the journey page name this cycle's new specs. The findings this cycle wrote are listed under Findings.

## Fixed

### CLI-991 — a project reads only its own tool's global installation

- **`list`, `compile`, `edit --from` and `doctor` in a project read only its own tool's global installation**, so after `uninstall --provider codex` at home a Codex project neither reads nor shows Claude's.

### CLI-901 — a global Codex uninstall removes its ejected skills

- **`uninstall` of a global Codex installation from home removes its ejected skills** from `$CODEX_HOME/skills`. Before, they stayed.

### CLI-979 — `edit --from` at home removes a plugin from another marketplace

- **`edit --from` at home really removes a dropped plugin that a project installed from another marketplace**, trying the name it was recorded under first, as `uninstall` does.

### CLI-995 — moving a plugin from another marketplace between scopes

- **Moving a plugin skill from another marketplace between global and project with `edit --from` removes the old plugin and installs it under the marketplace it came from**, switched on, with exit 0 and the global copy kept.

### CLI-911 — a public-catalogue id under a custom-marketplace global

- **Under a global installed from a custom marketplace, `init --from` with a public-catalogue id installs from the public catalogue.** The marketplace comes from `--marketplace`, then the id's, then `CC_MARKETPLACE`, then the public one, and never from a config.

### CLI-912 — that project records the public catalogue

- **Such a project records its marketplace as `agents-inc`**, so a later `edit --from` installs `<id>@agents-inc`. It recorded the global's before.

### CLI-997 — a public-catalogue project keeps its marketplace

- **A project set up from the public catalogue keeps its own marketplace and name when a global is installed from a custom marketplace afterwards**, so `edit --from` there installs `<id>@agents-inc`. The global config's same mismatch is fixed too.

### CLI-921 — declining `edit --from` says so once

- **Declining `edit --from`'s question prints `Edit cancelled` once**, still with exit 4. `Error: Cancelled` followed it before.

### CLI-982 — `init --from` that cannot save leaves no copies

- **When `init --from` cannot save its configuration it removes the skill folders it copied, in the project and at home, and leaves home's config as it was**, so the next run works.

### CLI-1001 — `init --from` that cannot save takes back its plugins and says so

- **After a refused save, `init --from` also uninstalls every plugin that run newly installed, at the scope it went to**; plugins already there are untouched. It says `Removed the N skills it copied, since the configuration could not be saved` for marketplace copies and, on its own line, `Removed the N skills this configuration carried, since the configuration could not be saved`. Exit 1, with the error printed once.

### CLI-1000 — a project config naming nothing reads the global marketplace

- **A project config that lists no skill and no sub-agent and names no marketplace uses the global installation's marketplace, as having no config does**, in `compile` (`Marketplace: global`), `search`, `eject` and `doctor`. A config naming a marketplace is left as it was.

### CLI-1002 — on Codex, `update` keeps a switched-off plugin switched off

- **On Codex, `update` moves a plugin you switched off to its newest version and switches it back off.** If it cannot, the other plugins still update, a warning names the plugin, `.codex/config.toml` and the `enabled = false` line to set, and `update` ends with an error.

### CLI-1008 — `init --from` and `edit --from` and a switched-off Codex plugin

- **On Codex, when `init --from` or `edit --from` cannot switch a plugin you had turned off back off, they no longer say `continuing with cached version`**: the warning names the plugin, `.codex/config.toml` and `enabled = false`, every step still runs, and the run exits 1 with `1 plugin you had switched off is switched on again: …`. A refresh that really fails keeps its line and exit 0.

### CLI-1004 — the "Set category" warning names the real file

- **The `Set category in …` warning for a custom skill whose category the installation does not declare names the absolute path of its `metadata.yaml`**, so a home-folder skill read from a project points at the real file.

### CLI-1007 — a marketplace's declared stacks file

- **`init --from` and `edit --from` install a stack from a marketplace that keeps its stacks at a custom `stacksFile` path**, reading the file it declares.

### CLI-1009 — `doctor` checks a declared stacks file

- **`doctor` in a marketplace that declares `stacksFile` checks the file at that path**; a broken one is an error with exit 1, as at the default path.

### CLI-1011 — `doctor` files a broken stacks file against itself

- **`doctor` files the warning for a broken stacks file, at the default or declared path or one that does not parse, and for a `config/skill-rules.ts` its schema refuses, against the file that failed.** A broken categories file keeps its warning.

### CLI-1013 — `doctor` files a broken skill-rules file against itself

- **`doctor` files a `config/skill-rules.ts` that does not parse, exports only named bindings or exports nothing against that file**, as `Cross-reference validation skipped: failed to load config/skill-rules.ts: …`, instead of against the categories file. Messages and exit codes are otherwise unchanged.

### CLI-887 — the carried-id guard cannot be steered

- **The marketplace a shared link names can no longer steer the guard that keeps a carried skill off a catalogue id**: with CLI-885's prefix, no carried id can take a marketplace skill's place.

### EDITOR-58 — scrolling from the keyboard

- **The output preview's text, a skill's contents, a long composer proposal and the Install dialog's lists in a short window can be reached and scrolled from the keyboard.** The editor's e2e page objects own the contents pane and the Install dialog's "Skills and agents" area, found by its screen-reader name.

### EDITOR-62 — "1 change"

- **A proposal with one change reads `1 change`, not `1 changes`.**

### EDITOR-93 — Tab across the stuck skills bar

- **Tab and Shift+Tab across the stuck skills bar no longer throw the page up.**

### EDITOR-96 — the rename prompt and the Contents dialog

- **The rename prompt for a clashing stack name no longer opens over an added skill's Contents dialog.**

### EDITOR-116 — a button group's Tab stops

- **The design system's `ButtonGroupItem` takes a caller's `tabIndex` only when it is set**, so `tabIndex={undefined}` no longer makes every option a Tab stop, and an explicit value still wins.

### EDITOR-120 — three more primitives' Tab stops

- **`SegmentedItem`, `LatticeRow` and `CommandBlock` take a caller's `tabIndex` the same way**, so `tabIndex={undefined}` no longer drops a Tab stop. `packages/ui/CLAUDE.md` gains the rule and names `Chip` as its exception.

### EDITOR-122 — a failed editor build shows its own error

- **A failed editor build shows its own error**, such as the first-paint budget, instead of one from copying the fallback page.

### EDITOR-123 — the Codex install dialog's "and"

- **The Codex install dialog joins the two sub-agents it leaves out with "and"**, not "or".

## Removed

### CLI-1010 — the config writer's import-the-global layout

- The config writer's layout that imported the global config, which no command wrote, is gone with its option and tests. The CLI's output is unchanged.

### CLI-1012 — what CLI-1010 left behind

- The `source` entry kind, `getGlobalConfigImportPath` with its test, and an assertion that could not fail are gone. A user sees no change.

### EDITOR-90 — the design system's focus-outline checks

- The design system's stories no longer check the keyboard focus outline.

### EDITOR-118 — the editor's focus-outline tests

- The editor's eight browser tests that only checked the keyboard focus outline, and their helpers, are deleted. The tests of where focus moves stay.
