# Release 0.139.0 (2026-04-20)

Backlog grooming and demo assets. No product code changes.

## Added

### Backlog

- **D-218** (plan): plugin-install hardening follow-ups — `mode-migrator.ts` data-loss ordering (deletes local eject copies BEFORE marketplace check) and `ensure-marketplace.ts:43` unwrapped `claudePluginMarketplaceAdd` (raw stack traces surface to the user). Item 2 of the original triage landed in 0.133.0 via `requireMarketplace`.
- **D-226** (plan): E2E sandbox collapses `HOME` into `projectDir` (`terminal-session.ts:56` default `HOME=cwd`), making `GLOBAL_INSTALL_ROOT === cwd` and `isEditingFromGlobalScope=true` for every project-context test. ~100 launch sites affected. Fix direction: change default `HOME` to sibling tempdir + add `launchInProject` / `launchInGlobal` named constructors on the wizard launchers.
- **D-227**: agent-path tombstone loss in `preselectAgentsFromDomains` and `stack-selection.tsx` — symmetric to D-223 but on the agents path; surfaced during D-223 verification.
- **D-228**: global skill install does not propagate to project `config-types.ts` / `config.ts`. Duplicate of D-216 Regression #1.
- **D-229**: plugin install failure leaves orphan `config.ts` entry — same resolve-before-mutate violation class as D-218 item 1.
- **D-230**: info-panel `-` next to global row on dual-scope G→P add — global is not removed (dual-scope), the `-` is wrong.
- **D-231**: remove dead `version` field from `config.ts`.
- **D-232**: info-panel `+` for globally-installed skill after G→P toggle on next `cc edit` — wizard mis-tags as newly-added instead of already-installed.

### Demo assets

- `assets/demo.tape`: VHS (charmbracelet/vhs) script that records a full `npx @agents-inc/cli init` wizard walkthrough to `demo.mp4` (1000×1000, Monaspace Neon, custom One Dark-ish theme).
- `assets/theme.json`: 24-bit ANSI color palette used for the recording.

## Changed

- D-216 plan updated: Regression #2 (scope hardcoded to `"global"` at creation sites) is obsolete — that behavior is intentional per the product's scope model (defaults to global; toggle to project is explicit). Regression #1 (`writeScopedConfigs` calls `writeStandaloneConfigTypes` instead of `regenerateConfigTypes`) remains the active fix.
- D-217 plan marked `Needs Re-Plan`: investigation found the plan mis-targets the fix site (`compileAgent` has zero production callers; real bug is `compileAgentForPlugin`'s whole-agent `installMode` gate failing mixed-mode agents) and the proposed fix expression `s.source !== "eject"` won't compile (`Skill` type has no `source` field). Plus edge cases around marketplace disambiguation, prose-embedded refs, local skills, and stale skill references.
- D-219 plan folded into D-226: shared plugin fixture becomes the default `source` inside the new `launchInProject` / `launchInGlobal` sugar. ~96% of the 172 `source: { sourceDir, tempDir }` call sites can drop the plumbing.
- Plan-file status notes added to D-216, D-217, D-219, D-220, D-221, D-222, D-223, D-224, D-225.
- Minor prettier/linter fixes on files already committed in 0.137.0 / 0.138.0.
