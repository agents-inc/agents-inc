# Release 0.164.0 (2026-09-06)

Every shipped sub-agent moves to the 2026-09-03 doctrine, the web skills say when to use them, and the editor takes the 2026-09-05 design refresh (EDITOR-09, EDITOR-75, EDITOR-76, EDITOR-79)

## Changed

### The eighteen shipped sub-agents

All 18 agents in `src/agents/` now read in the voice the doctrine settled on 2026-09-03. Two of them
already did — `meta/agent-summoner` and `meta/skill-summoner`, rewritten in 0.162.0 — and the other
sixteen still carried the forms it retired. Measured across the whole fleet:

|                                     | Before                | After              |
| ----------------------------------- | --------------------- | ------------------ |
| Markdown lines across the 18 agents | 14,236                | **9,026** (−37%)   |
| `**(You MUST …)**`                  | 228                   | **1**              |
| `CRITICAL:` headings                | 26                    | **0**              |
| "Failure to follow…" closers        | 15                    | **0**              |
| Largest agent                       | `codex-keeper`, 1,680 | `ai-tester`, 1,119 |

The one surviving `You MUST` is in `agent-summoner`'s `<voice>` section, where it names the retired
form in order to forbid it. `codex-keeper` went from the largest agent to 413 lines.

This is a prompt-content change and reaches every project that installs or recompiles. Nothing about
the agent contract moved: the roster is the same eighteen names, the three-file shape holds 18/18,
and no agent restates `operating-principles.liquid`.

### A skill's `usageGuidance` says when to reach for it

The `web-*` skills in the [`agents-inc/skills`](https://github.com/agents-inc/skills) marketplace went
through the same doctrine pass, and the vendored catalogue carries the result. The guidance sentences
name the situation a skill is for rather than restating its title — `web-styling-scss-modules` now
reads "Use when writing scoped component styles in .module.scss, organising Sass with @use and
@forward, or ordering styles with CSS cascade layers", where it had said "Use when styling with SCSS
Modules, design tokens, or CSS cascade layers".

A third pass closed two surfaces the first two never reached, found by byte-comparing every `web-*`
markdown file against the baseline rather than trusting a lane's local estimate: **38 files totalling
10,190 lines had never been opened**, against an estimate of ~4,000. The two surfaces needed opposite
work — a file the programme never wrote to cannot hold a programme-introduced defect, so a
substitution sweep over it is looking for something that is not there by construction.

### EDITOR-09 — the editor takes the 2026-09-05 design refresh (Phase G)

`.claude-design/` was refreshed in place for the third time and the owner named eleven changes. All
eleven landed:

- **`selected` moved to the skills hinge** and states its value — `all 238` ⇄ `selected 23` — drawn
  only once something is selected. It is still a chip; it moved. Two other homes were built and
  rejected, inside the search field and on the domain strip, both because they put a control that
  narrows the whole column inside something narrower than it.
- **The domain strip is equal cells spanning the column**, at one type size in every state. The
  25px-Inter active label is gone: it grew the strip, moved the sections under it, and so changed
  which domain the scroll spy called current — a selection that rewrote its own input.
- **The first stack cell is the reset.** It renames to `Clear and start from scratch` with a
  `removes N skills and every sub-agent` line once anything is selected, and releases the `selected`
  filter when pressed. The separate `N skills selected ✕` block is gone.
- **The assignment pulse is the whole agent row**, bleeding to the panel's border on one side and the
  scroller's own padding on the other. It sat on the pin button, which stops where the agent's three
  cycling words begin — so a pulse said "these skills reached this agent" while leaving that agent's
  model, effort and scope outside the thing being pointed at.
- **Save / Share / Preview are three equal outlined cells** in one row above Install, on a new
  `action` button variant. Install stays the panel's only filled element, and its label reads
  `N agents · N skills`.
- **The output preview gained fullscreen and a tree/code splitter.** The code pane is ~60 characters
  at 760px, which is narrow enough that generated `config.ts` lines wrap and stop looking like the
  file they claim to be. `esc` steps out of fullscreen before it closes; the splitter is clamped so
  neither pane can be dragged out of existence; both survive a close.
- **One icon set**, at stroke-width 1.75 with butt caps and miter joins. Five glyphs had come from
  four different places — `＋` and `−` were fullwidth CJK punctuation, `↩` and `▾` were typographic
  characters, and only the code brackets were drawn — so a text glyph inherited the font's weight and
  baseline where an SVG did not, and two glyphs a row apart disagreed about where the middle of a
  line is. `✕`, `✓`, `⌘` and `↗` stay text: the set is a closed list and none of them is in it.
- **Incompatible skill cells recede rather than fade.** The cell stops being white and sinks into the
  column at full opacity. `opacity: .4` put the skill's own name at roughly 2.1:1 and faded the
  cell's hairlines with it, so the lattice broke and it read as a rendering fault rather than a state.
  The name measures 14.8:1 now.
- **The main column is `#faf8f2`**, one value in `tokens.json`, carried by the four surfaces that
  must move together — the column, the sticky filter bar, the dock and the hinge button — because
  leaving any behind shows a seam when the bar or the dock sticks.
- **An amber field behind the active nav item and the roster's grouping control**, bled to the rail's
  own padding and the panel's inset by an equal negative margin, so the field paints larger without
  moving a single neighbour.

Two decisions the design does not state, both recorded in `todo/plans/editor-v6/`: the strip's
horizontal cell padding is not the design's 15px (drawn for 309px cells against three domains, where
this catalogue has nine), and the strip does not gain the design's stuck top padding (this band never
loses the 12px the design's own band loses, and a bar that grew as it pinned would land every
jumped-to section under itself).

## Fixed

### EDITOR-75 — the padding below a sticky dock was 132px of grid nobody could reach

`<main>` carried `pb-30`. A `sticky bottom-0` box is confined to its containing block's **content**
box, so the padding lay entirely below anywhere the dock could come to rest: measured at maximum
scroll, the dock parked 132px above the viewport floor over a strip of bare column, with 132px of
grid permanently off-screen. Deleted rather than tuned — the dock's own comment argues against
hardcoding its height at all, since it grows a conditional child. No spec could see it: the suite
reads `<main>`'s box exactly once, for width.

### EDITOR-76 — every bordered text field is the whole of its own border

The shared `Input` is a bare field meant to sit in a box that draws the border, and every one of those
boxes kept the padding as well — so the ring between the border and the text looked like the field,
sat inside its border, and moved the caret nowhere. All five bordered fields are now the whole of
their box: the search field at rest and stuck, the composer's band, the add-skill search, the
marketplace field and the access-token field.

The composer was the last and the hardest. Its control row is drawn over the field's measured foot
now — measured, because the row's height depends on the fallback font that draws `⌘↩` — and
`pointer-events-none` lets the empty run beside the Send button through to the field.

The acceptance is a click rather than a class: a rule about which element owns the padding is
satisfied by any number of arrangements that still leave a dead ring, so the spec presses 2px inside
each corner of each drawn box and reports which corners took the caret. It also asserts the caret
lands where the pointer went rather than at the end, which is the half a `<label>` wrapper satisfies
by accident.

### EDITOR-79 — the domain strip navigates the list rather than filtering it

Clicking `API` no longer hides `web`: it scrolls the API section to rest under the bar, and scrolling
back up makes `web` current again. `isVisibleDomain` stopped reading `search.domain`, so every domain
renders at every value; `?domain=` became an anchor honoured once on arrival rather than a filter that
persists; and the click-again-to-release toggle went, because a pick that hides nothing has nothing
to release. A tab reports `aria-current` and no longer `aria-pressed` — a pressed state on a control
that only moves the page is a toggle a reader cannot turn off.

### The nav rail's marketplace section, and the copy that pointed at a renamed label

The floating marketplace button moved into the rail as a section above the account row; `Home` became
`About` (the word names a destination instead of a position, and the logo directly above it already
went home), `Configure` became `Editor`, and the hairline between Marketplace and the account row
went with `RAIL_SECTION_CLASS` splitting into a layout half and a rule half.

The rename's second half is the defect worth naming: `shared-link.spec.ts` asserted the label's
literal against product copy, which is red in one direction only — copy drifts, red; label drifts,
green. Two locators in the same file did redden, so the file looked considered while product copy
told people their configuration was safe under a nav word that no longer existed.

## Added

- `Glyph` in `@workspace/ui` — the one icon set, with the geometry asserted rather than looked at,
  because round caps against a design with no radius anywhere are invisible at 11px until two glyphs
  sit on one row.
- `HingeToggle` in `@workspace/ui` — the `selected` filter, rendering `Chip` with the three overrides
  a chip standing on a rule needs: the hinge's own border, the column fill that masks the rule behind
  it, and a fixed height matching the accordion button on the rule above.
- `DialogPaneSplitter` and a `fullscreen` arm on `DialogContent`, with the tree's resting width and
  its bounds stated once in the design system.
- An `action` button variant — the only button in the design with no fill at all, because three
  filled cells over Install would make Install the fourth thing on the row.
- `retired-prose-forms.ts` under `src/cli/lib/__tests__/helpers/`, with its own tests: the doctrine's
  retired forms are now scanned for across every agent partial rather than spot-checked.
