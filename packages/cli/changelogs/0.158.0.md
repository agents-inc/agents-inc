# Release 0.158.0 (2026-08-24)

A rule author's reason reaches the grid, three defects leave the shipped surface, and the E2E suite stops describing states the CLI cannot produce (CLI-547, CLI-557, CLI-596, CLI-613, CLI-647, CLI-648, CLI-650, CLI-652, CLI-679, CLI-689, CLI-692, CLI-730, CLI-736, CLI-742, CLI-746, CLI-757, CLI-761, CLI-770, CLI-771, CLI-778, CLI-788, CLI-789, CLI-790, CLI-793, CLI-795, CLI-796, CLI-797, CLI-801, CLI-802, CLI-803, CLI-804, CLI-805, CLI-806, CLI-807, CLI-808, CLI-809, CLI-810, CLI-812, CLI-813, CLI-814, CLI-815, CLI-817, WWW-08)

The mechanical worklist that opened after 0.157.0 is empty. Thirty-seven rows were worked; the ones retired without work are in `todo/archive.md` with the measurement that retired them, and are summarised under Backlog rather than repeated here.

**Two rows were closed by disproving their own premise, and that is the release's recurring shape.** `CLI-736` was blocked on a design decision between two options; measuring the tree showed seventy of the seventy-six heaviest E2E files build a PLAIN source rather than a plugin one, which settles the choice and rules the other option out — a marketplace makes every skill non-local, and `defaultOriginFor` would have flipped seventy files' worth of unstated install origins. `CLI-730` named a real harm and prescribed a cure that cannot be applied to most of its own population: 67 of its 168 sites declare an installation with nothing installed, which is the negation of what a wizard run produces and precisely the precondition `compile`'s no-skills refusals need.

## Added

### CLI-757 — the grid says why a requirement is needed, in the rule author's words

`requireRuleSchema` has always required a `reason` on every `requires` rule, so every marketplace author has been made to write one — and nothing rendered it. The grid showed the synthesised half alone, `requires React or Next.js`, which says WHAT is missing and cannot say why. Both siblings already rendered theirs: `discourages[].reason` in the grid, `conflicts[].reason` through `reportValidationErrors`.

Clipped at 60 characters, and the budget is the design rather than a detail. The cell wraps rather than elides, so an unbounded authored string grows the tag, grows the frame and pushes the top of the wizard off the terminal — the shipped catalogue's longest reason is 242 characters and its React Router entry alone cost four lines. 60 leaves the median of 46 untouched and clips 24 of 110 rules. Guarded on emptiness rather than presence, because the schema requires the key and not a non-empty value.

### CLI-652, CLI-679 — two compiler-API checkers, and five the row argued against stay unbuilt

`scripts/check-boundary-union-casts.ts` walks for `string as <generated union>` and holds the twelve live sites in a declared backlog, so the count can only fall. `PARSE_BOUNDARIES` scopes the exemption by directory rather than by site, because such a cast at a genuine parse boundary is the construct working.

`scripts/check-symbol-file-pairs.ts` holds a document's `symbol | file` table to what the named file DECLARES — not what it exports, and not what it mentions. It refuses a run finding `NO_PAIRINGS`, because a checker that silently matches nothing reports zero drift forever. `CLI-679` is the narrowing that closes the gap between the two existing gates without the naive rule its own row warned against.

### CLI-770, CLI-689 — two helpers that were each written twice

`flattenCliOutput` undoes oclif's terminal wrapping, and twenty-three specs were reaching for a copy that lived in `e2e/fixtures/seed-config-store.ts`. `globalHomeFor` answers which HOME an installation answers to; `CLI.run` decides the HOME the spawned binary runs under and `expectFourSurfaces` decides the HOME it then reads, and nothing made the two move together. Both now live in `src/cli/lib/__tests__/helpers/` with their own tests — no vitest project collects `*.test.ts` under `e2e/helpers/`, so a helper tested there looks like coverage and never runs.

## Changed

### CLI-736 — the E2E suite shares two frozen fixtures instead of building one per file

`globalSetup` writes two trees once per run and freezes both with `chmod -R a-w`: the plugin-capable `fixture/`, and a plain marketplace-less `plain/` exported as `E2E_SOURCE`. `InitWizard` defaults to the plain one, so an ordinary spec names no source at all.

The freeze is not protecting the fixture — it is protecting the diagnosis. A shared fixture one spec mutates is one every LATER spec sees mutated, under a worker schedule that moves between runs; `chmod` turns that class into an `EACCES` at the offending line, in the file that owns it, every time. It is what found the copier defect below.

Eighty-seven files lose the same ceremony — two suite-level `let`s, a `beforeAll` calling `createE2ESource()`, an `afterAll` cleaning it up — and every one was building the identical tree. It measures at **10ms**, so the per-file sharing bought nothing; what it cost was ten lines a spec and a two-field object assembled at every launch. The thirteen helpers in `dual-scope-helpers.ts` now take one `source: E2ESource` where they took a pair.

`EditWizard` deliberately does not default. `edit` takes no `--marketplace`, so its launcher RECORDS the source into the install's config, and `recordInstallSource` refuses an install with no config yet — a default there turns "this project has nothing to edit" into a throw from a fixture helper.

### CLI-730 — a fixture's config.ts is now what the CLI would have written

`writeProjectConfig` rendered its own pretty-printed JSON while `config-writer.ts` emits typed named variables, an `import type`, `satisfies ProjectConfig`, canonical field order, space-free entry lines and a compacted stack. The two disagreed on every part of the file an assertion can see — including the spacing that decides whether `toContain('"scope":"project"')` matches at all. A fixture rendering its own shape pins every assertion over it to the fixture rather than to the product, which is the divergence the row was filed for, and it is now closed at one site for all 150.

The row's method — "E2E tests must only use CLI commands to create state" — is documented as not implementable, with the classification behind it: 67 sites declare an installation with nothing installed, 42 are populated installs each built around something the CLI cannot author, 13 are corrupt neighbours (no CLI writes an unreadable config), and 13 are the infrastructure the row already exempts.

What replaced it is a round-trip audit. Rendering through the writer proves a fixture's FORM; reading it back and writing it again proves its CONTENT is reachable, because the loader normalises. `writeProjectConfig` carries an env-gated `CONFIG_ROUNDTRIP_PROBE` that reports any config failing that trip — 19 of 150 do, all one cause, in four files.

### CLI-650 — the slug map has one direction, and a synthesised category keeps its declared domain

`SkillSlugMap.idToSlug` had zero readers anywhere; every occurrence was a write. Two maps built from one source can disagree, one cannot, so deleting it retires the class rather than guarding it. Beside it, the synthesis loop now warns when a source and the catalogue disagree about a skill's domain instead of silently taking one, and keeps a declared category when the source already names one.

### CLI-547, CLI-742 — the task-ID backlog closes to its irreducible core

Re-measured at an eighth of the size the row claimed. `CLI-430` in a page-object comment and `SKILLS-09` in a `skill-audit.ts` source line both go; the remaining `D-220` pair sits in file-level JSDoc, which `packages/cli/CLAUDE.md` names as the one permitted home.

### CLI-771, CLI-793, CLI-795, CLI-813 — the build race, and three gates that read their own inputs wrong

`turbo.json` already ordered `build` ahead of `test`, `test:e2e` and `test:smoke`, so the npm `pretest*` hooks were each a SECOND build — and turbo runs those tasks concurrently, so one invocation fired three `tsup` builds. `tsup` builds with `clean: true`, so two raced on one `dist/` and the loser died with `ENOENT ... unlink dist/chunk-*.js`. Measured at 3 invocations per run, now 1. A bare `bun run test` reaches `assertDistIsFresh`'s refusal instead of rebuilding, which is the posture that file already argued for.

`check-enumeration-drift.ts` loses a count from one anchor: `— all 12` made a prose number load-bearing for the anchor itself, so a thirteenth member reddened the members check and correcting the sentence then reddened a second row for an unrelated-looking reason. The from-scratch classifier in `spec-gates.test.ts` gains a word for the third shape a spec takes.

## Fixed

### CLI-790 — `uninstall` survives a metadata.yaml it cannot parse

`parseYaml` throws on malformed input and `existingMetadataFields` called it bare, so an installed skill whose `metadata.yaml` had been hand-edited into invalid YAML took the whole command down before it deleted anything. The read is a discriminated `YamlRead` now; a file that will not parse warns with its path and contributes no fields, and the warning names what that costs.

### The copier left ejected skills unwritable

No row — found by the frozen fixture above, which is the point of freezing it. `fs.copy` preserves mode, so ejecting out of a read-only marketplace checkout produced `r--r--r--` inside the user's own project. Eject means you own it, and a file you cannot write is not owned. `copy()` now ORs owner-write across the copied tree rather than assigning a mode, so an executable stays executable.

### CLI-814 — `doctor` counts one skill as one skill

The marketplace row read `1 skills available`. `plural()` exists for exactly this and every other count on that screen already went through it.

### CLI-647, CLI-803, CLI-804, CLI-807, CLI-810, CLI-788 — assertions that could not have failed

`expect(x.projects ?? []).toStrictEqual([])` cannot tell an absent key from an empty array, and those are different claims. `toBeGreaterThan(0)` over a compiled-agent roster cannot see a swap. `toContain(\`\`)`is true of every string.`listFiles` comparisons cannot see a file REWRITTEN in place. Each is repaired and mutation-proved — the old assertion stays green on the same mutation the new one catches.

### CLI-815 — the editor offers a loaded marketplace's own categories

The editor consequence of the scoped catalogue emission, now guarded: a spec run against the public catalogue cannot tell whether the placement list came from the loaded marketplace or from a hardcoded default, because the two agree there.

### WWW-08 — the site header reads at the type system's scale

Closed, and its stated remedy was refused in writing by the site it targets. The header set its wordmark from a hand-picked body size while the landing half used the token scale.

## Removed

### CLI-778 — two dead surfaces on the agent assertion helpers

`expectCompiledAgents` had zero call sites. `expectValidAgentMarkdown`'s `options` bag carried `hasCorePrinciples` and `hasMethodologies` that nothing could reach: all eight call sites pass two arguments and both flags defaulted to running their check, so the signature promised a discrimination no caller made.
