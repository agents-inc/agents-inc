# Release 0.137.0 (2026-04-20)

Config correctness overhaul — three independent merger / propagation bugs fixed.

## Fixed

### D-220 — Per-agent stack curation preserved across edits

User-authored curation of `stack.<agent>` (e.g., hand-removing a skill from one agent's stack via a `config.ts` edit) was silently re-added on the next `cc edit` run. `buildAgentStack` regenerated membership from ownership + scope defaults and only consulted `existingStack` for the `preloaded` flag; user intent was not representable.

`config-generator.ts` gains a `shouldIncludeTriple` predicate that keeps prior curation, appends skills in `newlyAddedSkillIds`, admits (agent, skill) pairs in `scopeEligibilityGained` (skills whose scope flipped to compatible this session), and seeds from ownership defaults only when the agent is brand-new. `local-installer.ts::buildEjectConfig` computes both deltas from `existing.config` and threads them into the generator.

E2E: `e2e/lifecycle/stack-per-agent-curation.e2e.test.ts` — three scenarios (curated-removal preservation, newly-added skill fanout with `preloaded:true` carried, new-agent seeding). 183/183 tests green across the D-220 surface.

### D-221 — `agents` array deduplicated on scope migration

Agent scope toggle (project→global) was leaving the stale project-scope row in the `agents` array while adding the new global-scope row, producing duplicates across repeated edits (observed: 5× `web-researcher` at project scope after multiple cycles).

`mergeConfigs` in `config-merger.ts` now uses compound keys `${name}:${scope}${excluded?:excluded}` for agents (parallel `skillKey` for skills) and applies **authoritative-from-newConfig** semantics: existing rows whose identity is in the new config but whose compound key is missing are dropped (the migration case). A final `uniqueBy` pass idempotently repairs on-disk corruption. The dual-scope invariant (active + excluded tombstone at different scopes) is preserved because the wizard emits both rows explicitly.

E2E: `e2e/lifecycle/agent-scope-toggle-agents-array.e2e.test.ts` (3/3). Unit: `config-merger.test.ts` 45/45.

### D-222 — `selectedAgents` propagated to type-side writer

When a global agent toggle propagated to other registered projects, the value-side writer merged `global.selectedAgents ∪ project.selectedAgents` correctly, but the type-side writer received a `combinedConfig` that omitted the merge — downstream projects saw `SelectedAgentName` narrower than the actual `selectedAgents[]` array, producing compile-time type errors in propagated projects.

`propagateGlobalChangesToProjects` in `local-installer.ts` now includes `selectedAgents` in the `combinedConfig` object literal with the same dedup-union pattern already used for `domains`. Single-site 7-line addition; no writer changes.

E2E: `e2e/lifecycle/global-agent-propagation-type-consistency.e2e.test.ts` (1/1).
