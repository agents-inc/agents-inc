# Release 0.142.0 (2026-07-18)

Dual-scope skill/agent scope-toggle semantics are now correct end-to-end: collapse, the guarded `s` no-op on a persisted pair, and restore via `s` all behave consistently across skills and agents (D-233, D-227).

## Fixed

### D-233 — Spacebar on a dual-scope `[P][G]` skill/agent now collapses cleanly instead of leaving an orphan tombstone

Pressing spacebar on a persisted `[P][G]` row used to drop the active project entry but keep
the global tombstone behind, producing an unreachable orphan state. `applySkillRemoval` and the
agent-side `toggleAgent` action now recognize the dual-scope case (active project entry + global
tombstone) and drop both together, re-surfacing the skill/agent as a plain inherited-global
entry. Pressing spacebar again on that inherited-global row restores the full `[P][G]` pair.

### D-233 — `s` (scope-toggle) is a guarded no-op on a persisted dual-scope pair, not a silent corrupter

Repeatedly pressing `s` on a reopened `[P][G]` row used to have no well-defined single target
and could corrupt the pair (`[P][G] → [G] → [P]`, losing `[G]`). `toggleSkillScope` and
`toggleAgentScope` now detect a persisted dual-scope pair (the saved snapshot already carries the
tombstone) and no-op with a toast directing the user to spacebar instead. Within-session G↔P
round-trips (where the snapshot still holds an active global entry, not yet a tombstone) are
unaffected and continue to work via `s`. Restoring project scope from a plain inherited-global
row is done via `s`, exactly like any other globally-inherited item — not spacebar, which
remains a no-op there.

### D-233 Scenario C — Unresolvable skills no longer silently dropped on an authoritative edit

A skill the wizard couldn't resolve from the loaded source this session (wrong `--source`,
stale cache, upstream rename) is now tracked explicitly (`unresolvableSkillIds`) and exempted
from the authoritative-drop rule on `cc edit`, instead of being silently deselected because it
was absent from the wizard's result.

### D-227 — Dual-scope tombstone preservation on domain/stack preselection

`preselectAgentsFromDomains` and `preselectAgentsFromStack` now preserve an agent's excluded
global tombstone when re-deriving `agentConfigs` from a selected domain or stack, mirroring the
skill-side D-223 fix. Without this, re-picking a domain or stack could silently drop a dual-scope
agent's tombstone.

## Findings

- `.ai-docs/agent-findings/2026-07-17-d227-preselect-fix-not-e2e-reachable.md` — the D-227 fix
  above is unit-tested only; traced why no realistic CLI flow can exercise it end-to-end (the
  only functions that could hit the buggy branch never see a project config's dual-scope state).
- `.ai-docs/agent-findings/2026-07-18-authoritative-drop-silently-loses-unresolvable-skills.md`
  (resolved) — the Scenario C fix above.
- `.ai-docs/agent-findings/2026-07-18-d233-agent-collapse-fix-in-toggleagent-action-not-helper.md`
  — the collapse/restore guard lives in the `toggleAgent` action, not the `applyAgentToggle`
  helper; documents the layering so future changes look in the right place.
- `.ai-docs/agent-findings/2026-07-18-dual-scope-s-toggle-persisted-pair-doc-vs-code.md` —
  tightens `tombstone-pattern.md`'s "Undo Path" wording, which read as if `s` always collapses a
  persisted pair (it doesn't; supersedes an earlier, narrower finding on the same topic).
- `.ai-docs/agent-findings/2026-07-18-mergeconfigs-projects-drop-fixed-docs-stale.md` — confirmed
  the documented `mergeConfigs` "drops `projects` field" bug is already fixed; the reference doc
  describing it as active is now stale.
- `.ai-docs/agent-findings/2026-07-18-sourceById-collapse-unreachable-in-production.md` — a
  suspected latent bug (`buildCompileAgents`'s `sourceById` map collapsing dual-scope same-id
  skills to one source) is real code but unreachable in production: tombstones are filtered
  before compilation on every live path, and config ordering makes the fallback safe even without
  that filter.

## Backlog

- **D-227 same-scope duplicate** (`.ai-docs/agent-findings/2026-07-17-d227-same-scope-active-tombstone-duplicate.md`,
  low severity) — when the only saved entry for a name/id is a stale global tombstone with no
  active counterpart, re-preselection can emit a fresh active entry while also preserving the
  stale tombstone, producing a same-scope duplicate. Confirmed reachable only via directly-seeded
  store state, not any realistic CLI flow — unit-level coverage (`d227-same-scope-tombstone-duplicate.test.ts`)
  documents it as `it.fails`; remains open.

## Test coverage

Extensive new E2E coverage across the dual-scope skill/agent matrix: same-source (both plugin,
both eject) and mixed-source (plugin+eject in both directions) combinations, `[P][G]` badge
rendering for both skills and agents, the collapse/restore spacebar round-trip, the `s`-guard
behavior, global-side-only removal leaving a project's own copy untouched, and propagation edge
cases (`edit-global-remove-dual-scope-partial`, `scenario-b-edit-home-preserves-projects`,
`project-only-deselect-integrity`, `eject-skill-directory-cleanup`).
