# Release 0.142.1 (2026-07-18)

Housekeeping: two standards-gap findings from this cycle's work, plus formatting-only cleanup carried over from the prior releases.

## Changed

- `README.md` and `todo/TODO-completed.md` — formatting-only (table column widths, stray blank lines); no content changes.

## Findings

- `.ai-docs/agent-findings/2026-07-17-d167-task-id-recurrence-no-lint-guard.md` — CLAUDE.md's
  "no task IDs in test names/assertions" rule has recurred at least 5 more times since D-167 was
  first opened, because it's documented but not automated. Proposes an ESLint rule flagging
  task-ID-shaped substrings in `describe`/`it`/`expect` message arguments under `e2e/**/*.test.ts`.
- `.ai-docs/agent-findings/2026-07-17-e2e-helper-tests-have-no-runnable-home.md` — a `*.test.ts`
  file placed directly under `e2e/helpers/` never actually runs under either vitest project's
  include glob, silently producing orphaned "coverage." Already resolved in 0.142.0 by placing
  the extracted `config-comparison` helper under `src/cli/lib/__tests__/helpers/` (which does
  run) and re-exporting through `e2e/helpers/test-utils.ts`; this finding documents the pattern
  as the standard going forward.

## Proposed standards

- Add an ESLint `no-restricted-syntax` rule scoped to `e2e/**/*.test.ts` flagging `/\b(D-\d+|Gap \d+)\b/`-shaped
  string literals in `describe`/`it`/`expect` call positions (D-167 finding).
- Document that a tested E2E helper's implementation + test belongs under
  `src/cli/lib/__tests__/helpers/`, re-exported through `e2e/helpers/test-utils.ts` — not placed
  directly under `e2e/helpers/`, where a co-located test would never run (e2e-helper-runnable-home
  finding).
