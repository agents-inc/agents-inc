# Release 0.161.1 (2026-09-01)

The editor's address gains the path that reaches it, and the two assertions that were green on its absence now derive it (WWW-03)

**This release is one constant and the guards that failed to hold it.** `agentsinc.sh` stopped being the editor: the apex is the marketing site, `/docs` is the documentation, and the editor answers `agentsinc.sh/editor*`. The CLI hands that address to a browser from three commands, so all three would have opened the landing page — a working page, the wrong one, with the shared configuration silently dropped. Nothing would have reported it. What makes it worth a release note rather than a one-line diff is that **two separate assertions covered this exact value and both stayed green**, for the same underlying reason: each restated the expected string instead of deriving it.

## Changed

### WWW-03 — the editor's address carries the path that reaches it

`EDITOR_URL` becomes `https://agentsinc.sh/editor`, so `editorConfigUrl(id)` yields `https://agentsinc.sh/editor/?fromId=<id>` — the same link the editor's own Share button mints, which is the point of the two being one function rather than two string builders.

Three commands hand it out: `share` prints it, `edit --ui` opens it, and `init --ui` opens the bare form when there is no id. The `--ui` flag description on both `init` and `edit` said "Open agentsinc.sh instead of the wizard", which is now literally the wrong page, and both were re-derived from the source strings rather than edited to look right.

**The trailing slash before `?` is real.** `editorConfigUrl` interpolates `${EDITOR_URL}/?fromId=`, so anyone re-deriving this by hand and trimming the "redundant" slash writes a URL that does not match what the CLI produces.

## Fixed

### Two assertions that were green on the defect they existed to catch

`e2e/commands/init-ui.e2e.test.ts` asserted `toContain("agentsinc.sh")`. That is a substring of both the right address and the wrong one, so the spec passed whatever the constant held. It now reads `STEP_TEXT.EDITOR_URL`.

`src/cli/utils/open-url.test.ts` hardcoded `https://agentsinc.sh/?fromId=Ab3xY9_Q` beneath a docblock describing it as "a link of the shape the CLI actually hands a browser" — a claim that had quietly stopped being true. It now calls `editorConfigUrl`, so the claim and the code cannot come apart again.

Both were verified by reinstating the defect and watching them fail, rather than by observing that they pass.

## Added

### A fourth row in the mirrored-constants registry

`STEP_TEXT.EDITOR_URL` in `e2e/pages/constants.ts` is a hand-maintained mirror of `EDITOR_URL` — correctly a mirror rather than an import, since a rendering assertion that imports its own expectation asserts nothing. Nothing checked that the two agreed, which is why the mirror held the old value through the whole migration while the spec reading it stayed green.

`scripts/check-mirrored-constants.ts` already existed for exactly this class and carried three rows. It now carries four. Verified by drifting the mirror and watching the checker report it.

## Backlog

Two rows were filed by this work and ship no code here.

**WWW-16** — nothing binds a documented editor URL to `EDITOR_URL`. `check-cli-claims.ts` binds the command roster and every flag to the command sources in both directions and says nothing about addresses, so thirty references across twenty-one documentation pages went stale with every gate green. Three of them are quoted CLI output, which is a second claim shape: those must match `sharedConfigDestinations` and `configUnreadableError` byte for byte.

**REPO-41** — the deploy job failed on every push from 2026-08-30 while all four check jobs stayed green, so nothing reported that the editor, the site and the worker had stopped shipping. The cause was an Actions token predating the D1 database; that half is fixed and archived. What survives is that a deploy which never happens produces no signal at all.
