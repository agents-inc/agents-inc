# Release 0.174.0 (2026-10-24)

Every summary names a skill by the display name its install recorded, `init --from` and `edit --from` stop when a
marketplace refuses the version check, every command says an old `.claude-src/` is ignored, and the editor says when
an account's stacks could not be read, with Retry (REPO-44, REPO-45, CLI-931, CLI-946, CLI-947, CLI-948, CLI-949,
CLI-950, CLI-951, CLI-952, CLI-953, CLI-954, CLI-955, CLI-956, CLI-958, CLI-959, CLI-960, CLI-961, CLI-962, CLI-963,
CLI-964, CLI-965, CLI-966, CLI-967, CLI-968, CLI-969, CLI-971, CLI-973, CLI-974, CLI-975, CLI-976, CLI-977, CLI-978,
CLI-979, CLI-980, CLI-982, EDITOR-85, EDITOR-101, EDITOR-102, EDITOR-103, EDITOR-104, EDITOR-105, EDITOR-106,
EDITOR-107, EDITOR-108, EDITOR-109, EDITOR-110)

This release ships three known gaps, each pinned by a spec that fails while the defect is there. They are under
Backlog below. The one most likely to be met is CLI-979: when `edit --from` at home drops a skill whose plugin came
from another marketplace, the plugin stays installed.

## Added

### CLI-963 — a skill's display name, recorded at install

- **`init --from` and `edit --from` record each skill's display name in `config.ts`**, as `displayName` on its
  `skills` entry, between `origin` and `excluded`. The loader refuses an entry whose `displayName` is not a string and
  names where it sits.
- **Every summary names a skill by that record, then by the catalogue's name, then by its id**: the panel of
  `init --from` and `edit --from`, `edit --from`'s removal line, `uninstall`'s panel and `list`. A skill from a private
  marketplace or added in the editor keeps its name offline. `uninstall` reads no marketplace folder and no global copy
  before its panel.
- An installation made by 0.173.0 records no names, and shows what 0.173.0 showed.

### CLI-959 — `list` names skills by display name

- **`list` at a terminal shows each skill by the name its install recorded**, plugins included. It reads nothing from
  a copy's `metadata.yaml` or from a marketplace.

### CLI-978 — piped `list` names each skill

- **Over a pipe, `list` names each skill on its own line under the `Skills:` count, with its scope**, as the panel
  does: the recorded name, then the catalogue's, then the id. The path lines stay paths.

### EDITOR-103 — Retry on a stack that could not load

- **Clicking an account's saved stack with nothing unsaved, when its load fails, shows `Couldn't load this stack.` with
  one Retry under the grid.** It is read aloud and is not a dialog. The setup and its saved copy are unchanged. Retry
  that fails says so again; Retry that works applies the stack and clears the line.

### EDITOR-108 — Retry on an account list that could not be read

- **While a signed-in account's stack list cannot be read, a line above the grid says `Couldn't load your saved
stacks.` with one Retry.** The grid shows this browser's saves meanwhile, and nothing uploads until a read works. A
  Retry that works shows the account's stacks once; on a first sign-in it carries the saves in once.

## Changed

### CLI-931 — an old `.claude-src/` folder is named as ignored

- **Every command first prints, to stderr, one line for each place holding an old `.claude-src/`**, HOME first as `~`,
  then the project by its absolute path:
  `<root>/.claude-src/ is ignored; agents-inc reads <root>/.agents-inc/claude/. Delete the old folder once you have kept anything you need from it.`
  The old folder is never read or written, and the run is otherwise unchanged. The 0.173.0 notice that said to move it
  is gone.

### CLI-946 — a refused version check stops `init --from` and `edit --from`

- **When a marketplace answers the version check with 404 or 403, `init --from` and `edit --from` stop with exit 1** and
  the existing wording (`Repository not found:` or `Access denied to:`), `edit --from` before its plan. The saved copy,
  its record, HOME and the project are untouched.

### CLI-958 — which refusals stop, and which keep the saved copy

- **`init --from` and `edit --from` stop on every 4xx answer to the version check except 405.** On a 5xx or a 405 they
  keep the saved copy and warn once a run:
  `<source> refused the request (<status>) — using the cached copy, which may be out of date.` This holds for the
  CLI's saved copy and for giget's saved tarball.

### CLI-962 — the other loads keep the saved copy over a refusal

- **`compile`, `search`, `eject` and `uninstall` keep the saved marketplace copy when the version check is refused.**
  They warn once a run on a 5xx or a 405, as above, and say nothing on any other 4xx.

### CLI-960 — `uninstall`'s panel header names what it removes from

- **`uninstall`'s panel header names the marketplace of the skills it removes**, and no longer says
  `All skills ejected` when a plugin is among them. When it removes no skill, the header names the marketplace of the
  skills it keeps, or `All skills ejected` for copies, as 0.173.0 did. The panels of `init --from` and `edit --from` are
  unchanged.

### CLI-947 — the summary panel is drawn as plain boxes

- **The panel's scrolling code is gone**: `usePanelScroll`, `useMeasuredHeight`, `ScrollAffordance`,
  `SCROLL_VIEWPORT`, `SETTLE_TIMEOUT_MS` and their specs. A user sees no change: no scroll hint was ever printed, and
  the output is identical from 53 columns up. A new spec pins the printed panel whole on a terminal shorter than the
  output.

### REPO-44 — the standards and the findings

- The e2e standards, the journey page, the anti-patterns and assertions pages, `clean-code-standards.md` and
  `editor-and-worker.md` follow the code. The findings this cycle wrote are listed under Findings.

### REPO-45 — the git rule names its one exception

- **The root `CLAUDE.md` and the three statements of the rule in `packages/cli/CLAUDE.md` name a `commit-plan` skill
  run as the one exception to "no git command that writes"**: read-only until its plan is confirmed, writes only per
  that plan, push and publish only on a per-release confirm, never passed to a sub-agent. `packages/cli/CLAUDE.md`'s
  display-name rule names `list`.

### CLI-948 — a library that can answer from its own cache

- **`clean-code-standards.md` 15.19**: a library that can answer from its own cache is asked which it did, only an ok
  status counts as an answer, and an answer that cannot be compared downloads or refuses.

### CLI-949 — the preview crossing spec sets both sources

- **`preview-matches-install.spec.ts` gets a row setting both sources for the model**, held against the catalogue by
  `LINK_MODEL`'s type, which fails when the preview's order is flipped. The rule is in `apps/editor/e2e/README.md`.

### CLI-950 — doctor's row patterns are built once

- **`doctorRow(name, status, message)` in `e2e/pages/constants.ts` builds doctor's row patterns** from mirrored text,
  escaped, its status limited to the three marks. The ten doctor and lifecycle specs that wrote them as literals use
  it. `check-mirrored-constants.ts` holds the four new mirrors to doctor's source.

### CLI-951 — a spec that counts a rate limiter

- **`editor-and-worker.md`: a spec that counts a rate limiter stubs it**, and keeps two callers its key must separate
  and two it must merge. `apps/server/src/stacks.test.ts` gets the merge pair for the stack-save write limit: an editor
  request and a CLI request from one address share a count.

### CLI-952 — which saved configuration was read

- **`editor-and-worker.md` says to ask which saved configuration was read** (`savedConfigurationOnScreen()`, or
  `marketplaceOnScreen()` where an open link counts), never the stored marketplace choice.

### CLI-953 — the switch question's cost, with a restore waiting

- **`use-apply-stack-request.test.ts` covers the stack-switch question's cost with a restore waiting and with a shared
  link open**, each beside its allowed case.

### CLI-955 — the resize specs wait for the settled frame

- **The two resize specs wait for the settled frame with `vi.waitFor`** instead of reading it once after a fixed delay.
  `clean-code-standards.md` 6.5 says a frame set by an effect or a resize listener is awaited.

### CLI-956 — a spec's pattern matches only what it names

- **Every path, URL, id and mirrored text a spec puts into a pattern goes through one tested escaper,
  `matchedAsWritten`**, so it matches only itself. The old `127.0.0.1` pattern passed on `127x0x0x1`. 23 specs were
  converted, each shown red on a text change.

### CLI-961 — the fixtures name skills by their display names

- **The three test-fixture writers write each skill's real display name**, so 23 specs that pinned the id where the CLI
  prints a name now assert the name and fail when the product prints the id.

### CLI-974 — the `edit --from` plugin specs check what was left behind

- **Eleven `edit --from` plugin specs also check the project config's skills, the local copies, the global config
  beside the project and the exact calls to the mocked plugin host**, not only what the run printed.

### CLI-976 — three more spec files check what was left behind

- **`compile-says-what-it-did`, `init-from-plugins-says-what-it-did` and `init-from-says-what-it-did` check what each
  run left behind**: config entries, local copies, compiled sub-agents, `config-types.ts`, the mocked host's calls and
  untouched folders after a refusal.

### EDITOR-102 — a "nothing saved" test checks both halves

- **`editor-and-worker.md`: a "nothing saved" test checks that the state is the same object and that the slot took no
  write**, since each catches a mutant the other misses. The guard specs in `config-store.test.ts` and
  `saved-stack-store.test.ts` gained the missing check.

### EDITOR-109 — every store action is filed by what a second call does

- **`config-store.test.ts` holds a census of every store action**, each filed by what a second identical call does. A
  new action without a row fails at compile and at run time.

## Fixed

### CLI-954 — `uninstall` names what it keeps

- **`uninstall`'s panel shows the display name of a global copy a project uninstall keeps**, and of a plugin skill from
  a local marketplace folder, where it printed the id.

### CLI-965 — the old-folder line names Codex's folder

- **A root whose installation is Codex is told `agents-inc reads <root>/.agents-inc/codex/`**. It said Claude's folder
  by a literal.

### CLI-966 — giget's saved tarball, offline

- **With the marketplace unreachable and only giget's saved tarball left, every load but `doctor`'s prints
  `Could not reach <source> — using the cached copy, which may be out of date.`** once a run, as the saved-copy path and
  the docs already said.

### CLI-967 — a run given `--provider`

- **On a run given `--provider`, the old-folder line names that provider's folder**, on that very run.

### CLI-968 — a run inherits no earlier run's provider

- **A run no longer inherits the provider an earlier run in the same process named.** The `init` hook forgets it first.
  One process is one run in real use, so nothing changes there.

### CLI-969 — `list` under a HOME holding one installation

- **A bare `list` under a HOME holding one installation no longer prints
  `…holds 1 installations — codex — and this is the claude one`.** The line names the installation `list` shows and
  appears only where that scope holds both.

### CLI-973 — a sub-agent's gains and loses line

- **The line under `edit --from`'s panel naming what a sub-agent gains or loses names each skill as the panel does**:
  the recorded name, then the marketplace's, then the id. A withdrawn plugin showed its id, and a renamed one its new
  name.

### CLI-975 — `edit --from` asks the plugin host once

- **`edit --from` asks the plugin host once, not twice, when it switches a skill between a copy and a plugin and also
  moves it between project and global.** The scope-move step takes the planner's own move list, which also removes a
  project-uninstall of nothing and redundant file moves.

### CLI-977 — HOME's old-folder line follows the project's tool

- **On a run without `--provider`, HOME's old-folder line names HOME's folder for the project's tool**, so a Codex
  project under a Claude home is told `~/.agents-inc/codex/`.

### CLI-964 — the findings check in an exported tree

- **The findings-frontmatter check gives the same verdict in a clean `git archive` as in a checkout and in CI.** It asks
  git which paths are ignored through a throwaway empty git folder pointed at the tree, and stops with an error if git
  cannot answer. `prepublishOnly` no longer needs `handrun.gen.mjs` or the commit-plan skill copied in.

### CLI-980 — `generate:types:check` without the skills checkout

- **Without the skills checkout beside the repository, `generate:types:check` stops with one line** naming the folder
  it looked in and how to pass another (`bun run generate:types:check <path>`), exit 1, instead of a stack trace.

### EDITOR-101 — pressing the option already in effect

- **Pressing the skill option already in effect saves nothing and sends no `skill_configured` event**, on the cell or
  in its ••• panel, selected or not.

### EDITOR-104 — a saved stack the grid's first read missed

- **A click and its Retry read the account's stack through the account store**, which also lights the tile of a stack
  whose first background read had failed and stops a false "discarding 1 selected skill".

### EDITOR-105 — applying a stack already in effect

- **Applying a stack or a saved stack already in effect changes nothing**: no save and no `stack_applied`. A real
  change saves once and reports.

### EDITOR-106 — a list that could not be read is not an empty account

- **A failed read of the account's stack list no longer counts as an empty account**, so a failed load no longer
  carries every browser save in again. Browser saves are adopted only after a read that succeeded.

### EDITOR-107 — "already in effect" by value

- **Whether a stack is already in effect is judged by value, whatever the key order**, and the switch question shows
  the grid's one `Couldn't load this stack.`

### EDITOR-110 — the keyboard after a Retry that works

- **A Retry that works no longer drops keyboard focus to the page**: on `Couldn't load this stack.` it lands on the stack
  it loaded, and on `Couldn't load your saved stacks.` on the Stacks grid itself, which is not a Tab stop. A failing
  Retry keeps focus, and a dialog the read opened keeps it.

### EDITOR-85 — where the keyboard goes

- **Closing the owed-save dialog lands keyboard focus on the Stacks grid**, never a cell and never the page. **Escape
  inside a skill's options panel puts focus back on that skill's `•••`**, and **Apply on a composer proposal puts it in
  the composer field**, as Discard does. The owner chose to leave the remaining three cases as they are.

## Removed

- The panel's scrolling code (CLI-947) and the startup notice that told a user to move an old `.claude-src/` (CLI-931).

## Backlog

Known gaps this release ships. Each is pinned by a spec marked as expected to fail, which turns red once the fix lands.

### CLI-979 — known gap: `edit --from` at home leaves another marketplace's plugin installed

- **When `edit --from` at home drops a skill whose plugin came from another marketplace, the plugin stays installed and
  enabled**, though the run prints `✓ Done` and the docs promise removal. Reproduced with the real `claude`: a global
  installation made from one marketplace, then a project made from a second that leaves a skill at global scope. The
  CLI asks Claude Code to remove the plugin under the global installation's marketplace name; Claude Code answers that
  it is not installed, and the CLI ignores that. The fix is waiting on the owner's card `q-cli-979-fix`. Pinned by
  `e2e/lifecycle/edit-from-at-home-drops-a-global-plugin-from-another-marketplace`.

### CLI-971 — known gap: a project config that declares nothing

- **A project whose `config.ts` declares nothing, under a HOME holding a Claude and a Codex installation, is counted as
  an installation by the refusal and by `list`'s line, while the commands skip it.** `compile` rewrites the Claude
  installation and `edit --from` applies to it, and `share` and `edit` say no installation exists. The owner ruled
  "Never count it, and say so"; the fix is queued. Pinned by
  `e2e/lifecycle/a-folder-whose-config-declares-nothing-under-a-home-holding-both`.

### CLI-982 — known gap: `init --from` that cannot write the project's config

- **When `init --from` cannot write the project's `config.ts` (for example, EACCES), it has already copied the skill and
  registered the project in the home config**, leaving a half-install with no `config.ts`. Waiting on the owner's card
  `q-cli-init-half-install`. Pinned in `init-from-says-what-it-did.test.ts`.

Filed this cycle and not in this release: CLI-957 (reading a marketplace folder's catalogue replaces the loaded one
for later display names), CLI-970 (`list` says `Agents: 0` for a Codex installation; parked), CLI-972 (one
`edit --from` block names a skill two ways), CLI-981 (test follow-ups), CLI-983 (`init-from-says-what-it-did` runs
without a plugin-host mock), EDITOR-111, EDITOR-112, EDITOR-113, SERVER-10 and SERVER-11. Each is a row in
`todo/cli.md`, `todo/editor.md` or `todo/server.md`.
