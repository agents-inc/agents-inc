# Release 0.170.0 (2026-10-17)

The wizard's removal is finished: a stack installs every sub-agent it declares, `edit --from` names what it adds to
the global install, and a global run says each warning once (CLI-926, CLI-927, CLI-928, CLI-929)

**Before you upgrade.** A bare `edit` now exits 1, before it mints an id, when an installed ejected skill's
`metadata.yaml` describes no skill. `build marketplace` writes nothing when it fails.

## Fixed

### CLI-926 — finishing the wizard removal

- **A stack picked in the editor installs every sub-agent it declares.** A sub-agent the stack gives no skills
  (`cli-tester` in CLI Tool and the Next.js stacks) was named by no assignment, so the payload installed one sub-agent
  fewer. Applying a stack now pins each such sub-agent on.
- **`edit --from` and `init --from` from a project name the global sub-agents they add to.** A held global sub-agent
  that an arriving skill joins was listed as "Kept as installed". It is now listed under
  `Added to sub-agents in the global install — each keeps everything it already has, since a project run only adds to the global install:`,
  one `sub-agent <name>: + <skill ids>` line each. `edit`'s Changes block lists it as `~ <name> [G] (agent: skills added)`.
- **A bare `edit` refuses unusable skill metadata before minting.** An installed ejected skill whose `metadata.yaml`
  describes no skill stops the run before an id is made:
  `The editor opens on what these files describe, so no link is made until each one describes its skill.` Both halves
  of a skill installed at both scopes are read.
- **`eject skills` copies into the installation's own skills folder.** It wrote `.claude/skills` whatever the
  provider. A Codex installation now gets `<repo>/.agents/skills`, or `$CODEX_HOME/skills` at global scope.
- **`build marketplace` reads and refuses before its first write.** Over a marketplace-repo config module that would
  not load, it wrote `marketplace.json` and then failed. A failed build now leaves `marketplace.json` and
  `catalog.json` as they were.
- **A global run says each warning once.** It printed each marketplace warning 1 + 2N times for N registered projects.
  Catalogue loads and global-skill scans now say each warning once per run. `doctor` no longer says each `[matrix]`
  health finding twice.
- **The editor's Install dialog names the rate limit.** The 21st open in a minute read `id unavailable`. It now reads
  `rate limit reached — try again in 1 minute`. The worker's 429 on `POST /configs` carries `Retry-After` and exposes
  it to the browser, and `@workspace/api` reads it.
- **Wording that described the wizard:**
  - `edit`'s summary is `Open this installation in the editor, or apply a configuration with --from` (was
    `Edit skills in the plugin`);
  - an unreadable config's remedy is to fix the file, or `uninstall` then `init --from <id>` with an id from the
    editor (a bare `init` no longer installs anything);
  - a marketplace repository's own unreadable config says it is fixed in that repository;
  - `search`'s help says to add a skill in the editor to install it.
- **Docs.** Every page of the site describes one way to make each change, with no wizard. The "Three ways in" page is
  "Ways in", and project-scope plugins are described as registered in `~/.claude/plugins/`. The landing page's
  recording slot reads "Video coming soon". The README walks the editor route and keeps the wizard's recording as the
  Legacy Wizard (`npx agents-inc@0.168.0 init`). The `CLAUDE.md` files, the READMEs, the architecture overview and the
  standards stop citing removed code. The standards rules cut since 551c9164 that were not about deleted code are
  restored.
- **The codex-keeper sub-agent's playbook** no longer says a completion gate runs the typecheck.
- **Test harness.** Seven specs that drive no terminal moved from `e2e/interactive/` to `commands/` and `lifecycle/`.
  The worker's typed-client tests cover saving a stack and composing a proposal.

### CLI-927 — the TMPDIR-length specs

- **Six e2e specs pass at any temp-folder length** (9 to 150 characters). Paths are compared through
  `compactCliOutput`, `config.ts` is read with `loadConfigOrFail`, and goldens are compared after
  `formatInstalledConfigs`. The dead `"projects"` filter in `config-comparison.ts` is gone. The product is unchanged.

### CLI-929 — current skill wording

- **The `composable-components` rule's reason and the `meta-reviewing-web-reviewing` audit quote describe the current
  skills.** Both generated `matrix.ts` files were regenerated from the published skills commit.

## Changed

### CLI-928 — the prompt bible, re-validated for Opus 5.5

- **`prompt-bible.md` targets Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1.** `<thinking>` is gone from the
  recommended tag names, because Opus 5.5 may decline a prompt that asks it to write out its reasoning. `xhigh` effort
  is kept for work where it has measured better. "Thinking is always on" replaces "Extended thinking is enabled by
  default".

## Removed

- **`edit`'s record of a project-context switch of a global skill** (`recordGlobalSourceMigrations`) and the gate's
  `migrate-skill-sources` mutation. Since 2026-10-04 a project run leaves global skills as installed, so it changed
  nothing. (CLI-926)
- **The wizard's leftover code:** `matrix-resolver.ts`, `findStack`, `isDomain` (CLI and `@workspace/matrix`'s
  index), `isSameMarketplace`, the exported `skillSlotKey` / `agentSlotKey`, and the `OptionState` and `SkillOption`
  types. `writeScopedFromWizard` is now `writeConfigByScope`. (CLI-926)
- **`assets/demo.tape`.** `assets/demo.gif` is now `assets/legacy-wizard.gif`. (CLI-926)
