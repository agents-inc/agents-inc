# Release 0.166.0 (2026-10-04)

From a project, `share`, `edit --ui` and every `--from` now treat the global install as one every project reads, every write refuses a broken `config.ts` by name, and the audit that followed the journey fixes is applied (CLI-868, CLI-902)

**What this release is.** CLI-902 is the 14 non-Codex failures from the 2026-10-01 manual journey run on 0.165.0, each fixed the way the owner ruled it. After it landed, every suite was run unfiltered and every non-Codex user journey was driven by hand again, in six audit rounds. Every failure those rounds found was given a test that failed first, then fixed. The audit issues have no tracker rows, so this file cites them as "audit issue N". Failures that only the terminal wizard showed were dropped, because the wizard is being removed.

## Added

### Every `--from` says what goes where, and asks

- **`init --from` and `edit --from` list, before writing anything, what goes into this project and what into the global install**, under `Into this project:` and `Into the global install:`. In a project, `init --from` adds a third list, `Skipped, already in the global install:`, for global skills the global install above the project already holds; each is left as installed.
- **`init --from` then asks `Install this configuration?`** `edit --from` already asked before applying, so its lists join that question. At the home directory the run is the global install, so only the second list can have anything in it.
- **With no terminal, `init --from` prints the lists and carries on** (owner ruling, 2026-10-02). Elsewhere, `edit --from` run where nothing is installed is refused with or without a terminal, and the refusal names `init --from <id>` rather than a route that would refuse in turn (audit issue 19).
- **`init --from` in a project no longer refuses because a global install exists.** It adds to the global install what it lacks and leaves the rest as installed. A directory with its own installation is still refused, naming `uninstall` and, now, `edit --from <id>`.
- **`init --from` and `edit --from` print the marketplace's load warnings**, as the other commands do.

### `share` says what its id cannot carry

- When the marketplace it names is a folder on this machine, `share` says the id installs only where that folder exists.
- When what it sends comes from more than one marketplace, it names the skills that will not install elsewhere, since a payload names one marketplace. CLI-903 makes such a share whole.

### A skill whose `SKILL.md` frontmatter does not parse is named

It was skipped without a word by every command except `doctor`. It is now skipped with a warning naming the file and the parser's reason: `Skipping '<dir>/SKILL.md': unparseable SKILL.md frontmatter at <path> — <reason>`.

### `bun run dev` brings a local worker in line with production

`apps/server`'s `bun run dev` is now `bun scripts/dev.ts`. Before starting `wrangler dev` it applies the local D1 migrations, and it builds the skill index the way `.github/workflows/build-skill-index.yml` does whenever the local store holds none or one older than three days. Without these, a local worker failed every sign-in and answered 503 to the editor's Add skill search. The crawl stops after 30 seconds. Neither step stops the worker from starting: a failure is said in one line, and the worker starts over whatever the store holds. `--persist-to` reaches both steps, and `--remote` skips them. `apps/server` gains a `test:e2e` suite that drives it.

## Changed

### From a project, `--from` only adds to the global install

The global install is one installation that every project on the machine reads, so a run started in one project is not a decision about the rest (owner ruling, 2026-10-02).

- **From a project, `--from` never removes or changes a global entry.** An id with no global entries used to empty the global install, and an id with some removed the global skills it lacked. A global skill or sub-agent that the configuration states differently, or leaves out, now stays as installed, and the run names it under `Kept as installed in the global install`. That includes a carried skill whose global copy differs from the configuration's (audit issues 82 and 83).
- **A project run adds nothing global except its registration**: a project-only `edit` no longer writes `marketplaceName` into the global `config.ts` (audit issue 2).
- **The dropped project copy is disclosed.** Where the configuration leaves out the project half of a `[P][G]` pair, the plan lists `<skill>: this project's copy is removed; the global one takes over` among the removals. It used to say `Nothing is removed` while deleting it (audit issue 78).
- **A kept skill joins the configuration's row** instead of overwriting it, where a destructive apply keeps a hand-written skill in the same category on the same sub-agent (audit issue 80). In a category that holds one skill, the configuration's skill takes the slot. The kept skill stays installed, unassigned there, with one plan line: `<skill>: kept, no longer assigned to <agent>'s <category>` (audit issue 90).
- **Refusals come before the question.** A hand-written folder at a carried skill's id, a configuration with nothing installable, the two Codex `--from` refusals, a stack the config writer would refuse, and a `stackId` the marketplace does not ship are all refused before `Install/Apply this configuration?` and before anything is written. The unshipped stack used to be refused only after installing, which left a half-finished install (audit issues 1, 81 and 90).

### `share` refuses ejected skills

A share carries plugins only (owner ruling, 2026-10-02). `share` refuses an installation holding ejected skills, editor-added skills included, listing each under `This installation holds ejected skills, and ejected skills cannot be shared:`. `edit --ui` still opens the same installation in the editor. `share` also gains the two-source-folder check the write commands have.

### `init --marketplace` takes the bare-init route

- **`init --marketplace Y` works the same as a bare `init`** (owner ruling, journey 26). In a project with no installation of its own under a global install, that is the dashboard, whose Edit sets the project up from Y, with the global's sub-agents and skills shown locked. Since 0.133.0, `init` there opened the global install's dashboard and nothing read the flag.
- **Where the folder's own installation came from another marketplace, it refuses** (exit 2), saying an installation's marketplace is chosen once, when it is made.
- **`init --ui --marketplace` refuses**, because the editor's address carries a configuration id and nothing else. The refusal names `init --ui`, which runs in every folder (audit issue 84). CLI-905 makes the pair work.

### A custom marketplace needs a valid `marketplace.json`, and four names are reserved

- **A marketplace other than the default one must publish a valid `.claude-plugin/marketplace.json`.** One without it is refused as `not a marketplace yet`, and one whose manifest does not parse or fails the schema is refused with the reader's reason. Both refusals name `build plugins` then `build marketplace`. An unbuilt folder used to install in Local mode labelled "Agents Inc".
- **`eject` is reserved beside `agents-inc`, `external` and `local`.** A marketplace named `eject` turned every plugin install into a silent local copy, because `eject` is the `origin` an installation records for a copied skill (audit issue 18). `build marketplace` and `new marketplace` refuse all four names.
- **The loader refuses `eject`, `local` and `external` too**, by manifest name and by the `marketplaceName` an installation recorded, which used to outrank the manifest. `agents-inc` stays loadable as the public catalogue's own name (audit issues 25 and 26). A refusal over a recorded name says to correct the recorded name or set the installation up again, not to rename a manifest that is fine (audit issue 45).
- `build marketplace`'s namespace refusal now says to rename the `name` in each skill's `SKILL.md` (audit issue 6). `new marketplace`'s reserved-name refusal names `new marketplace <other-name>`, the one way out it has (audit issue 7).

### A broken `config.ts` is refused by every write

- **`compile`, `edit`, `eject`, `init`, `share` and `update`, and `list` and `search` with them, refuse when any config this folder uses, the project's or the global one, exists and cannot be loaded.** An empty or invalid `config.ts` used to read as absent to `search` and `eject`.
- **The refusal names whose config it is, the file and the reason**, and says to run `uninstall` and then `init` from that config's own folder. It also names the editor and `doctor`. It names every broken config, not only the first.
- **A bare `agents-inc` over a broken config refuses the same way**, where it used to print help (audit issue 58).
- **`uninstall` always works on one**: it warns that plugins and compiled agents the config lists may be left behind, then removes what it can.
- **`doctor` reports and finishes**, adding a tip with the same way out.

### `uninstall` and `doctor`

- **`uninstall` removes both `.claude-src/` and `.agents-inc/claude/` in one run** and never refuses over two folders. Files you made yourself stay. `list` used to report the leftover folder as an installation until a second `uninstall`. `uninstall` also skips the terminal-size wait.
- **`doctor`'s Config Valid row names the config it read.** A project with no `config.ts` under a global install reads `This project: no config.ts, using the global installation's (~/…/config.ts)`, rather than the global file under the project's path.
- **`doctor` counts only the skills the reached marketplace carries**, not the global install's ejected skills (audit issue 85).

### Commands that need a terminal refuse cleanly

- **`init` and `edit` refuse to open the wizard without a terminal**, naming what runs without one (`init --from <id>`, `edit --ui`). A bare `init` in CI used to die on Ink's raw-mode error over a React stack trace.
- **`uninstall` without a terminal refuses and names `--yes`**, so a confirm nobody can answer never becomes a yes.

### `update` says what it refreshed

`update` refreshes each marketplace's listing, and the installed plugins keep their version. It now prints, for example, `Refreshed 2 marketplace listings. Installed plugins were not changed.` rather than `Update complete! 2 marketplaces refreshed`. The docs site's quickstart said `update` pulls newer skill content, and now says what it does (audit issues 61 and 86). Whether `update` should also update installed plugins is CLI-918.

### The editor's build and test harness

- **The editor's Playwright suite runs on its own port**, 5199 (`EDITOR_E2E_PORT` moves it), with `--strictPort` and `reuseExistingServer: false`. On 5173 it reused whatever server answered there, so a run in one tree could test another and report green (audit issue 35). The axe audits get 90 seconds.
- **Vite's modulepreload polyfill is off, and the first-paint budget is 352 KiB** (was 344), the owner's choice of 2026-10-03 when the preview's descriptions put first paint 95 B over. Browsers without native `modulepreload` (Safari before 17, Firefox before 115) still load every chunk, without preloading.

## Fixed

### CLI-902 — the 2026-10-01 manual journey run's 14 non-Codex failures

- **`share` and `edit --ui` from a project carry the global sub-agents' skills.** The installation payload read only the project `config.ts`, so global sub-agents went out with no skills. The same provider's global stack rows are now laid under the project's: the project wins, and masked `[P][G]` rows are skipped. A project now mints the same id as the home directory, and journey 29 rebuilds all 8 sub-agents byte-identical. `edit --from` from a project keeps the global sub-agents' skill rows for the same reason.
- **Dropping the project half of a `[P][G]` pair writes nothing global.** It deletes the project copy, Plugin or Local, at project scope. It used to copy the project folder over `~/.claude/skills/<id>`, which broke in 0.142.2.
- **False warnings are gone.** Two marketplaces may ship skills sharing a short name, and `Duplicate slug … ignoring …` no longer fires across them; both skills work. A clash inside one marketplace is still named. `Skill '<id>' is assigned to no sub-agent` no longer fires for a skill a global sub-agent loads.
- **`config.ts` rewrites keep `branding`**, and keep it off the global half, along with the five layout fields (`skillsDir`, `agentsDir`, `stacksFile`, `categoriesFile`, `rulesFile`) in the file that carried them. `ProjectConfig` declares them.
- **`edit` prints the Claude trust line** that `init` and `compile` print, at both of its endings that write.
- **The startup band no longer contradicts itself.** Stack ids are read straight from the stack's assignments, so the per-skill "may be a custom or local skill" line, which also appeared in `compile`, is gone. The stack-level sentence from 0.159.0 stays.
- **The editor's output preview matches the install.** It shows each skill's `SKILL.md` description, from a generated table that loads only with the preview (`@workspace/matrix` exports it, and the source-types generator writes it). It also draws the CLI's own file set, through the blank-pair merge, carried-skill rendering and global-config merge, which move into `@workspace/compile` so the preview and the CLI share them. Both `config.ts` files carry the `marketplaceName` line `init --from` writes (audit issue 8). The order of skills was ruled not a bug.

### Audit fixes — terminal, dashboard and trust

- **Raw mode is held before the first paint.** Ink took raw mode only after its first frame, so an Enter pressed in between was echoed, scrolled the full-height frame up a line, and was lost. Each prompt now sets raw mode before rendering and restores it afterwards (audit issue 22).
- **Ctrl+C on the dashboard exits as cancelled** (exit 4), as every other prompt does. It exited 0 (audit issue 29).
- **The bare `agents-inc` dashboard no longer prints the help listing** after Escape or a chosen command. oclif swallowed the hook's exit 0 and fell through to the root help (audit issue 38).
- **Keys in one burst act on the focus they reach.** Down Down Enter on the dashboard opened Edit, not Doctor, and a fast Right Space in the grids toggled the cell before the move. Focus is now read at key time (audit issues 28 and 37).
- **The Claude trust check follows git roots and `CLAUDE_CONFIG_DIR`.** Claude Code records trust under the folder's git repository root (the main checkout's root for a linked worktree), and the check read the exact project folder, so a project below a repo root was told it was untrusted forever (audit issue 62). Below a trusted plain folder Claude Code never shows the prompt, so the line now says to set `hasTrustDialogAccepted` in the state file rather than to accept a prompt (audit issue 63). The state file is `$CLAUDE_CONFIG_DIR/.claude.json` while that variable names a directory (audit issue 87). A global install still writes to `~/.claude/` under it, which is CLI-914.

### Audit fixes — what the CLI prints

- **Skipped registered projects get bare lines**: `Skipped <path>: its config.ts can't be read.`, `… nothing is installed there any more.`, `… it is another provider's installation.` and `… updating it failed.`. A global `edit` used to skip a broken project silently, and a global `compile` warned in `uninstall`'s wording (audit issues 59, 60 and 89).
- **Counts are singular for one**: in the install report, `eject`, `build plugins`, `build marketplace`, `compile`'s `Discovered N skills` and per-scope recompile lines, `doctor`'s ratios, and `N agents are global-scoped` (audit issues 20, 27 and 57).
- **The install report names the right folder.** From a project, a global install's skills line named `.claude/skills/` though they went to the home directory's (audit issue 20).
- **`init --from` no longer prints `No agents found to recompile`** right after compiling, when one sub-agent failed (audit issue 3).
- **A refused `compile` writes nothing**: it no longer refreshes `config-types.ts` before exiting 1 (audit issue 4).
- **The `--ui` hints follow the folder.** `edit --ui --from` in a folder with no installation names `init --from`, and `init --ui` over an existing installation names `edit --from` (audit issue 5).
- **Re-applying an id whose carried skill changed** reports the change and recompiles the sub-agent. It used to rewrite the skill, print `No changes made` and never recompile (audit issue 66). A destructive `edit --from` keeps a sub-agent the id names whose only skill cannot be placed (audit issue 67).
- **A carried skill keeps its full description.** Its `metadata.yaml` no longer gets the whole description as `cliDescription`, which made `doctor` warn on almost every editor-added skill (audit issue 69), and a re-share reads the description from `SKILL.md`, so `edit --ui` no longer truncates it (audit issue 79).
- The removal plan's items are indented under their headings (audit issue 88).

### Audit fixes — the editor

- **Signed out, the composer sends nothing** and says so. It used to send `POST /compose`, get a 401, and then say "nothing was sent". A session that ends while the tab is open now reads `Your session ended. Sign in again — nothing changed.` (audit issue 9).
- **Keyboard focus stays clear of the docked composer and the sticky filter bar**, tabbing forwards and backwards (audit issues 13 and 21). A lattice cell's focus ring is drawn inset, so tabbing onto a skill cell shows one (audit issue 23). An open options panel near the bottom no longer lifts the app or draws below the composer (audit issue 24).
- **The Add skill and Marketplace dialogs return focus** to the button that opened them (audit issue 14).
- **The EDITOR nav link stays active** when the URL carries `?q=`, `?domain=` or `?sel=` (audit issue 15).
- The options panel's disabled `need project scope` label is padded and fits its button (audit issue 16). The install dialog's footer keeps `npx agents-inc edit` on one line (audit issue 17), and names each scope's own folder for ejected skills, `~/.claude/skills/` for global ones (audit issue 20).

### CLI-868 — a dated plan in `todo/plans/` resolves as a plan, not a missing finding

`check-finding-citations` reads every name under `todo/plans/`, at any depth, as resolvable, so a tracker linking a dated plan no longer reads as a dangling finding. A dated name found nowhere still dangles, and a control test pins that. With it, `compile.test.ts`'s "a failed matrix seat" case flattens wrapped oclif output, so it no longer depends on TMPDIR's length. The CLI unit suite is green with the default TMPDIR and with a 90-character one.

## Removed

- **`warn()`'s `suppressInTest` option.** The stack warning it existed for is gone, and so is `e2e/commands/warn-suppression-stops-at-the-harness.e2e.test.ts`, whose only subject was that warning.
- **`update`'s claim that refreshed content lands without recompiling**, from its command description, because a listing refresh changes no installed plugin.
