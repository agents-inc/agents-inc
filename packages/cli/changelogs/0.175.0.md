# Release 0.175.0 (2026-10-27)

A project config that declares nothing is no longer an installation, a project under a home holding both tools reads
only its own tool's global installation, `init --from` and `edit --from` refuse two more broken links before they ask,
and an account refuses a second stack under a name it already holds (REPO-44, REPO-42, REPO-46, REPO-47, REPO-48,
CLI-930, CLI-933, CLI-934, CLI-935, CLI-936, CLI-938, CLI-939, CLI-940, CLI-941, CLI-942, CLI-957, CLI-971, CLI-972,
CLI-981, CLI-983, CLI-984, CLI-985, CLI-986, CLI-987, CLI-988, CLI-989, CLI-990, EDITOR-98, EDITOR-99, EDITOR-100,
EDITOR-111, EDITOR-112, EDITOR-113, EDITOR-114, EDITOR-115, SERVER-07, SERVER-09, SERVER-10, SERVER-11, SERVER-12,
WWW-17)

## Added

### SERVER-10 — an account holds each stack name once

- **The worker refuses a stack save or rename under a name the account already holds, from any caller**, with a 409
  and `{"error":"name taken"}`. Names are compared as the editor's Save compares them: trimmed, in any case, accented
  letters included. Another person's stack of the same name, a rename of a stack to its own name in another case, and
  a name freed by a delete all still work. Two saves sent together leave one stack.
- A name holding half of a surrogate pair is refused with a 400. An account that already holds such a name can still
  save.

### EDITOR-111 — Save waits for the account's stacks

- **While the signed-in account's stack list cannot be read, Save stores and sends nothing.** The dialog stays open
  with the typed name, says `Saving needs your account's stacks first.` and offers Retry. Once the list loads, a name
  the account holds is refused in place on the field, and the worker's "name taken" answer is refused the same way.

### EDITOR-112 — a failed stack-list read reaches error monitoring

- **A failed read of the account's stack list is reported to error monitoring**, as the editor's other reads are: a
  refused read with its status, an unreadable list and an unreachable worker each as their own kind. What the person
  sees is unchanged: `Couldn't load your saved stacks.` with Retry.

### WWW-17 — new-tab links are checked

- **The site's tests fail when a built link that opens a new tab lacks `rel="noopener noreferrer"`.** The check runs
  first in the site's test script and refuses an empty or missing build.

### REPO-42 — the pre-push hook has a spec

- **A spec runs the real `.husky/pre-push` with stand-ins for `git`, `bun` and `bunx`** and checks which suites run,
  in what order, for 18 kinds of push, and that a failing suite blocks the push. It fails if the hook stops running a
  suite it must, including merging the CLI's unit and end-to-end runs back into one call.

## Changed

### CLI-934 — a skill that could not load is named as one

- **A skill the marketplace ships and could not load is reported as `Skipped N skill(s) this catalog could not
load: …`**, apart from the skills it does not know at all, each with the sub-agents installed without it.
- **A skill folder with no `SKILL.md` is warned on every load**, not only under `--verbose`.

### CLI-972 — the notices under the `--from` panel name skills as the panel does

- **The five notices under the `init --from` and `edit --from` summary box name each skill the way the box does**: by
  the name its install recorded, then the catalogue's, then its id — `skill My House Style`, `+ Vitest`. They printed
  ids before.

### CLI-939 — the docs say when a saved marketplace copy is checked

- **The command reference, the CI recipe, the troubleshooting page and the private-marketplace recipe now say that a
  saved marketplace copy with no version stamp is never checked again, except by `doctor`**, and how to refresh it:
  run `doctor` while online, or delete its `.etag.json`. The promise that every load revalidates is gone. The CLI's
  behaviour is unchanged.

### SERVER-11 — a sign-in lasts 90 days, renewed on use

- **An editor sign-in lasts 90 days, and a use more than a day after its last renewal starts a fresh 90 days.**

### EDITOR-113 — a sign-in that ends mid-read

- **A sign-in that ends between the editor's check and its read of the stack list is treated as a list it could not
  read**: nothing is uploaded again, nothing is marked as still owed, and the grid shows `Couldn't load your saved
stacks.` with Retry.

### EDITOR-98 — the Switch marketplace refusal

- **The Switch marketplace dialog's refusal reads as two sentences**, the cause and then `Nothing has changed.`, and
  offers "load it from Marketplace to try a token" only when GitHub answered 401, 403 or 404 — not when it was
  unreachable, failed, or served a catalogue it could not read.

### CLI-941 — doctor's config verdicts

- `doctor`'s config check handles each state of the config by name, so a new state cannot pass for a loaded config.
  Every verdict, detail line and exit code is pinned and unchanged; a user sees no change.

### REPO-46 — CI's Node setup

- CI's seven Node setup steps use `actions/setup-node@v7`, which runs on Node 24. The installed toolchain is
  unchanged.

### REPO-47 — one rule for stack names

- How two stack names compare has one definition in `@workspace/matrix`, used by the editor's Save, the worker and
  the shared mock.

### REPO-48 — the CLI's cached test run

- A change to a file outside `packages/cli` that a CLI spec reads — the pre-push hook, the CI workflow, the root
  `package.json` and `README.md`, `docs/`, each workspace's `package.json`, `tsconfig*`, `vitest.config.*` and
  `eslint.config.*` — now reruns the CLI's tests instead of replaying a cached pass.

### REPO-44 — the standards, the journey page and the findings

- The e2e standards and the journey page follow the code, and the root `CLAUDE.md` says to compact a session at 200k
  context used. The findings this cycle wrote are listed under Findings.

### CLI-940 — the e2e config writer takes an inlined global

- The e2e helper `writeProjectConfig` accepts a project config carrying its global config inline, splitting the
  global part off as the CLI does. The import-and-copy form it could never accept is gone.

### CLI-981 — the `edit --from` plugin-switch specs pin exact calls

- The specs that switch a skill between plugin and copy pin every call to the plugin host, so a second install fails
  them. The old-folder end-to-end specs share one writer.

### CLI-983 — `init --from`'s specs never reach the real `claude`

- `init --from`'s specs run behind a logging stand-in for `claude`. A new spec pins the calls made when nothing is held.

### CLI-989 — no spec reaches the developer's `claude`

- `uninstall`'s and `init --from`'s specs assert only what changes Claude's setup, through the same stand-in. An
  `uninstall` run made 18 calls to the developer's real `claude` before, and makes none now.

### CLI-986 — a command spec's first Ink render

- A command spec pinning stderr no longer fails its first attempt when it is the first Ink render in its test worker.
  The test's request guard lets yoga's built-in `data:` URL through; every other unexpected request is still refused.

### CLI-990 — `list` under a home holding both tools

- `list`'s count and agents folder, and the startup config check, are pinned for a Codex project under a home holding
  both tools' global installations, beside Claude controls.

### SERVER-09 — the server dev spec stands alone

- The server dev spec's "asks GitHub for nothing" check hands `wrangler` an empty config folder inside the run's
  scratch, so it no longer depends on the developer's `wrangler` cache.

### SERVER-12 — the id-hashing spec finds its own id

- The worker's id-hashing spec searches for a qualifying stack id at run time, so a share-link version bump no longer
  needs a hand-searched id.

### EDITOR-99 — the accounts specs are reliable

- The editor's flaky `accounts.spec.ts` specs pass reliably. The end-to-end dev server runs without live reload, so a
  file saved during a run no longer reaches a page a spec is driving.

### EDITOR-115 — the rail's refusal lines are pinned

- A spec group pins, word for word, the six sign-in and sign-out refusal lines the editor's rail shows, and the line
  clearing after a sign-out goes through.

## Fixed

### CLI-971 — a project config that declares nothing is not an installation

- **A project `config.ts` that declares no skill and no sub-agent is never counted as an installation.** `compile`,
  `edit`, `list`, `share`, `update` and `doctor` print `This project's config declares nothing, so this works on your
global installation.` to stderr, then work on the global installation. `uninstall` in such a project changes nothing
  and leaves the file as yours.
- `doctor`'s config row names the file that declares nothing before the global config it uses.
- A run from home that reaches each registered project warns by name of one whose config declares nothing and leaves
  it as it is.
- The per-command wording waits on an owner answer; see Backlog.

### CLI-984 — a project inherits only its own tool's global installation

- **A Codex project under a home holding both a Claude and a Codex global installation reads only the Codex one**:
  `compile`, `edit --from`, skill discovery, the global compile pass, the config checks, `list` and `doctor`. Before,
  those reads took Claude's.

### CLI-933 — `eject --force` restores what an earlier eject wrote

- **`eject skills --force` and `eject all --force` restore every skill an earlier eject wrote**: an edited `SKILL.md`
  comes back as the marketplace ships it, and the success line counts every skill. Without `--force` the edit is kept.

### CLI-935 — a project-only skill on a global sub-agent

- **`init --from` and `edit --from` refuse a link that puts a project-only skill on a global sub-agent whether or not
  the skill loads**, with exit 1, every such pair named and nothing written at either scope. Before, a skill that
  failed to load let the link through and the sub-agent was installed globally.

### CLI-936 — a skill id too long for a folder

- **`init --from` and `edit --from` refuse a carried skill id longer than a folder name can be (over 255 bytes) before
  the panel**, naming each such id, with exit 1 and the project untouched. Before, they asked to confirm, then crashed
  with a raw `ENAMETOOLONG` and left empty folders behind. Ids of exactly 255 bytes still install.

### CLI-938 — a download made in the same second as giget's saved copy

- **`doctor` no longer refuses a fresh download as giget's saved copy when both were written within the same
  second**, and other commands stop warning `(405) — using the cached copy` over a copy they have just downloaded.
- A download holds a lock, `.agents-inc.lock`, in giget's cache folder for that host, so two runs at once never mix up
  their checks; a leftover lock says why the run is waiting.

### CLI-930 — a source checkout under a folder named `dist…`

- A source checkout of the CLI under any folder whose name starts with `dist` finds its own files. The published CLI
  is unchanged.

### CLI-987 — the panel's labels stay whole

- **The confirm panel of `init --from`, `edit --from` and `uninstall` keeps its `Marketplace` and `Stack` labels whole
  when a name is too long for the line**; the long name wraps under itself. At 80 columns it printed `Marketplac` and
  `e`.

### CLI-988 — a marketplace document's value stays on its error line

- **A key, slug or path a marketplace document writes across lines stays inside its one validation-error line**, so a
  document can no longer print a line that reads as the CLI's own, such as `Marketplace verified.`

### CLI-957 — reading a marketplace folder keeps the run's catalogue

- `build marketplace` reading a marketplace folder no longer replaces the catalogue the rest of the run names skills
  from, and a load refused after reading a folder leaves the previous catalogue in place. A user sees no change.

### SERVER-07 — CORS runs once per request

- The worker's cross-origin check runs once per request, so its routes answer `Vary: Origin` instead of
  `Origin, Origin`.

### EDITOR-100 — the Switch marketplace dialog and a waiting configuration

- **The Switch marketplace dialog no longer says the switch "loses nothing" when a shared link or saved stack waiting
  on that marketplace would replace what is on screen.** It says the switch finishes what was waiting and that
  anything unsaved on screen is lost.

### EDITOR-114 — leaving a shared link keeps its notice

- **Leaving a shared link by loading another marketplace keeps the notice naming the skills the saved configuration
  could not place**, from the Marketplace dialog, the saved-marketplace switcher, or a stack built on another
  marketplace. Leaving through the Editor nav item still clears it.

## Removed

### CLI-942 — four metadata keys nothing read

- The four `METADATA_KEYS` members no code read — `CLI_DESCRIPTION`, `FORKED_FROM`, `CONTENT_HASH` and
  `USAGE_GUIDANCE` — are gone. A user sees no change.

### CLI-985 — the detected installation's `skillsDir`

- The detected installation no longer carries `skillsDir`, a field only specs read and which named Claude's folder for
  a Codex installation. A user sees no change.
