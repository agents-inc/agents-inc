## What Was Wrong

Two of the three generated artifacts were already stale on disk before this change touched
anything. Discovered by running each generator against an unmodified tree and diffing the output
against a snapshot taken first:

- **`src/schemas/metadata.schema.json`** was missing the `meta-planning` category and five planning
  skill slugs (`ai-planning`, `api-planning`, `cli-planning`, `web-planning`, and the `meta-planning`
  category entry). `src/cli/types/generated/source-types.ts` already carried all six, so the two
  artifacts disagreed with each other: somebody ran `generate:types` and not `generate:schemas`.
- **`src/cli/types/generated/matrix.ts`** carried one stale skill description — the seed-proposal
  skill's `cliDescription` had been rewritten in the sibling `skills` checkout and never regenerated.

`DOCUMENTATION_MAP.md` -> "Tooling Gates" already predicts this ("Open gap: no generator check runs
at pre-commit"). What is new here is that the drift is no longer hypothetical: it had accumulated,
in two artifacts, and it rides along in the diff of whoever next runs a generator for an unrelated
reason. That is the part that makes it a review hazard rather than a housekeeping item — the person
whose change regenerates the file inherits an unexplained hunk they did not author.

A second, separate problem surfaced while trying to report the checkers green. Two of the three
checkers are implemented as a `git diff` against the working tree:

```
"generate:types:check":   "bun run generate:types   && git diff --exit-code src/cli/types/generated/"
"generate:schemas:check": "bun run generate:schemas && git diff --exit-code src/schemas/"
```

That shape has two consequences. It answers "does the generator output differ from what is committed",
which is _not_ the question "is the committed artifact stale" whenever the change under way is
deliberately meant to alter generator inputs — during this task both checkers were red by
construction and staying red was the correct outcome. And it makes the checkers unrunnable by any
agent operating under the repo's no-git constraint, so the gate silently goes unreported rather than
failing loudly. `generate:matrix:check` has neither problem: it compares emitted bytes to on-disk
bytes itself (`scripts/generate-matrix-package.ts` -> `check()`), needs no VCS, and answers the
staleness question directly.

## Fix Applied

None for the drift itself — deliberately. Both stale artifacts were regenerated as part of this
change because the task required a generation round, so the corrections are folded into this diff
rather than isolated. They are called out here so the extra hunks are attributable:
one `cliDescription` string in `matrix.ts`, and six added entries in `metadata.schema.json`.

For the checker shape, the substitute used here was an idempotency comparison: run the generator,
snapshot its output, run it again, and diff the two rounds. That establishes the on-disk artifact
matches what its inputs produce, which is the property the checker exists to assert, without
consulting VCS. Both rounds were byte-identical.

## Proposed Standard

Two changes, both in `.ai-docs/reference/features/code-generation.md`, which owns the generator
contract:

1. **Give `generate:types` and `generate:schemas` the same self-contained `--check` mode
   `generate:matrix` already has.** `scripts/generate-matrix-package.ts` -> `check()` is the working
   pattern: emit into memory, compare against the bytes on disk, list the drifted paths, exit
   non-zero. Once all three answer staleness without VCS, all three can run at pre-commit, in CI,
   and under an agent — which is what closes the gap `DOCUMENTATION_MAP.md` currently only names.
   The `git diff` forms should then be deleted rather than kept alongside, so there is one answer
   to "is this artifact stale".

2. **State that a generated artifact is regenerated by the change that alters its inputs, and that
   pre-existing drift found while doing so is reported, not silently absorbed.** This finding is
   the shape that reporting should take: name the artifact, name the hunks, say why they are in a
   diff that did not intend them. The rule matters because the alternative — a reviewer discovering
   an unexplained generated hunk — is indistinguishable from an accidental regeneration.
