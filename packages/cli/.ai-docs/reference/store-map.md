# Store / State Map

## State Management Library

**Library:** Zustand
**Version:** v5
**Pattern:** Single store with `create<WizardState>()`, accessed via `useWizardStore` hook with selectors

## Store

| Store          | File                             | Purpose                  |
| -------------- | -------------------------------- | ------------------------ |
| useWizardStore | `src/cli/stores/wizard-store.ts` | Entire wizard flow state |

There is exactly **one** Zustand store in the codebase.

> **The per-skill provenance field is `SkillConfig.origin`, not `source`.** `src/cli/types/config.ts` declares `SkillConfig` as `{ id, scope, origin: string, excluded? }` — `origin` holds `eject` (the project's own copy) or a marketplace name. Two neighbouring things keep the older word and are NOT the same field: the diff row `SkillDiffRow.source` (`lib/wizard/scope-diff.ts`), which is populated FROM `origin`, and the UI type `CategoryOption.source` (`components/wizard/category-grid.tsx`). Read `origin` when the subject is a config entry; `source` only when the subject is one of those two row types. Store helpers named `…Source…` (`resolveEffectiveSource`, `primarySourceName`, `marketplaceSourceName`, `sourceForInstallMode`, `installModeOfSource`) all read or produce an `origin` VALUE — the name is about marketplaces, not about the field.

## WizardState Shape (`src/cli/stores/wizard-store.ts`)

### Navigation State

| Field     | Type           | Purpose                         |
| --------- | -------------- | ------------------------------- |
| `step`    | `WizardStep`   | Current wizard step             |
| `history` | `WizardStep[]` | Step history stack for goBack() |

`WizardStep` = `"stack" | "domains" | "build" | "sources" | "agents" | "confirm"`

Step progression: `stack -> domains -> build -> sources -> agents -> confirm`

#### Step-Flow Surface (module scope, `wizard-store.ts`)

Two answers, deliberately separate: every step the wizard HAS, and the steps THIS run has.

| Symbol                      | Exported | Signature / value                                                                                   | Purpose                                                                                                                                             |
| --------------------------- | -------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WIZARD_STEP_ORDER`         | yes      | `["stack","domains","build","sources","agents","confirm"] as const satisfies readonly WizardStep[]` | The canonical full order. One source for step ORDER — `wizard-tabs.tsx` labels it, it does not re-list it                                           |
| `getActiveStepFlow`         | yes      | `() => WizardStep[]`                                                                                | The steps this session runs. Returns `WIZARD_STEP_ORDER` when the loaded source offers a stack, otherwise the same list with `"stack"` filtered out |
| `offersStacks`              | no       | `() => boolean`                                                                                     | `matrix.suggestedStacks.length > 0` — the single "does this run have a stack step" test, read by `getActiveStepFlow` and by `hydrateForInit`        |
| `stepsBefore`               | no       | `(flow: WizardStep[], step: WizardStep) => WizardStep[]`                                            | The flow's steps preceding the active one; `[]` when the step is outside the flow. Backs `getStepProgress`                                          |
| `FIRST_STEP_WITHOUT_STACKS` | no       | `WizardStep` = `"domains"`                                                                          | Where `hydrateForInit` opens when `offersStacks()` is false                                                                                         |

`getActiveStepFlow()` is what the tab bar is drawn from (`wizardTabsFor(getActiveStepFlow())` in `wizard-layout.tsx`), so the tabs cannot advertise a step the flow does not have. See [wizard/state-transitions.md](./wizard/state-transitions.md) and [features/wizard-flow.md](./features/wizard-flow.md).

### Selection State

| Field                    | Type                         | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `selectedDomains`        | `Domain[]`                   | Active domains                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `currentDomainIndex`     | `number`                     | Currently visible domain in build step                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `domainSelections`       | `DomainSelections`           | **Selection intent** — nested `domain → category → SkillId[]`. Represents what the user has ticked in the build step UI. | `_stackDomainSelections` | `DomainSelections \| null`   | Internal snapshot of domainSelections taken by `populateFromSkillIds` (via `structuredClone`), covering both the edit flow and stack/scratch population in init. Read by `toggleDomain` to re-apply the original per-domain selection when a previously-removed domain is re-enabled. Never cleared except on `selectStack` / `reset`. Leading underscore flags it as internal — do not read from UI components.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `selectedAgents`         | `AgentName[]`                | List of agent names the user has selected. Loosely paired with `agentConfigs`: an agent may appear here while `agentConfigs` has an `excluded: true` entry for the same name — the dual-scope pair `restoreDualScopeAgent` builds (see `toggleAgent`). Wizard state only: `ProjectConfig` persists no selected-agent list. The hydration input (`initialAgents`) and the emitted `SelectedAgentName` union are both derived from non-excluded `config.agents[]` rows via `activeAgentNames` in `src/cli/lib/configuration/scope-predicates.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `agentConfigs`           | `AgentScopeConfig[]`         | Per-agent `{ name, scope, model?, effort?, excluded? }` — `model`/`effort` are optional per-agent tuning overrides (see [features/model-and-effort.md](./features/model-and-effort.md)). Source-of-truth for agent scope and tombstones. May contain tombstones for agents not in `selectedAgents` (preserved across `preselectAgentsFromDomains`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `skillConfigs`           | `SkillConfig[]`              | **Saved-config shape** — flat `{ id, scope, origin, excluded? }[]` that mirrors what will be written to project/global config. Kept in sync with `domainSelections` via `reconcileSkillConfigs` / `restoreSkillConfigs` / `applySkillRemoval`. May contain excluded tombstones absent from `domainSelections`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `installedSkillConfigs`  | `SkillConfig[] \| null`      | Immutable snapshot of skill configs installed before the wizard opened. Set once by `hydrateWizardStore` and NEVER modified post-hydration. Serves as (a) the diff baseline for `SkillAgentSummary`, (b) the "was-previously-installed" probe that tells `applySkillRemoval` which entries the project merely INHERITS (immutable) from those it added this session, and that gates tombstone creation in `toggleSkillScope` and the lock in `toggleTechnology`, (c) the source-of-truth for locked global rows in `buildSourceRows`, and (d) the baseline for the Sources tab's own session diff — the added (`+`) and pending-removal (`-`) markers. `null` in pure init mode with no prior installation, and the two Sources-tab collectors read that `null` differently ON PURPOSE: `collectRemovedInstalledEntries` returns `[]` (no snapshot, so nothing can have been emptied) while `collectInstalledSkillSlots` collapses it to the EMPTY SET, which flags every row added — see "Sources-tab session diff". |
| `installedAgentConfigs`  | `AgentScopeConfig[] \| null` | Same semantics as `installedSkillConfigs`, but for agents. Drives the global-agent lock in `toggleAgent` and tombstone creation in `toggleAgentScope`. It does not feed `applyAgentToggle`, which has no installed-configs parameter and no tombstone branch. Outside the store its **only** reader is `skill-agent-summary.tsx`, which selects it and forwards it to `computeScopeDiff`. `step-agents.tsx` does not subscribe to it — the dual-scope badges derive from the LIVE `agentConfigs` pair, never from the snapshot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `unresolvableSkillIds`   | `SkillId[]`                  | Skill IDs from the saved config that `populateFromSkillIds` could NOT resolve against the currently-loaded matrix (skill removed/renamed). The wizard cannot represent them, so they are absent from the result and the merge removes their config entries like any other absent owned entry. The list is carried out of the wizard so `edit` can NAME each one in its `Changes:` block with the reason it went — the removal is the only one the user did not ask for, so it may not be silent. The reason is **class-specific**, not one sentence: `unresolvedSkillRemovalReasons` in `src/cli/lib/skills/unresolved-skill-entries.ts` classifies each id at its own install path and renders one of four sentences (a fifth class refuses the run instead). See `config/config-merger.md`, "A skill the wizard could not resolve is dropped, not exempted". Reset to `[]` by `createInitialState`.                                                                                                                 |

### Source State

**There is none.** No `WizardState` field is about marketplace enablement; per-skill provenance lives on `skillConfigs[].origin` and nowhere else.

> **`enabledSources` / `setEnabledSources` do not exist — do not look for them, and do not reintroduce the pair.** The field was initialised `{}` and written only by its setter, which had no call site anywhere in the repo, so the summary panel's `Marketplace` row could never name anything but the hardcoded public default. The row now derives from the distinct non-`EJECT_SOURCE` values in `SkillConfig.origin` (`formatSkillMarketplaces` in `summary-panel.tsx` — see `component-patterns.md`, "SummaryPanel"). Nothing replaced the state field; there is no enabled-source concept in the store. Source: `.ai-docs/agent-findings/2026-07-31-a-hardcoded-header-lets-its-fixture-omit-the-field-it-will-derive-from.md`.

### Selection

| Action                  | Signature                                           | Effect                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `toggleDomain`          | `(domain: Domain) => void`                          | Add/remove domain, manages selections. Deselect is a **view filter**: it hides the domain and drops only the project-owned entries in it via `applySkillRemoval`; inherited global entries survive byte-identical. No guard, no toast — it has no authority over a global install rather than refusing one                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `toggleTechnology`      | `(domain, category, technology, exclusive) => void` | Radio (exclusive) or checkbox toggle. Guards (emit `GLOBAL_SKILLS_LOCKED` unless noted): (1) on a DESELECT the composite `isGloballyLockedSkill(installed, skillConfigs, technology)` blocks on either of its two arms — both GLOBAL-OWNED; on a SELECT only its active-global arm is applied, so the re-select restore path still runs; (1b) spacebar on a live dual-scope `[P][G]` row DROPS the project half (the pair collapses to the inherited global entry through `applySkillRemoval`) — the half the project owns is the project's to remove; (2) in exclusive mode, `blocksExclusiveSwap` blocks selecting a replacement when the current selection is globally locked OR a live `[P][G]` pair, since dropping the pair sideways would unmask its global install beside the new pick; (3) blocks deselecting the last skill in an `exclusive && required` category (`ONLY_SKILL_IN_CATEGORY`). Reconciles `skillConfigs` via `reconcileSkillConfigs`. |
| `toggleAgent`           | `(agent: AgentName) => void`                        | Add/remove agent. Dual-scope aware: spacebar on a live `[P][G]` pair is inert — `isDualScopeAgentPair(agentConfigs, agent)` returns the `GLOBAL_AGENTS_LOCKED` toast and leaves badges unchanged (only `s`/`toggleAgentScope` changes a dual-scope row); re-selecting an inherited-global row rebuilds the pair via `restoreDualScopeAgent`. Also guards against toggling globally-installed agents from project scope (`GLOBAL_AGENTS_LOCKED`) in every flow, init included. A deselect that reaches `applyAgentToggle` is one the project owns, so it is a clean removal — never a tombstone.                                                                                                                                                                                                                                                                                                                                                                 |
| `nextDomain`            | `() => boolean`                                     | Advance to next domain, returns success                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `prevDomain`            | `() => boolean`                                     | Go to previous domain, returns success                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `setCurrentDomainIndex` | `(index: number) => void`                           | Set domain index directly (no-op if out of range)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

### Scope / Source Per-Skill

| Action                            | Signature                         | Effect                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `toggleSkillScope`                | `(skillId: SkillId) => void`      | Toggle skill scope project/global. No-op if `isEditingFromGlobalScope`. Round-trips a pair both ways — `[P][G]` → `[G]` → `[P][G]`. It is the sole toggle on the AGENT path; on the skill path spacebar reaches the same collapsed shape by dropping the project half. Guard: project eject→global blocked when a global eject is already installed → `ALREADY_EJECTED_AT_GLOBAL` toast (unless an excluded tombstone allows the undo). G→P adds an excluded global tombstone (gated on `wasInstalledGlobally`, which counts an existing global tombstone as installed); P→G unconditionally drops any global tombstone. |
| `setFocusedSkillId`               | `(id: SkillId \| null) => void`   | Set focused skill for the S hotkey. Dispatched by `CategoryGrid`'s **mount effect** keyed on the drawn cell — it fires on mount and on every change of that cell, not only on navigation, so a category reshape re-syncs the store too. Complements the synchronous store seed (`seedFocusedSkillForActiveDomain`) rather than replacing it.                                                                                                                                                                                                                                                                             |
| `seedFocusedSkillForActiveDomain` | `() => void`                      | Synchronously set `focusedSkillId` to the active domain's first grid option (via `buildCategoriesForDomain`), or `null` if none. Called by `setStep("build")`, `nextDomain`, `prevDomain`, `setCurrentDomainIndex`, and both hydration paths (Fix A).                                                                                                                                                                                                                                                                                                                                                                    |
| `toggleAgentScope`                | `(agentName: AgentName) => void`  | Toggle agent scope project/global. No-op if `isEditingFromGlobalScope`. Mirrors `toggleSkillScope`: the sole dual-scope toggle, `s` round-trips a pair both ways — `[P][G]` → `[G]` → `[P][G]`. G→P adds the excluded global tombstone (gated on `wasInstalledGlobally`, which counts a tombstone as installed); P→G unconditionally drops it.                                                                                                                                                                                                                                                                           |
| `setFocusedAgentId`               | `(id: AgentName \| null) => void` | Set focused agent for S hotkey (seeded by a post-mount effect in `step-agents.tsx`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

### Source Management

| Action           | Signature                                                                               | Effect                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `setInstallMode` | `(skillId: SkillId, mode: "eject" \| "plugin", scope: SkillScope \| undefined) => void` | **Scope-keyed**. Resolves the mode to the `origin` value it writes — `eject`, or the one marketplace `marketplaceSourceName` finds — and rewrites that ACTIVE entry at `(skillId, scope)` only, via `withActiveEntryOrigin`; every other entry — in particular a dual-scope skill's excluded global tombstone — keeps its own origin, so a project-side mode change cannot leak across scopes. **Scope-gated**: a project-context call (`!isEditingFromGlobalScope`) against a global slot the hydration snapshot already carries (`isInheritedGlobalSlot`) returns the state unchanged, so the store agrees with the grid, which renders that row inert. No-op with a warning on an empty `skillId`; there is no empty-origin case left to guard, because the caller no longer supplies one. The acting scope is threaded in by `step-sources.tsx`'s `handleGridSelect`, which reads it off the single non-inert row for that skill (`isRowInert`). |

> **`setAllSourcesEject` / `setAllSourcesPlugin` do not exist — do not look for them, and do not reintroduce the pair.** They set `origin` on every active skill config, and their only callers were the Sources step's `l` / `p` hotkeys, which are withdrawn. Neither carried scope authority, so from a project edit they rewrote inherited global-active rows — rows the same step renders locked and non-focusable, and which `setInstallMode` now refuses outright. Nothing replaced them: setting several skills' modes means committing each row, which is what the E2E driver `SourcesStep.setAllLocal` does.

## Usage Pattern

**In wizard components:**

```typescript
// Select specific state slices (Zustand selectors)
const step = useWizardStore((s) => s.step);
const toggleTechnology = useWizardStore((s) => s.toggleTechnology);
const selectedDomains = useWizardStore((s) => s.selectedDomains);

// Or get the entire store
const store = useWizardStore();
```

**Files using the store (production only).** Re-derive with `grep -rln "useWizardStore\|hydrateWizardStore" src/cli/`, then drop `wizard-store.ts` itself, every `*.test.*`, and the one test-support module under `src/cli/lib/__tests__/` (`helpers/wizard-simulation.ts`, which drives the store directly for unit specs). What remains is exactly the eleven files below. Note `step-confirm.tsx` is NOT on it: it renders `SummaryPanel`, which does its own selecting.

- `src/cli/components/wizard/wizard.tsx` - Main wizard orchestrator
- `src/cli/components/wizard/wizard-layout.tsx` - Layout wrapper
- `src/cli/components/wizard/step-build.tsx` - Technology selection step
- `src/cli/components/wizard/step-sources.tsx` - Source selection step

## Internal Helpers

All declared at module scope in `wizard-store.ts`, not exported. Domain ordering is NOT one of them: it comes from the imported `orderDomains()` in `src/cli/lib/wizard/domain-order.ts`, which sorts custom domains alphabetically and then built-in domains per `DOMAIN_ORDER` from `@workspace/matrix`. It is called wherever a domain list is set (`toggleDomain`, `populateFromSkillIds`).

The store does not hand-roll its scope tests. The shared predicates `isActiveAt(entry, scope)`, `isGlobalTombstone(entry)` and `isProjectOwned(entry)` are imported from `src/cli/lib/configuration/scope-predicates.ts`; the module-scope helpers below are thin id-keyed wrappers over them. See `concepts/scope-system.md` for the predicate contract.

**Scope predicates (skills):** `hasProjectActive(configs, id)`, `hasGlobalActive(configs, id)`, `hasGlobalTombstone(configs, id)` test for an active project / active global / excluded-global entry. `findGlobalActive(configs, id)` returns that active global entry itself (not just a boolean) — it is what `classifySkillSourceRows` reads to pin a locked row's source, and `hasGlobalActive` is defined in terms of it. `isDualScopePair(configs, id)` = active project entry + global tombstone (the `[P][G]` shape). Consumed by `toggleTechnology`, `toggleSkillScope`, `applySkillRemoval`, `reconcileSkillConfigs`, `buildSourceRows`.

**`isGloballyLockedSkill(installed, liveConfigs, id)`**: the composite deselect guard behind `toggleTechnology`, in two arms, both about GLOBAL-OWNED halves — an active global entry in the hydration SNAPSHOT (genuinely global-only), or a snapshot tombstone paired with a LIVE plain active global entry (the stale shape a persisted `[P][G]` reaches after an in-session collapse, whose deselect would tombstone a still-real global install). A live `[P][G]` pair matches neither: its project half is the project's own install, and dropping it collapses the pair to the inherited global entry without touching that install. A skill added this session matches no arm either and stays freely deselectable. `toggleTechnology` applies the full predicate on a DESELECT and only the first arm on a SELECT, so the re-select restore path still runs. **`blocksExclusiveSwap(installed, liveConfigs, id)`** wraps it for the radio-swap path, adding the live `[P][G]` pair back: a swap that dropped the project half implicitly would unmask the global install beside the new pick, seating two active skills in an exclusive category.

**`wouldOverwriteGlobalEject(config, liveConfigs, installedSkillConfigs)`**: true when re-scoping a project-eject entry to global would overwrite an already-installed global eject that the live config does not already override with a tombstone. Drives `toggleSkillScope`'s `ALREADY_EJECTED_AT_GLOBAL` toast.

**`withActiveEntryOrigin(configs, id, scope, origin)`**: rewrites the `origin` of the ACTIVE entry at `(id, scope)` and nothing else. The whole mechanism behind the scope-keyed `setInstallMode` — an excluded global tombstone for the same id keeps describing the masked global install. (There is no `withActiveEntrySource`; that name never existed in the tree.)

**`isInheritedGlobalSlot(installed, id, scope)`**: `setInstallMode`'s refusal predicate — true when the targeted `(id, scope)` slot is a global install the hydration SNAPSHOT already carried. Keyed on the slot, never on the id, so the project half of a `[P][G]` pair (the half the grid leaves editable) stays configurable. Read off the snapshot, never off the live entry's scope: a `null` snapshot is a first `init`, and a global-scope skill added this session is nobody's install yet — both return false, so a fresh install can still choose its install mode.

**Scope predicates (agents):** `agentHasProjectActive(configs, name)`, `agentHasGlobalActive(configs, name)`, `agentHasGlobalTombstone(configs, name)`, `isDualScopeAgentPair(configs, name)` — the agent-side mirror, consumed by `toggleAgent` and `toggleAgentScope`.

**`createDefaultSkillConfig(id)`**: Returns a fresh `{ id, scope: "global", origin: defaultOriginFor(matrix.skills[id]) }` SkillConfig for a skill that has no saved config. **`defaultOriginFor(skill)`** is the origin a skill takes when nothing saved names one: `EJECT_SOURCE` when `isLocalOnlySkill(skill)` — a marketplace origin on a skill no marketplace carries names an install that cannot happen, which is what made a locally-written skill default to a plugin it could never be — otherwise `primarySourceName(skill) ?? DEFAULT_PUBLIC_SOURCE_NAME`.

**`buildSkillConfigForId(id, savedConfigs?)`**: Builds a `SkillConfig` for a skill ID, preferring a project-scoped non-excluded entry from `savedConfigs` over a global one when duplicates exist (defensive fix). Degrades to `createDefaultSkillConfig`'s output when the snapshot has no entry.

**`applySkillRemoval(configs, removedIds, installedSkillConfigs)`**: Removes only what the project OWNS — a project-scoped entry, the project's own global tombstone, or an entry absent from `installedSkillConfigs` (added this session). An INHERITED global-active entry present in the snapshot survives **byte-identical**; the helper never stamps `excluded`, so it is not a tombstone producer. `installedSkillConfigs === null` means "editing FROM global scope": nothing is inherited, so every removed id is dropped (Scenario C). A dual-scope pair collapses to a single inherited-global entry (Scenario B). Invoked by `toggleDomain` and `reconcileSkillConfigs`.

**`reconcileSkillConfigs(configs, added, removed, installedSkillConfigs, isEditingFromGlobalScope)`**: Wrapper applied by `toggleTechnology`. Calls `applySkillRemoval` for removed skills (passing `null` for installed when `isEditingFromGlobalScope`, so a removal is a genuine uninstall — Scenario C; at project scope the snapshot is the ownership test instead), then for each added skill: rebuilds the `[P][G]` pair on a dual-scope restore, un-excludes an existing tombstone, or appends `buildSkillConfigForId(id, installedSkillConfigs)`.

**`restoreSkillConfigs(existingConfigs, restoredIds)`**: Used by `toggleDomain` when a domain is re-enabled and a `_stackDomainSelections` snapshot exists. Clears `excluded` flags on the restored IDs and appends defaults for any newly-introduced IDs.

**Agent config builders/togglers:** `buildAgentConfigForName(name, savedConfigs?)` mirrors `buildSkillConfigForId` on the agent path (preselection), and carries a saved entry's `model` / `effort` overrides through the rebuild on the same terms as `scope` — those are the user's deliberate choice, not something a roster re-derives. `applyAgentToggle(configs, agent, isSelected)` removes the agent's entries on deselect and restores/adds on select. It has no `installedAgentConfigs` parameter and no tombstone branch, so it mirrors `applySkillRemoval` in never minting one. `restoreDualScopeAgent(...)` is the dual-scope restore used by `toggleAgent` when re-selecting an inherited-global row; the collapse half is `toggleAgentScope`'s `s` toggle (dropping the tombstone), not a helper. `collectTombstones(configs)` returns excluded entries (preserved across reconcile/preselect merges), used by `populateFromSkillIds` and `preselectAgentsFromStack`. `survivesRosterRebuild(agentConfig, roster)` is the named predicate `preselectAgentsFromDomains` filters its retained entries through: an entry outlives a domain-roster rebuild when it is ANY excluded tombstone (deliberately not filtered by roster membership) **or** when the project does not own it and the roster does not contain it, so a globally-installed agent outside the selected domains' roster is never silently uninstalled. Entries the roster itself rebuilds are excluded, because `buildAgentConfigForName` re-derives those. `nextSelectedAgents(selectedAgents, agent, { isSelected, isInList })` computes the post-toggle name list — its former `isExcludedToggleOff` arm (which kept a tombstoned agent listed) went away with the tombstone branch.

**Selection helpers:** `addToDomainSelections(selections, domain, category, skillId)` adds a skill if absent (`populateFromSkillIds`). `flattenCategorySelections(selections)` / `collectSkillIdsFromSelections(selections)` flatten a domain's category map to skill IDs.

**`resolveSkillForPopulation(skillId)`**: Looks up a skill → `{ domain, subcat, techId }` for `populateFromSkillIds`. Returns `null` with a warning when the skill isn't in the matrix or its category has no domain.

**Install-mode option builders (for `buildSourceRows`):** `resolveEffectiveSource(...candidates)` returns the first defined source else `DEFAULT_PUBLIC_SOURCE_NAME`. `primarySourceName(skill)` returns the primary available source name. `marketplaceSourceName(skill)` returns the one marketplace a skill can be installed from as a plugin — the first non-local `availableSources` entry, else `DEFAULT_PUBLIC_SOURCE_NAME`. `sourceForInstallMode(skill, mode)` is the pair's write half: `eject` for the project's own copy, that marketplace name for a plugin. `installModeOfSource(origin)` is its read half — the per-skill twin of `deriveInstallMode`, which asks the same question of a whole selection. `buildInstallModeOptions(selectedMode)` emits the row's two cells in `INSTALL_MODES` order with the current one selected. `withSelectedMode(options, origin)` returns a copy with the PERSISTED origin's mode selected — used by the row shapes that pin to a persisted value rather than the live one. `resolveSkillRowInputs(id, skillConfigs)` bundles the per-skill inputs every row shape shares: the canonical id, the live config entry that drives scope/lock classification, and the cells with the effective mode preselected.

**Source-row builders (for `buildSourceRows`):** `classifySkillSourceRows(skillId, options, context)` splits one skill's LIVE config entry into `SourceRow[]` — a locked global row for an excluded-global entry, a locked-global **plus** editable-project pair for a skill re-scoped global→project this session, or a single row otherwise. It **no longer produces pending-removal rows**: those belong to snapshot slots with no live entry left and are built separately (see below). Every shape derives its own `added` flag from its own slot. `toLockedGlobalRow(skillId, options, installedSource, installedSkillSlots)` builds the `readOnly` row and pins it to the INSTALLED source's mode, so an inherited install reads as a plain lock rather than as new. `toPendingRemovalRow(skillId, options, removedInstalledEntry)` builds the inert `disabled` row from a snapshot entry, carrying the entry's PERSISTED scope and origin; it is deliberately not `readOnly` (a lock reads as "installed globally", not "about to be removed") and never carries `added`, since the slot it renders comes from the snapshot. `isSlotAlreadyRendered(rows, removedInstalledEntry)` suppresses a removal row for a slot an already-emitted row renders — the one shape that reaches it is a global install adopted at project scope with no tombstone, where the locked global row is rendered from the snapshot and the install is inherited, not removed. `sourceRowSortTier(row)` orders the rows (global readOnly, global editable, project); a pending-removal row has **no** dedicated tier — it sorts by its own scope and, being appended after every live row, trails inline within that scope section, matching the info panel's in-place removals.

**Sources-tab session diff:** `collectRemovedInstalledEntries(installedSkillConfigs, skillConfigs)` returns the snapshot **(id, scope) slots** this session emptied — every ACTIVE snapshot entry whose slot no live `skillConfigs` entry occupies. Each becomes an inert row (`toPendingRemovalRow`) carrying the removal marker and the entry's persisted scope + origin, so the user can see what saving removes. It applies at **every** scope — a global-scope edit shows the removal too, matching `computeScopeDiff`, which has no such gate. A gate here would make a deselected global skill vanish from the tab: at global scope `reconcileSkillConfigs` passes `null`, so `applySkillRemoval` drops the entry outright and the snapshot becomes the only surviving record — precisely the record this collector reads. Candidates are additionally filtered to ids the loaded matrix still carries: a skill the marketplace no longer has was already skipped into `unresolvableSkillIds` at hydration and would throw in `getSkillById` downstream.

Removal is keyed per **slot**, not per id, using the same `skillSlotKey` the confirm step's removal match uses, so one skill can render twice: collapsing a dual-scope `[P][G]` pair to `[G]` (either the persisted project-entry-plus-global-tombstone pair or an active entry at both scopes) keeps the surviving **global** row AND emits a **project** pending-removal row — the same two-row shape the confirm step prints (`-` at Project, `•` at Global). Rows are therefore no longer disjoint per skill; they stay disjoint per slot, enforced by `isSlotAlreadyRendered`, which suppresses a removal row for a slot a live row already renders (the inherited-global case: `[G]` snapshot, `[P]` live with no tombstone, where the locked global row is rendered from the snapshot). Snapshot **tombstones** are deliberately excluded as removal candidates — narrower than `computeScopeDiff`, whose removal filter counts them — because a tombstone is a mask over a global install, not an install: dropping it deletes nothing.

`collectInstalledSkillSlots(installedSkillConfigs)` and `addedSlotFlag(installedSkillSlots, id, scope)` decide the added marker per **(id, scope) slot** rather than per id, using `skillSlotKey` exported from `lib/wizard/scope-diff.ts` — the same key the confirm step's `classifyDiffRow` uses, so the two surfaces cannot drift. Adopting a globally-installed skill at project scope therefore flags the new project row as added, even though the id already existed globally. Tombstones count as occupied slots on both sides, so re-activating a masked global install reads as unchanged rather than added.

**A missing snapshot is the EMPTY SET, not a third state.** `collectInstalledSkillSlots` has no `null` branch of its own — `installedSkillConfigs === null` returns `new Set()`, and `addedSlotFlag` therefore stamps `added` on every row. That is deliberate and is what makes a genuine first `init` agree with the confirm step, which already treats a null baseline as "everything is new" in `classifyDiffRow`. The removed branch returned no flags at all, so the confirm step listed every skill with a green `+` while the Sources tab showed no markers whatever — the two surfaces reading the same `null` in opposite directions. Only the `null` case changed; an empty snapshot already flagged every row.

## Hydration Entry Point

**`hydrateWizardStore(options: HydrateOptions): void`** — exported from `wizard-store.ts`. MUST be called before `render(<Wizard />)` so React captures the intended initial snapshot on the first frame (running hydration inside a render-phase hook causes a one-frame flash of the default `"stack"` step).

Called through `runWizardSession()` in `components/wizard/run-wizard-session.tsx` (used by `commands/init.tsx` — no `initialStep` → init flow — and `commands/edit.tsx`'s `runEditWizard()` — with `initialStep`, `installedSkillIds`, etc. → edit flow), and directly by `commands/list.tsx` (dashboard view, snapshot-only). It delegates to the non-exported `hydrateForEdit` / `hydrateForInit`.

```typescript
type HydrateOptions = {
  initialStep?: WizardStep; // When absent → init mode (isInitMode=true, stays on "stack")
  initialDomains?: Domain[]; // Overrides domains derived by populateFromSkillIds
  initialAgents?: AgentName[]; // Derived by callers from non-excluded config.agents rows (activeAgentNames)
  installedSkillIds?: SkillId[]; // Passed to populateFromSkillIds (edit flow only)
  installedSkillConfigs?: SkillConfig[]; // Snapshot + savedConfigs for populateFromSkillIds
  installedAgentConfigs?: AgentScopeConfig[]; // Snapshot + restored when initialAgents set
  isEditingFromGlobalScope?: boolean; // Disables scope toggling (~/.claude/ edit)
};
```

Sequence:

1. `useWizardStore.setState(createInitialState())` — fresh reset
2. Sets `isInitMode = !initialStep`
3. If edit flow: `populateFromSkillIds(installedSkillIds, installedSkillConfigs)`
4. If `initialStep`: jumps to that step with empty `history`, sets `approach: "scratch"`
5. Overrides `selectedDomains` / `selectedAgents` / `agentConfigs` from the hydration options if present (`initialDomains` from the saved `selectedDomains` field; `initialAgents` derived from non-excluded `config.agents[]` rows via `activeAgentNames`)
6. Seeds `installedSkillConfigs` / `installedAgentConfigs` snapshots (diff baseline)
7. In init flow with existing global configs: seeds `globalPreselections` / `globalAgentPreselections` for `stack-selection.tsx` / `preselectAgentsFromStack` to merge after the user picks stack/scratch
8. In init flow when `matrix.suggestedStacks` is empty — a source offering no stacks — calls `startFromScratch()` and sets `{ step: "domains", history: [] }`: the stack step would hold nothing but its own scratch row, so the wizard opens where that row leads and has nothing behind it
9. Both paths end by calling `seedFocusedSkillForActiveDomain()` so `focusedSkillId` is set before the first frame

DOMAIN_AGENTS = {

**Cell order** is `INSTALL_MODES` in `consts.ts` — `["eject", "plugin"]`, captioned `Local` and `Plugin` by `INSTALL_MODE_CELL_LABELS`. There is nothing left to sort: a skill is installed either as the project's own copy or from the one marketplace `marketplaceSourceName` resolves, so there is no set of marketplaces to rank against each other.

**`TOAST_MESSAGES`** — every key, exhaustive, module-private const in `wizard-store.ts`. Bound to source by `scripts/check-enumeration-drift.ts`, so a fifth guard cannot land without a row here. E2E asserts the strings verbatim:

| Key                         | Message                                              | Emitted by                                                         |
| --------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------ |
| `GLOBAL_SKILLS_LOCKED`      | `Global skills cannot be changed from project scope` | `toggleTechnology`                                                 |
| `ONLY_SKILL_IN_CATEGORY`    | `Cannot deselect the only skill in this category`    | `toggleTechnology` (exclusive+required, 1 skill)                   |
| `ALREADY_EJECTED_AT_GLOBAL` | `Already exists as ejected skill at global scope`    | `toggleSkillScope` (project eject → global)                        |
| `GLOBAL_AGENTS_LOCKED`      | `Global agents cannot be changed from project scope` | `toggleAgent` (active-global guard + live `[P][G]` inert-spacebar) |

## State Reset

`reset()` action restores all state to `createInitialState()` defaults.

`selectStack()` also resets: domainSelections, \_stackDomainSelections, selectedDomains, skillConfigs, selectedAgents, agentConfigs, currentDomainIndex, stackAction.

Initial state:

- `step: "stack"`, `approach: null`, `selectedStackId: null`, `stackAction: null`
- `selectedDomains: []`, `currentDomainIndex: 0`, `domainSelections: {}`, `_stackDomainSelections: null`
- `showLabels: false`, `showInfo: false`
- `skillConfigs: []`, `focusedSkillId: null`
- `selectedAgents: []`, `agentConfigs: []`, `focusedAgentId: null`
- `installedSkillConfigs: null`, `installedAgentConfigs: null`
- `unresolvableSkillIds: []`
- `isInitMode: false`, `isEditingFromGlobalScope: false`, `toastMessage: null`
- `globalPreselections: null`, `globalAgentPreselections: null`, `history: []`
