# Test Factories & Helpers

> **Split from:** `reference/test-infrastructure.md`. See also: [infrastructure.md](./infrastructure.md), [mock-data.md](./mock-data.md), [e2e-infrastructure.md](./e2e-infrastructure.md).

## Test Utilities (Domain-Scoped Directories)

Test utilities live in three domain-scoped directories under `src/cli/lib/__tests__/`. Each has a barrel `index.ts` for imports. Tests import from `factories/`, `helpers/`, or `assertions/` as needed.

**This document owns the factory / helper / assertion counts**, and each table below is exhaustive — a symbol absent from it is not exported from that directory.

| Directory     | Exported symbols |
| ------------- | ---------------- |
| `factories/`  | 45               |
| `helpers/`    | 46               |
| `assertions/` | 12               |

Re-derive both the counts and the membership from source rather than carrying either forward.
`scripts/check-enumeration-drift.ts` binds all three tables — factories, helpers and assertions —
reading each DIRECTORY rather than its barrel. A barrel is not the claim, and binding one would
report real members as drift (`factories/index.ts` re-exports a strict subset of what its directory
declares; the helper table names `extractNamedSection` and `extractScopeSections`, which no barrel
re-exports at all). Its directory reader takes each module's own declarations plus every name it
re-exports by name, over every non-spec module in the tree, and dedupes. The single-file inventories
further down (FS utilities, expected values, content generators, the journey-page reader) are
registered too.

**`createTestSkill()` / `createMockSkill()` taxonomy contract:** neither reads domain, category or
slug off the ID's segments. Both look the ID up in the canonical taxonomy table at the top of
`skill-factories.ts`, where every value is stated per ID, and overrides win over what is found
there. An ID in neither place THROWS, naming the fields to pass — `createTestSkill` wants
`{ domain, category, slug }`, `createMockSkill` wants `{ category, slug }`. A novel ID therefore
carries the taxonomy its author gave it or fails loudly; it can never carry a plausible-looking one
nobody wrote. `displayName` follows from the slug that resolution produced, so stating a slug
retitles the skill with it.

Fields are written in a fixed order the caller cannot influence — `custom`, `domain`, `author`, `displayName`, `category`, `slug`, `cliDescription`, `usageGuidance`, `contentHash`, `forkedFrom` — and a trailing newline is always appended. A fixture that must omit `contentHash`, drop `author`, or use a different field order cannot use this renderer (the one former carve-out, `outdatedForkMetadata`, went with the `update` rewrite that stopped comparing hashes).

## Test Source Factory (`src/cli/lib/__tests__/fixtures/create-test-source.ts`)

Creates complete project directory structures for integration tests:

```typescript
import { createTestSource } from "../fixtures/create-test-source.js";

const dirs = await createTestSource({
  skills: [...],         // TestSkill[]        — source skills under <sourceDir>/src/skills/
  agents: [...],         // TestAgent[]        — source agents
  stacks: [...],         // TestStack[]        — writes config/stacks.ts
  matrix: {...},         // Partial<TestMatrix>
  projectConfig: {...},  // TestProjectConfig  — writes <projectDir>/.claude-src/config.ts
  pluginManifest: {...}, // TestPluginManifest
  localSkills: [...],    // TestSkill[]        — writes into <projectDir>/.claude/skills/
  asPlugin: true,        // build as a plugin structure under .claude/plugins/<plugin-name>
});
```

`TestSourceOptions` field names are load-bearing: the project config option is **`projectConfig`**, not `config`.

`TestDirs` (the return shape) is `{ tempDir, projectDir, sourceDir, skillsDir, agentsDir, pluginDir?, configDir? }`. There is no `root` / `skills` / `agents` / `config` field. `cleanupTestSource(dirs)` tears the whole tree down.

The module also re-exports the file-IO helpers used alongside it: `readTestFile`, `readTestYaml`, `readTestJson`, `writeTestFile`, `writeTestYaml`, `fileExists`, `directoryExists`.

Three marketplace helpers live in the same module, because a fixture source's skill ids are written
inside its marketplace's namespace: `TEST_MARKETPLACE_NAME` (`"test-fixture"`),
`testMarketplaceSkillId(bareId)` which composes one id inside it, and `inTestMarketplace(skills)`
which re-namespaces a whole `TestSkill[]`. `cleanupTestSource(dirs)` tears the tree down.
